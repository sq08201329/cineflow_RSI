## 2. 五个特性一览

### 001 发现树与评估器框架（L1 地基）

- **交付**：不可变发现树（frozen dataclass + PostgreSQL 触发器 + REVOKE 双保险）、三维谱系查询、
  内容寻址工件存储（BLAKE3）、评估器注册中心（`evaluator_id@version` 唯一 + 确定性校验）、
  合成评分（硬规则门禁 + 加权求和）
- **关键决策**：SQLAlchemy Core（不用 ORM）；双方言触发器让 SQLite 单测也能证明不可变；
  `eval_breakdown` 键格式应用层强制
- **代码**：`core/tree/`、`core/evaluators/`　|　迁移 `0001_tree_immutable.py`

### 002 回放模拟器与沙箱（正确性核心）

- **交付**：`ReplaySimulator`（observed/probe、规范化精确匹配、UNKNOWN 语义、虚拟时钟 ⌈k/W⌉）、
  模拟器池、轨迹产出、Kendall τ-b 无偏性验收、stdio JSON Lines 沙箱（gVisor/加固双后端）、
  对抗测试三件套（反射偷看 / 计时侧信道 / 哈希反查）
- **关键决策**：病态宽树下的 children 全量物化有物理下限——基准按真实分支形态（分支因子 10）；
  响应时延量子化（确定性抗侧信道）
- **代码**：`core/replay/`、`core/sandbox/`、`policies/`

### 003 宣发 Agent 全闭环

- **交付**：探索执行器（预算 2% 门禁、事务扣减防双花、轮次幂等、三方对账）、三评估器
  （合规 / CTR 分桶贝塔平滑 / 平台真值）、确定性模拟平台 + 真实适配器骨架、回流管道
  （写入即冻结）、进化对比报告、LLM 网关最小版（计费/缓存/重试）
- **关键决策**：**两段式落盘**——投放与回流的时间差由可变运营表承载，指标到位后节点一次性
  完整 INSERT，"写入即冻结"由 immutable 天然保证，不给树开口子
- **代码**：`agents/promo/`、`core/llm_gateway/`　|　迁移 `0002_promo_campaigns.py`

### 004 视觉 Agent 闭环

- **交付**：五评估器（格式合规门禁 / 美学代理 / 主体一致性 / 闪烁检测 / judge 委员会）、
  确定性视频生成模拟器（参数种子 → 程序化帧 → mp4，逐字节复现）、帧采样管线（N=8、规则进版本）、
  一致性验收（重算逐字节一致率 100%）
- **关键决策**：**得分定点归一**（6 位小数）——否则"重算逐字节一致"在浮点层面不可达成；
  judge = 3 固定提示词 × 冻结锚点集，提示词/锚点哈希进版本号
- **代码**：`agents/visual/`、`core/evaluators/quantize.py`　|　迁移 `0003_visual_gen_jobs.py`

### 005 做梦层与谱系报表（自动进化）

- **交付**：候选生成双实现（确定性变异器 / LLM 生成器）、做梦管线（静态检查前置 → 沙箱全池
  串行回放 → reward 排名）、reward = `pareto_auc − λ·并行惩罚`、train/validation 防过拟合
  （最近树永远只做 validation）、人工审批闸门 + 部署指针、谱系报表 + 进化曲线 + 塌缩检测
- **关键决策**：`pareto_auc` 定为**梯形归一化面积**（早收敛奖励，全项目统一口径）；
  谱系元数据与做梦轮次**文件化**（`policies/history/*.meta.json`、`dreaming/history/*.json`）；
  候选回放用轮次临时目录——**未经审批不得进权威谱系**
- **代码**：`dreaming/`

## 5. 跨特性关键设计决策（复用价值最高的八条）

1. **两段式落盘**（003/004）：投放/生成的中间态存可变运营表，工件与指标齐备后节点一次性
   INSERT——immutable 与"事后回流"的张力在架构层消解。
2. **定点归一**（004）：得分入库前 6 位小数——"重算逐字节一致"可达成的前提。
3. **版本号即元信息**（001/003/004/005）：`evaluator_id@1.0.0+<实现/提示词/锚点/数据快照哈希>`，
   任何影响结果的输入变化自动成为新版本。
4. **适配器 + 确定性模拟 + 契约套件**（003/004）：真实渠道不接凭证时，双实现跑同一套契约，
   接口语义仍受约束，接入真实渠道只需配置。
5. **沙箱双后端**（002）：CI 用 gVisor（权威），本地用等价加固旗标容器；对抗测试无 Docker
   报错而非跳过。
6. **规范化精确匹配**（002）：生成参数规范化 JSON 相等，无模糊匹配——覆盖不足靠线上探索，
   不靠模拟器编造。
7. **文件化谱系**（005）：策略代码 + `meta.json` + 做梦轮次 JSON 同 lifecycle，随 git 版本化，
   不引入新表与双写漂移。
8. **审批闸门语义边界**（005）：候选回放走临时目录，只有 approved 的版本才进
   `policies/history` 与部署指针——沙箱回放不得污染权威谱系。

## 6. 诚实边界：真实 vs 模拟

| 环节 | 一期实现 | 接入真实的方式 |
| --- | --- | --- |
| LLM 调用 | Mock 后端（确定性、零成本）+ HTTP 后端骨架 | 配 `OPENAI_BASE_URL`/`OPENAI_API_KEY` |
| 视频生成 | 确定性程序化生成器（numpy → mp4） | `HttpRealVideoGen` 骨架 + `VISUAL_GEN_*` 凭证 |
| 广告投放平台 | 确定性模拟平台 + 契约套件 | `HttpRealPlatform` 骨架 + 平台凭证 |
| 美学/主体嵌入模型 | 确定性启发式代理（实现哈希即版本） | 换真实模型权重（哈希进版本号），代码路径不变 |
| 人类评估锚点 | 平台回流真值已实现；人评录入待接运营 | 评估器 `calibration` 字段已预留 |
| "次日部署" | 更新 `configs` 部署指针 | 接发布系统 |
| 真实在线轨迹采集 | 录制夹具（周期以运营节奏） | 无代码变更 |

**原则**：模拟不等于假装——所有模拟实现都在契约套件的同等约束下，切换真实渠道是配置动作
而非重写。

## 7.5 CI 门禁与推送通道

**五个 job 及各自守什么**

| job | 守什么 |
| --- | --- |
| unit | ruff（锁定版本，含 agents/dreaming）+ 单元测试覆盖率门禁 ≥85% |
| contract | 平台适配器/生成适配器契约套件（模拟实现全过，真实实现无凭证按用例跳过） |
| integration | 起 PostgreSQL 16 + MinIO → 迁移 → 集成测试（immutable 双保险 / jsonb / 三维索引 / 基准） |
| adversarial | **装 gVisor runsc 并注册 docker runtime**，断言后端可用（不可用即失败不降级），跑作弊三件套 |
| unbiasedness | τ ≥ 0.95 门禁与注入偏差拒绝用例 |

**推送通道（本机特有）**：WSL 里 `github.com` 被解析到回环地址（`::1`）无法直连，提交经
「WSL `git push win main` → 本地裸仓库 `D:\repos\cineflow_RSI.git` → Windows 重新 clone →
GitHub」中转，脚本为 `D:\repos\push-to-github.ps1`（含 `-DryRun`、行尾纪律校验、HEAD 一致性
校验；**只允许 clone 后直接 push，绝不在该目录提交**）。

**CI 首跑暴露并修复的五个真实缺陷**（本地环境照不出来，全靠 CI）：

1. **CRLF 污染**：Windows clone 里的提交把 `policies/history/*.py` 写成了 CRLF 内容，
   而文件名 = 内容 BLAKE3 → unit 红。修复：`.gitattributes`（`* text=auto eol=lf`）+ 中转脚本
   强制 `core.autocrlf=false` + 推前 `git ls-files --eol` 校验。
2. **schema 一致性测试在预迁移库上撞 `DuplicateTable`**：CI 先 `alembic upgrade head` 再跑
   pytest，而该测试清场只 drop 树表、没清两张运营表。修复：整 schema 重置后从零迁移。
3. **schema 重置后缺 `USAGE` 授权**（修复 2 的副作用）：应用账号连表都看不见。修复：测试清场
   补授权，且**迁移 0001 显式 `GRANT USAGE ON SCHEMA public TO cineflow_app`**，不再依赖 initdb 默认值。
4. **`docker compose up -d --wait` 返回 1**：`minio-init` 是一次性服务，退出即被 `--wait` 判失败。
   修复：长驻服务用 `--wait`，一次性服务单独 `up minio-init`（文档与 CI 同步）。
5. **基准 p99 擦线误报**（实测 50.7ms vs 阈值 50ms）：共享 runner 的调度/IO 离群停摆主导 p99。
   修复：改为「中位数守真实退化 + p99 守灾难停摆」双阈值，并支持 `CINEFLOW_BENCH_*` 覆盖。

顺带固化的两条环境纪律：PowerShell 重定向输出是 **UTF-16**（日志需转码再读）；
PS 5.1 执行含中文的 `.ps1` 必须 **UTF-8 with BOM**（无 BOM 会按 GBK 解码而语法报错）。

## 8. 遗留事项与二期范围

**一期遗留（不影响功能成立）**

1. 成本回归告警阈值（宪章门禁表）目前是执行器内三方对账，**每日定时告警任务待接运维**；
2. 人类评估锚点的录入通道、真实在线轨迹采集周期属运营接入；
3. 做梦审批的 `decide` 会全量重写 yaml（丢注释）——生产审批若需保注释，改定点改写；
4. 真实运营轮次的 `dreaming/history/` 与 `policies/history/` 数据待实际运行积累；
5. 集成基准的阈值是"守退化"而非"守指标"：CI 硬件噪声下限已由中位数阈值确定，
   性能画像的精确标定属二期（需要专用基准环境）。

**二期范围（宪章治理规则已锁定，一期禁止提前展开）**

- 跨项目发现树合并回放（池化复用）
- judge 漂移自动检测（对比历史锚点评分分布）
- 前端可视化（发现树浏览器、进化曲线看板）
- 策略部署评估自动化（去掉人工 approve）
- 剧本/开发 Agent 自动进化（视评估信号质量决定）
