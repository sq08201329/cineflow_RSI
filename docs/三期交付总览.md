## 1. 三期结论

**一句话定位**：CineFlow 是「影视全 Agents 自我进化生产系统」——七个生产 Agent 串成一条链
（`dev → script → storyboard → visual → sound → editing → promo`），每环各自跑一个
「发现树 + 回放模拟器 + 策略进化」的**内环**闭环；**做梦层**在模拟器池上零成本进化策略；
外层按周期做盲评校准与平台真值回流（**外环**）；三者立在业务无关的 **L1 基座**上
（发现树 / 回放引擎 / 沙箱 / 评估器注册中心 / 成本计量，见 `docs/影视全Agents公司技术方案.md` §1.1），
并由**宪章 + CI 门禁**贯穿约束（评估器版本冻结、节点不可变、昂贵动作仅限线上、诚实边界）。

**三期做了什么**：从「六个环节各自闭环 + 单形态排练」走到「**七 Agent 全链路 + 真实渠道（LLM 腿）+
四形态**」——即**治理转正与多形态扩展**。三个工作流各自收口：

| 里程碑（立项书 §4） | 特性 | 任务 | 状态 |
| --- | --- | --- | --- |
| 周 1~3：WS3 治理转正（影子期 / `auto` 开启 / 遗留 5·6 收口） | —（治理事项，非特性） | — | ⏳ 机制已交付，**影子期 ≥2 周属墙钟依赖**；遗留 5 已完成、遗留 6 待办（本文 §6） |
| 周 3~5：G1 开发 Agent 降级接入 | [017](../specs/017-dev-agent-degraded/spec.md) | 49 | ✅ 2026-09-23（T1701~T1749 全量落地） |

**总量**：三期五个特性 **323 个任务全部勾选**（49 / 35 / 51 / 86 / 102），新增 **2 个 DB 迁移**
（0010 `dev_jobs` / 0011 `daily_feedback`；018 / 019 / 021 零迁移），新增 **2 个业务无关
`core/` 通用件包**（`core/degraded/`、`core/billing/`）与插件化装配面

## 4. 与一/二期的衔接：机制交付 vs 等真实运营

**三期如何承接二期结转**（立项书 §5 对应表）：

| 二期遗留 | 三期落点与现状 |
| --- | --- |
| 真实 2 周影子期与误入率标定 | WS3 第 1 项——机制、计时门禁与对照报告已交付；**墙钟待运营**（本文 §6 ②） |
| B/C 路径未交付 | **G3**（LLM 渠道已交付）+ **G4**（投放侧机制已交付 / 真实回流待运营） |
| 抽检未复核告警阈值（二期已入配置） | 三期运营检验（`spot_check.pending_alert_days`：电影 7 天 / 短剧 2 天） |
| 基准性能画像标定（挂起） | WS3 第 3 项——仍挂起，需**目标基准环境**（本文 §6 ③） |
| ffmpeg 负载抖动 | WS3 第 4 项——运维化处置（编码重试 + 断点续跑）；根因属环境 |
| 运营数据积累（池子 / 曲线 / 判据） | 贯穿三期（G2 / G4 的真实运行，无代码变更） |
| 剧本 Agent 升级判据 | WS3 第 2 项——**治理决议，需人签署**（本文 §6 ④） |

**分层口径（三期把它从"配置动作"升级为"逐环节可机检的标注"）**：

1. **机制交付**（本文 §2 的"交付面"）：全部可**离线复现**——零真实花费、零外部网络、零凭证，
   且由常驻断言与退出码机检（如 `ops/demo_shortdrama_feedback.py` 七步退出码 0、
   `ops/demo_form_plugin.py` 对任何已声明形态零改动可演示）。
2. **等真实运营**（本文 §2 的"未交付面"）：只有三类**外部条件**能把机制变成结论——
   ① 真实凭证与账户；② 真实预算档数字与**墙钟窗口**；③ 业务侧判定（合规审查判据、形态业务定义与签字）。
3. **口径纪律**：未具备期间一律按「**最小规模档 + 如实标注"未标定"**」运行；产物与报告写
   「**机制已就绪 / …待运营**」；**禁止**以模拟冒充真实。`docs/pilot-upgrade-manifest.json` 的
   A 路径（LLM 腿）`delivered`、B 路径（真实生成）与 C 路径（真实投放）`not_delivered` **未改**。

## 6. 治理转正与遗留项

> 逐条给出**现状**与**依赖的外部条件**。①②的机制侧均已机检，"待办的是墙钟或凭证"。

   现状：覆盖 ∧ 连续双条件机检（`ops/billing.py runs`，`covered_days` **只计 `source=real`**、断档逐段
   报出、**禁止插值补齐**）；短剧态窗口下限 `budget.runs.min_window_days: 14`，未达标退出码 1 并点名缺口。
   当前仓内实测：`billing/llm/runs/` 的两条日片**全部 `source: simulated`** ⇒ 真实覆盖天数 **0**。
   依赖：**运营侧墙钟 + 平台凭证 + 真实预算**（三项齐备才起算）。

## 8. 跨特性关键设计决策（三期新增，复用价值最高的八条）

1. **机制侧不是零代码改动**（021）：`baseline_ref` 与 `mechanism_ledger_ref` **非空且不相等**，
   以 ledger 之前的 ref 为基线跑 `onboarding` ⇒ `violations` 必然非空并逐条命中 `modified` 项——
   把"我们改了多少"变成**可复现的反证**，而不是口头承诺。
2. **"恰好两份"升级为"登记完备"**（021）：`form:` 取值两两唯一 ∧ 派生形态集与各登记点**双向相等** ∧
   配置数 ≥ 2（下界保留）；删掉枚举式断言换成派生面，新形态**自动**进遍历面（静默逃逸被消除）。
3. **形态名只作数据、不作分支**（021）：守卫是**单一实现**（副本数 ⇒ 1），形态名一律由
   `configs/*.yaml` 的 `form:` 与 `form_aliases` 派生；两层扫描（字面量 + 判断分支）零违规。
4. **声明集即全集**（021）：`impl` 的**唯一解析点**是配置声明——插件文件放进目录但不在配置里声明 ⇒
   **装配期不可用**；"目录不决定可用性"堵死"假装绑定"。
5. **拒绝即零成本、已花的照记**（019）：预算拒绝走显式前置分支——被拒那一笔三量全零、后端 0 次调用，
   同轮**已发生**花费照常入账；"花了的钱"与"没花的钱"在账面上可分辨。
6. **分类只由声明的驱动列决定**（019）：账单差异六类**不用金额阈值或符号启发式**，映射不到即
   `unclassified` ⇒ 不可解释 ⇒ 100% 告警；宁可告警，不可静默归类。
7. **归属日必须由平台显式给出**（020）：`metric_date` 缺失即**显式失败**、该条不落锚点，
   归属日 / 采集墙钟 / 平台时间戳三者并列可见——**不以采集时刻兜底**，把"数据迟到/回补"变成可诊断事实。
8. **迁移只迁结论、不迁权重**（020）：迁移件 append-only、可比性条件**由配置声明**、不可迁移 100% 登记原因；
   采纳**不改变任何既有节点的 `eval_breakdown` 与得分**——跨形态先验不得绕过外环的人工确认。
