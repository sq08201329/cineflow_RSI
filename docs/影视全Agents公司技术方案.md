# 影视全 Agents 公司技术方案
## —— 以电影为主形态，基于 Dream-RSI 范式的自我进化生产系统

> 文档版本：v1.0　|　定位：公司级技术顶层设计文档
> 方法论基础：Dream-RSI（arXiv:2609.14858）的"发现树 + 回放模拟器 + 做梦式策略进化"框架
> 主形态：院线/网络电影（90~150 分钟）；扩展形态：短剧、广告、AI 漫剧（架构预留）

---

## 0. 设计总纲

### 0.1 核心命题

影视生产是典型的"评估高度主观、无廉价确定性评估器"领域，不能直接套用 Dream-RSI 原论文的闭环。本方案的核心设计思想是：

> **把"做梦"机制（记录—回放—策略进化）与"评估信号来源"解耦。做梦框架本身不挑评估器，它只要求评估器确定、可复现、足够便宜。因此系统设计的重心不在 Agent 智能程度，而在为每个环节构造满足这三条性质的评估器组合。**

### 0.2 三条不可动摇的系统公理

1. **评估器版本冻结**：一切评估器（硬规则、代理模型版本、judge 提示词、权重参数）必须版本化并随发现树节点落盘。评估器变化即意味着历史得分不可复现，回放模拟器正确性前提崩塌。
2. **昂贵资源只在线上探索阶段消耗**：视频生成、渲染、真人拍摄等昂贵动作只允许发生在真实执行中；回放阶段严格只读历史数据。成本模型完全依赖此纪律。
3. **人类是校准锚点，不是流水线工人**：人不参与逐条评估，只以稀疏抽检方式校准自动评估器的系统偏差。

### 0.3 形态扩展原则

电影 vs 短剧/广告的差别，本质不是生产流程的差别（流程同为：开发→前期→生成/拍摄→后期→宣发），而是三个参数的差别：

| 参数 | 电影 | 短剧/广告/漫剧 |
| --- | --- | --- |
| 真实反馈周期 | 极慢（上映后数月，票房/口碑） | 快（小时级，完播率/转化率） |
| 单项目成本 | 极高 | 低 |
| 评估信号主体 | 代理信号 + 影节/试映人评 + 滞后票房 | 平台数据直接可用 |

因此架构上把**评估器组合与反馈频率做成可配置插件**，同一套发现树/回放/做梦基建，换一套评估器配置即切换形态。短剧形态可作为电影形态的"高频练兵场"：在短剧上验证进化机制，把学到的策略与评估器校准结论迁移回电影线。

## 1. 系统总体架构

### 1.1 三层结构

```
┌────────────────────────────────────────────────────────────────────┐
│ L3 商业验证层（外环，周/月级）                                        │
│   试映评审 · 影节/点映反馈 · 票房与口碑数据 → 校准 L2 评估器          │
├────────────────────────────────────────────────────────────────────┤
│ L2 生产进化层（内环，天级）—— 每个 Agent 一个小型 Dream-RSI 闭环      │
│   开发Agent → 剧本Agent → 分镜Agent → 视觉Agent → 声音Agent          │
│      → 剪辑Agent → 宣发Agent                                        │
│   每个 Agent：发现树 + 回放模拟器 + 做梦式策略进化                     │
├────────────────────────────────────────────────────────────────────┤
│ L1 基础设施层（与业务无关，形态共享）                                  │
│   发现树存储 · 回放模拟器引擎 · 前缀可观测校验 · 沙箱执行              │
│   评估器注册中心 · 版本谱系 · 成本计量                                │
└────────────────────────────────────────────────────────────────────┘
```

### 1.2 七大生产 Agent 职责与进化对象

| Agent | 职责 | 探索策略（被进化对象） | 昂贵动作 |
| --- | --- | --- | --- |
| 开发 Agent | 选题、IP 评估、立项组合 | 题材方向探索策略 | 无（纯检索分析） |
| 剧本 Agent | 大纲→分场→剧本 | 结构探索策略（先写哪条线、分支数） | 无（文本生成，便宜） |
| 分镜 Agent | 剧本→分镜脚本/动态预演 | 镜头语言策略（景别节奏、备选数） | 预演渲染（中） |
| 视觉 Agent | 画面/片段生成 | 生成参数与重试策略 | 视频生成 API（高） |
| 声音 Agent | 配音、音效、配乐 | 声音风格探索策略 | TTS/音乐生成（中） |
| 剪辑 Agent | 粗剪→精剪→成片 | 剪辑节奏与结构策略 | 渲染合成（中） |
| 宣发 Agent | 物料、预告、投放策略 | 物料组合与投放策略 | 投放预算（高） |

**统一约定**：每个 Agent 的"探索策略"均为可执行代码（`OptimalPolicy.solve()` 形态），由元层策略开发 Agent 在回放模拟器中进化；底层生成模型权重一律不动。

## 2. 评估器体系设计（本方案的核心）

### 2.1 分级评估器框架

每个 Agent 的评估函数由四层信号加权合成，按可靠性递减、成本递增排列：

```
score = w1·硬规则 + w2·代理模型 + w3·Judge委员会 + w4·人类锚点(稀疏)
```

| 层级 | 性质 | 覆盖 | 成本 |
| --- | --- | --- | --- |
| L1 硬规则 | 确定性代码，二值/连续 | 可行性过滤 + 基础质量 | ~0 |
| L2 代理模型 | 冻结版本的检测/评分模型 | 技术指标 | 低 |
| L3 Judge 委员会 | 3 个固定提示词 LLM 成对比较投票 | 主观质量 | 中 |
| L4 人类锚点 | 内容负责人盲评 | 校准用，top-k 抽检 | 高（仅头部） |

### 2.2 各 Agent 评估器配置（电影形态）

**剧本 Agent**
- 硬规则：节拍表结构完整性（可解析的三幕/序列结构）、页数-时长换算（1 页≈1 分钟）、场景-角色一致性校验、对白/动作行比例统计
- 代理模型：角色名实体一致性检测、时间线冲突检测
- Judge：成对比较"哪个大纲的戏剧张力更强"，3 judge 投票
- 锚点：内容负责人每周评 3~5 份 top 大纲

**分镜 Agent**
- 硬规则：镜头语法（景别切换合理性规则库）、剧本覆盖率（每个场景必须有镜头承接）、轴规则检测
- 代理模型：预演画面与剧本情绪的 CLIP 类对齐度
- Judge：成对比较分镜与剧本段落的贴合度

**视觉 Agent**（评估信号相对最强，可作为内环验证先锋）
- 硬规则：分辨率/时长/帧率合规
- 代理模型：美学评分模型、人脸/主体跨镜头一致性嵌入距离、闪烁与伪影检测、运动幅度统计
- Judge：成对比较"哪条更电影感"

**声音 Agent**
- 硬规则：响度规范（对白 -27 LUFS ±2 等电影标准）、音画同步误差阈值
- 代理模型：ASR 转写与台词比对、情绪-配乐匹配度分类器

**剪辑 Agent**
- 硬规则：总时长合规、镜头时长分布统计、转场规则
- 代理模型：节奏曲线（镜头时长方差/趋势）与类型片基准曲线的距离
- Judge：成对比较 3~5 分钟片段的叙事流畅度

**宣发 Agent**（唯一接近"真实自动评估器"的环节）
- 预告片/物料先行投放小规模流量，直接以完播率、点击率、想看转化率作为确定性得分
- 这是整条链上唯一不需要 judge 的环节

**开发 Agent**
- 代理信号：历史票房数据库的同类型回归预测、舆情检索热度
- 重要警示：该环节信号噪声最大，**建议只复用记录-回放骨架，策略由人主导**，不做自动进化（对应通用方案中的"诚实边界"）

### 2.3 评估器注册中心

所有评估器以插件形式注册，强制携带：

```python
@dataclass
class EvaluatorSpec:
    evaluator_id: str          # 唯一标识
    version: str               # 语义化版本，任何变更必须升版
    kind: str                  # rule | proxy_model | judge | human
    deterministic: bool        # 必须为 True 才能用于回放打分
    cost_per_call: float       # 成本计量
    calibration: dict          # 最近一次人评/票房校准的偏差记录
```

非确定性评估器（含随机性的模型）必须固定种子并缓存结果，否则只能用于线上探索、禁止用于回放。

## 3. 基础设施层（L1）设计

### 3.1 发现树存储

电影项目单条线索即可达数万节点，且节点携带工作区快照（剧本版本、分镜稿、素材引用），存储设计：

- **内容寻址 + 增量快照**：素材大文件只存哈希引用，快照只存 diff；
- **谱系索引**：`(项目, Agent, 策略版本)` 三维索引，支撑跨项目回放；
- **只读约束**：节点写入即 immutable，由存储层强制。

### 3.2 回放模拟器引擎

- **前缀可观测拦截层**（正确性核心）：策略在回放中只能读取"按其走法本应已揭示"的节点信息；为拦截层配备对抗性单元测试（故意编写试图偷看未来的作弊策略，验证必然被拦截）；
- **虚拟时钟**：实现决策轮与有效串行轮计数，支持并行惩罚计算，不要求真实并行执行昂贵动作；
- **无偏性验收标准**：新评估器上线前，必须用"回放得分 vs 真实重跑得分"的一致性测试验收（相关系数门槛建议 ≥0.95）。

### 3.3 沙箱执行

LLM 生成的策略代码与候选工件（脚本、剪辑指令）一律容器化执行：资源限额、网络隔离、素材库只读挂载。

### 3.4 成本计量

每次 LLM 调用、生成 API 调用、渲染、人评工时统一入账到节点 `CostRecord`。这是对内证明"做梦省算力"、对外支撑商业模型的核心数据。

## 4. 双层闭环运行机制

### 4.1 内环（天级，每 Agent 独立运行）

1. **线上探索**：当前策略执行真实生产任务（消耗真实预算），全程落发现树；
2. **树转模拟器**：新树冻结入库，加入该 Agent 的模拟器池；
3. **做梦进化**：策略开发 Agent 生成上百套候选策略代码，在模拟器池零成本回放打分，奖励函数沿用 `pareto_auc − λ·parallel_penalty`；
4. **优胜策略次日部署**，进入下一轮。

**冷启动**：每个 Agent 第一轮用手工策略跑一个完整任务形成引导树，策略控制器从模仿成功轨迹起步。

### 4.2 外环（周/月级，公司级）

- **周校准**：内容负责人对 top-k 产出盲评，检测结果写入评估器注册中心的 `calibration` 字段，自动触发代理权重再拟合；
- **月/项目级真值回流**：试映反馈、影节结果、票房/流媒体数据回流，回答"哪个内环指标真的预测商业成功"——例如可能发现"judge 的戏剧张力分与试映留存强相关，而美学评分几乎无关"，据此重新配权；
- **跨形态迁移**：短剧线高频数据验证出的评估器校准结论，按迁移学习思路平移到电影线作为先验。

### 4.3 两条风险红线

1. **回放过拟合**：策略在历史树上表现好 ≠ 新题材上表现好。缓解：模拟器池持续扩容、保留 ε-随机探索比例、每月一次纯在线验证集对照；
2. **Reward hacking**：策略学会讨好 judge（更长、更华丽、更自信的产出）。缓解：judge 委员会多提示词 + 盲测样本 + 人评锚点监控 judge 漂移。

## 5. 组织与实施计划

### 5.1 团队配置（第一期，约 8~10 人）

| 角色 | 人数 | 职责 |
| --- | --- | --- |
| 平台工程师 | 2 | L1 基建：发现树、回放引擎、沙箱 |
| 评估工程师 | 2 | 各 Agent 评估器实现与校准 |
| Agent 工程师 | 2 | 生产 Agent 与策略开发 Agent |
| 内容负责人 | 1 | 人评锚点、评估口径裁决 |
| 制片/宣发 | 1~2 | 试映组织、投放执行 |

### 5.2 三阶段落地路线（总计约 9 个月）

**阶段一（月 1~3）：基建 + 双先锋环节闭环**
- 完成 L1 全部基建；
- 打通**宣发 Agent**（唯一真实自动评估器环节，验证整个做梦机制）与**视觉 Agent**（代理信号最强）两个闭环；
- 产出：基建可用、两个环节的策略进化曲线、第一批成本对比数据。

**阶段二（月 4~6）：生产链铺开**
- 声音、剪辑、分镜 Agent 接入；剧本 Agent 以"记录-回放 + 人工改策略"的降级模式接入；
- 外环周校准机制运转；
- 产出：首部 AI 主导的中短体量试水作品（可用短剧形态练兵）。

**阶段三（月 7~9）：电影长片全流程 + 多形态扩展**
- 七 Agent 全链路跑通一部电影长片；
- 剧本 Agent 视 judge 信号质量决定是否升级为自动进化；
- 以配置化评估器插件方式接入短剧/广告形态，验证形态扩展性。

### 5.3 成功度量（北极星指标）

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 进化增益 | 同任务下，进化 N 轮后策略 vs 初始策略的回放/在线得分比 | 持续 >1 且无平台期塌缩 |
| 算力杠杆比 | 达到同等质量的真实调用次数：传统方式 / 本系统 | 阶段一 ≥10×，阶段三 ≥50× |
| 评估器信度 | 内环得分与人评/商业结果的相关系数 | 逐月上升，核心环节 ≥0.6 |
| 单项目边际成本 | 第 N 部片 vs 第 1 部片的总成本 | 显著递减（复利曲线） |

## 6. 与传统影视公司/普通 AI 工具流的差异

| 维度 | 传统影视公司 | AI 工具辅助流 | 本方案 |
| --- | --- | --- | --- |
| 经验沉淀 | 人脑，随人员流失 | 无沉淀 | 发现树，公司级可复用资产 |
| 策略改进 | 项目复盘，低频 | 靠人调 prompt | 做梦式自动进化，天级 |
| 试错成本 | 真实拍摄/生成 | 真实生成 | 回放零成本试错 |
| 规模瓶颈 | 人才与资本 | 生成成本 | 评估器信度（可工程化改善） |

**核心资产观**：这家公司真正的护城河不是 Agent，而是**持续膨胀的跨项目发现树库 + 被真实商业数据反复校准过的评估器体系**——两者都随时间复利，且无法被购买。

## 7. 风险登记册

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 剧本/开发环节评估信号过弱，进化失效 | 高 | 降级为人工策略 + 回放沙盘；不硬进化 |
| Judge 漂移导致全线 reward hacking | 高 | 委员会 + 盲测 + 人评锚点监控 |
| 电影反馈周期过长，外环校准太慢 | 中 | 短剧线作高频练兵场，校准结论迁移 |
| 快照存储成本爆炸 | 中 | 内容寻址去重 + 低价值分支剪枝 |
| 生成素材版权/合规 | 中 | 素材来源审计链，节点记录生成来源 |
| 前缀泄露 bug 使全部实验失真 | 低概率高影响 | 对抗性单元测试 + 上线前无偏性验收 |
