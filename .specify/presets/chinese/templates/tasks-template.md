# 任务列表：[FEATURE NAME]

**输入**: 来自 `/specs/[###-feature-name]/` 的设计文档

**前置条件**: plan.md（必需）、spec.md（用户故事必需）、research.md、data-model.md、contracts/

**测试说明**: 下文包含测试任务示例。测试是可选的——仅在功能规格中明确要求时才包含。

**组织方式**: 任务按用户故事分组，支持每个故事的独立实现和测试。

## 格式：`[ID] [P] [Story] 描述`

- **[P]**: 可并行（不同文件，无依赖）
- **[Story]**: 属于哪个用户故事（如 US1、US2、US3）
- 描述中包含具体文件路径

## 路径约定

- **单一项目**: `src/`、`tests/` 在仓库根目录
- **Web 应用**: `backend/src/`、`frontend/src/`
- **移动端**: `api/src/`、`ios/src/` 或 `android/src/`
- 以下路径假设为单一项目——根据 plan.md 结构调整

## 依赖关系与执行顺序

### 阶段依赖

- **搭建（阶段 1）**: 无依赖——可立即开始
- **基础（阶段 2）**: 依赖搭建完成——阻塞所有用户故事
- **用户故事（阶段 3+）**: 全部依赖基础阶段完成
  - 用户故事可并行推进（多人协作）
  - 或按优先级顺序推进（P1 → P2 → P3）
- **打磨（最后阶段）**: 依赖所有需要的用户故事完成

### 用户故事依赖

- **用户故事 1（P1）**: 基础（阶段 2）后可开始——不依赖其他故事
- **用户故事 2（P2）**: 基础（阶段 2）后可开始——可能集成 US1 但应可独立测试
- **用户故事 3（P3）**: 基础（阶段 2）后可开始——可能集成 US1/US2 但应可独立测试

### 每个用户故事内部

- 测试（如包含）必须在实现前编写并通过失败验证
- 模型先于服务
- 服务先于端点
- 核心实现先于集成
- 故事完成后再进入下一优先级

### 并行机会

- 所有标记 [P] 的搭建任务可并行
- 所有标记 [P] 的基础任务可并行（阶段 2 内）
- 基础阶段完成后，所有用户故事可并行开始（如人力允许）
- 用户故事的测试中标记 [P] 的可并行
- 故事内的模型中标记 [P] 的可并行
- 不同用户故事可由不同成员并行推进

## 实现策略

### MVP 优先（仅用户故事 1）

1. 完成阶段 1：搭建
2. 完成阶段 2：基础（关键——阻塞所有故事）
3. 完成阶段 3：用户故事 1
4. **停下并验证**：独立测试用户故事 1
5. 准备就绪后部署/演示

### 增量交付

1. 完成搭建 + 基础 → 基础就绪
2. 添加用户故事 1 → 独立测试 → 部署/演示（MVP！）
3. 添加用户故事 2 → 独立测试 → 部署/演示
4. 添加用户故事 3 → 独立测试 → 部署/演示
5. 每个故事增加价值而不破坏先前故事

### 并行团队策略

多人开发时：

1. 团队共同完成搭建 + 基础
2. 基础完成后：
   - 开发者 A：用户故事 1
   - 开发者 B：用户故事 2
   - 开发者 C：用户故事 3
3. 故事独立完成和集成

## 备注

- [P] 任务 = 不同文件，无依赖
- [Story] 标签将任务映射到特定用户故事以便追溯
- 每个用户故事应可独立完成和测试
- 验证测试在实现前必须先失败
- 每个任务或逻辑组后提交
- 在任何检查点停下，独立验证故事
- 避免：模糊的任务、相同文件冲突、破坏独立性的跨故事依赖
