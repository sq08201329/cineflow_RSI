# CineFlow 项目宪章

本宪章是「影视全 Agents 自我进化生产系统」（CineFlow）的最高工程约定，约束 L1 基建层、
L2 生产 Agent 层与做梦层的全部设计与实现。技术依据见 `docs/影视全Agents公司技术方案.md`
（顶层设计）与 `docs/CineFlow开发文档.md`（工程实现）。

## 核心原则

### 一、评估器确定性与版本冻结（不可协商）

- 一切评估信号（硬规则、代理模型、judge 提示词、合成权重）**必须**版本化，并以
  `evaluator_id@version` 全局唯一标识注册；同 id 同 version 重复注册**必须**被拒绝，
  任何行为变更**必须**升版本号。
- 用于回放打分的评估器**必须**是确定性的（`deterministic=True`）。非确定性评估器
  （含随机性的模型）**禁止**进入回放打分路径，除非固定随机种子并缓存结果。
- 每个节点的 `eval_breakdown` **必须**包含其所用每个评估器的 `evaluator_id@version`，
  缺失即拒绝写入；评估器配置与权重**必须**以全量快照冻结进
  `DiscoveryTree.config_snapshot`。
- `human` 类评估器**仅**作为校准锚点存在，其产出（人评、平台回流数据）一经写入即冻结为常数。

**理由**：评估器一旦变化，历史得分不可复现，"回放即等价于重跑"的前提崩塌，整套进化机制
随之失效。评估器版本冻结不是工程洁癖，而是系统正确性的第一前提。

### 二、节点不可变与全量谱系（不可协商）

- 发现树节点一经落盘即 **immutable**：领域模型使用 `frozen=True` 的 dataclass，
  存储层（PostgreSQL）**必须**用触发器拒绝 `UPDATE`/`DELETE`，只允许 `INSERT`。
- 每个节点**必须**完整记录 `TreeNode` 的全部字段：`node_id`、`tree_id`、`parent_id`、
  `depth`、`agent_id`、`policy_version`、`prompt`、`observation_context`、`artifact_hash`、
  `eval_breakdown`、`score`、`cost`、`status`、`created_at`。
- 工件**必须**内容寻址存储（BLAKE3 哈希作为对象存储 key），天然去重。
- `CostRecord` 对每个节点**必须**入账，包括 `FAILED` 节点——成本已经发生，不得因失败而不计。
- 谱系**必须**全链路可查：`(policy_version → tree_ids → child_policy_versions)`，
  并支持按 `(项目, Agent, 策略版本)` 三维索引。

**理由**：发现树是公司级可复用资产与唯一的事实来源。任何就地修改都会同时破坏可复现性与
审计能力；成本数据是"做梦省算力"这一商业命题的唯一证据，不允许有缺口。

### 三、昂贵动作仅限线上探索（不可协商）

- 视频生成、渲染、TTS、真实投放、真人拍摄等昂贵动作**只允许**发生在线上真实探索阶段。
- 回放模拟器路径内 `max_generation_calls` **恒为 0**：**禁止**在模拟器内触发任何内容生成，
  **禁止**由模拟器编造或插值历史得分。做梦层自身生成候选策略代码的 LLM 调用不受此限，
  但同样**必须**经网关计费入账。
- 回放中的揭示**必须**返回与该父节点、该生成参数**精确匹配的真实历史节点**；无匹配时
  **必须**返回 `UNKNOWN` 且策略不得获得得分。
- 经验覆盖不足**必须**通过扩大线上探索解决，**禁止**通过放宽模拟器匹配来"补齐"。
- 一切 LLM 调用**必须**经由自研 LLM 网关（统一计费、缓存、重试），**禁止**业务代码
  绕过网关直连模型 API。

**理由**：成本模型与"零成本试错"的承诺完全建立在这条纪律上。模拟器一旦被允许生成数据，
系统就退化为一个昂贵的幻觉机器，且成本账目不再可信。

### 四、沙箱隔离与前缀不可泄露（不可协商）

- 策略代码**必须**在独立容器（Docker + gVisor runtime）中执行：资源限额、网络隔离、
  素材库只读挂载，且不持有对象存储凭证。
- 策略与模拟器之间**必须**通过 IPC 交互，**禁止**同进程传递对象；模拟器的未揭示状态
  (`_latent`) 在沙箱内**必须**物理不可达。
- 策略的信息入口**仅限** `observed()` 与 `probe()` 两个方法；拦截层只暴露
  `observation_context` 中允许的字段。
- 对抗测试（`tests/adversarial/`）**必须**作为合并阻塞门禁常驻 CI，至少覆盖：
  `peek_latent`（反射偷看未揭示节点必须失败）、`timing_side_channel`（响应时间必须加入
  固定抖动）、`hash_oracle`（用 `artifact_hash` 反查对象存储必须 403）。
- 回放响应时间**禁止**携带任何与隐藏得分相关的信息。

**理由**：前缀泄露是低概率、高影响缺陷，一旦发生会让全部实验结论失真且难以察觉。
唯一可靠的防线是"物理不可达 + 对抗测试"，而非代码评审时的自觉。

### 五、单向依赖与形态配置化（不可协商）

- 依赖方向**必须**严格单向：`agents → core`、`dreaming → core`，**禁止**任何反向依赖；
  `core/` **必须**保持业务无关。
- 形态差异（电影 / 短剧 / 广告 / 漫剧）**必须**通过 `configs/*.yaml` 配置表达——
  评估器组合、权重、预算、并行度、反馈频率；切换形态**必须**零代码改动。
- 形态配置例外情况**必须**是"新增配置项"而非"新增分支代码"。
- 编排**必须**使用自研轻量 DAG 执行器，**禁止**引入 Airflow 等静态 DAG 框架
  （探索决策是动态的，静态框架不匹配）。
- Web 前端（二期起允许）**必须**是只读视图：**禁止**在 Web 层写入发现树、谱系、
  部署指针与任何权威数据；前端代码**必须**独立于 `core`/`agents`/`dreaming`，
  仅经只读查询接口取数。

**理由**：`core` 一旦混入业务概念，跨形态复用与跨项目回放池化即失效；配置化是"同一套
基建、多形态复用"这一核心资产观的技术载体。范围纪律则保护一期能否按期闭环。

### 六、诚实边界与人类锚点（不可协商）

- 评估信号过弱的环节**禁止**强行自动进化：开发 Agent（选题/IP 评估）一期**仅复用**
  记录-回放骨架，策略由人主导，不做自动进化；剧本 Agent 在阶段二以"记录-回放 +
  人工改策略"降级模式接入，是否升级为自动进化取决于 judge 信号质量。
- 人类是校准锚点，不是流水线工人：人**不得**参与逐条评估，**只**以稀疏抽检方式
  （top-k 盲评）校准自动评估器的系统偏差，校准结论**必须**写入评估器的 `calibration` 字段。
- Judge 漂移**必须**被持续监控（委员会多提示词 + 盲测样本 + 人评锚点对比）。
- 策略部署（二期起）：候选策略**必须**同时满足证据门槛——回放 reward 超过现部署版本、
  validation 排名不跌出前 20%、judge 漂移检测通过——方可自动接班部署；人工 approve
  转为事后抽检，抽检否决**必须**立即回滚并恢复全人工审批，直至门槛重新标定。
  自动部署机制上线前**必须**先以影子模式运行并记录对照证据。
- 指标口径**必须**可被证伪：任何"提升了质量"的结论**必须**给出对应的评估器、版本与
  可复现的回放证据。

**理由**：本系统是 Dream-RSI 在"弱评估"领域的工程化外推，而非原论文范围内的直接套用。
在评估信号不足以支撑自动进化的地方诚实地降级，比让 reward hacking 污染整条链路更可取。

## 技术栈与架构约束

| 层 | 约束 |
| --- | --- |
| 语言与包管理 | Python 3.11+，依赖与虚拟环境统一用 `uv` 管理 |
| 任务编排 | 自研轻量 DAG 执行器 |
| 存储 | PostgreSQL（元数据/谱系） + S3 兼容对象存储（工件/快照） |
| 内容寻址 | BLAKE3 哈希，工件 key 即哈希 |
| 沙箱 | Docker（gVisor runtime） |
| LLM 接入 | 自研薄网关，统一计费/缓存/重试 |
| 交付形态 | 内部 CLI + JSON 报告；二期起增加只读 Web 看板（`web/`） |

Monorepo 结构**必须**保持如下边界，新增目录**必须**先归入 `core`（业务无关）或
`agents`（业务相关）之一；二期起 `web/`（只读前端，见原则五）为唯一例外：

```
cineflow/
├── core/         # L1 基建：tree / replay / sandbox / llm_gateway / cost / evaluators
├── agents/       # L2 生产 Agent：visual / promo ...
├── dreaming/     # 策略开发 Agent + 奖励函数
├── policies/     # 探索策略基类 + 历史版本（history/{agent_id}/{version}.py）
├── configs/      # 形态配置（movie / shortdrama / ...）
├── tests/        # adversarial（合并阻塞） / unbiasedness（发布阻塞）
└── ops/          # 部署、迁移、数据回流脚本
```

**策略版本标识**：`version` = 策略代码内容的 BLAKE3 前 12 位；策略即代码，代码变更即版本变更。

## 开发工作流与质量门禁

**测试纪律**

- 遵循 TDD：先写测试 → 审查确认测试有效（必须能因目标行为缺失而失败）→ 再实现。
- 测试**禁止**依赖真实昂贵调用（视频生成、真实投放）；此类路径以录制的历史节点/夹具替代。
- 新增评估器**必须**同时提交：单元测试、注册元数据（含 `cost_per_call`）、
  与既有评估器的对比样本。

**门禁清单（对应开发文档 §8，全部为强制项）**

| 门禁 | 内容 | 阻塞级别 |
| --- | --- | --- |
| 对抗测试 | 全部作弊策略必须被拦截 | 合并阻塞 |
| 无偏性测试 | 回放轨迹与真实轨迹得分序列 Kendall τ ≥ 0.95 | 新评估器/Agent 发布阻塞 |
| Immutable 审计 | 随机抽 100 个历史节点重算 score，与落盘值一致 | 每日定时，失败即告警 |
| 成本回归 | 相同回放任务成本突增 > 20% | 每日定时告警 |

**过拟合与多样性约束**

- 模拟器池**必须**按时间划分 train/validation 树，**最近一棵树永远只做 validation**。
- 候选策略在 train 上第一但 validation 跌出前 20%，**必须**判为过拟合并丢弃。
- 线上探索**必须**保留 ε=0.1 的随机预算以维持树多样性。
- 奖励函数**必须**为 `pareto_auc(score, probes) − λ·parallel_penalty`，并行惩罚基于虚拟时钟
  的有效串行轮 `ceil(batch_size / worker_count)` 计算。

**里程碑验收（一期）**

| 周 | 交付物 | 验收 |
| --- | --- | --- |
| 1~3 | core/tree + core/evaluators + 注册中心 | 单元测试覆盖率 ≥ 85% |
| 4~6 | core/replay + sandbox + 对抗测试套件 | 作弊策略全拦截；无偏性 τ ≥ 0.95 |
| 7~8 | agents/promo 全闭环（真实投放，单轮 ≤ 总预算 2%） | 首轮进化曲线产出，成本数据入账 |
| 9~10 | agents/visual 五个评估器 + 闭环 | 回放打分与真实重跑一致性验收 |
| 11~12 | dreaming 层 + 谱系报表 | 连续 5 轮进化 reward 曲线无塌缩 |

**评审要求**

- 每个 PR **必须**在描述中声明其触及的宪章条款，并说明合规方式；触及"不可协商"条款的
  变更**必须**走宪章修订流程，不得以代码变更绕过。
- 变更**必须**可回放验证：涉及评估器、策略、模拟器的变更**必须**附带回放对比证据。
- 复杂度**必须**被论证：新增抽象、框架、依赖需说明为何不能用既有能力解决（YAGNI）。

## 治理规则

- **效力**：本宪章高于项目内其他一切工程实践与口头约定；与技术方案文档冲突时以本宪章为准，
  并**必须**同步修订文档。
- **修订流程**：任何修订**必须**以 PR 形式提交，包含——变更理由、受影响的原则或章节、
  迁移计划（对已落盘历史数据的兼容性影响）、以及修订后的版本号。
- **版本策略**：语义化版本。MAJOR = 移除或重新定义原则等不兼容变更；MINOR = 新增原则或
  实质性扩充；PATCH = 措辞澄清、错别字、非语义性调整。
- **合规评审**：每个 PR 与发布**必须**核对门禁清单；Immutable 审计与成本回归为每日定时任务，
  失败即告警并**必须**在下一个工作日内定位。
- **已知边界**：跨项目发现树合并回放、judge 漂移自动检测、前端可视化、策略部署评估
  自动化已随二期立项（`docs/二期立项书.md`）解禁，按二期特性 F6~F9 各自的规格与
  前置条件推进；剧本/开发 Agent 自动进化仍为受控事项，升级须另立决议。
