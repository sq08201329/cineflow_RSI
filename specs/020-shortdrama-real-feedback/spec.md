- Q: 日级量纲怎么定（缺口 A：周期标签一律取 ISO 周、漂移窗口按周计）？ → A: **周期标签与漂移窗口都按"外环量纲"**。周期标签**必须**由形态声明的 cadence（`calibration.period_days`）**派生**（周级 ⇒ ISO 周、日级 ⇒ 日期），**不得**再一律取 ISO 周；漂移窗口的**单位与 cadence 同量纲**（日级 `window: 3` = **3 天**，周级 = 3 周），并写进产物。硬要求：**同一周期多轮零覆盖**（机检——同日级周期内多份快照/报告不得互相覆盖），且"外环日级"必须有**运转**断言而不是只断言配置数字。
- Q: 周期窗口的边界口径怎么定（缺口 B：缺省窗口跨 `period_days + 1` 天）？ → A: **统一为半开区间**。窗口 = `[start, start + period_days)`（按日历日），边界口径**显式声明并机检**（`end - start == period_days`）；**禁止**再出现"缺省跨 `period_days + 1` 天"的含首尾口径。
- Q: 日级"多日采集"怎么承载（缺口 C：既有"一次活动一次快照"、`node_id` 即终态唯一标识）？ → A: **同一投放活动按"采集日"分片**。每个日级周期一份快照，唯一性键由"活动"改为 **（活动, 周期）**；`node_id` **不再是**终态唯一标识；同一活动跨多日各采一次**必须合法且不覆盖**。
- Q: 投放渠道接进门禁的命名空间与单渠道硬拒绝怎么处理（缺口 D，结构性前置）？ → A: **给 019 的 `budget` 段补渠道命名空间并放开单渠道硬拒绝**。`tiers` 由扁平环节键改为**按渠道分组**（`channels.<id>.tiers.<环节>`），`sole_channel()` 的硬拒绝改为"**按配置声明的渠道集合分派额度**"；**旧扁平形状仍可读**（迁移规则明示、不得静默误判为另一个渠道）；这是对 019 的**兼容性扩展**，019 的既有断言按扩展更新（**不削弱**）。同时明确区分 **015 的进程内按轮上限**与 **019 的跨进程账本**，不得混同。
- Q: 周期归属按"归属日"还是采集时刻（缺口 E）？ → A: **周期归属由显式"归属日"决定**——取**平台指标所描述的日期（归属日）**，不是采集时刻；平台真值锚点的 `created_at` **保持**平台时间戳、回流节点 `created_at` **保持**采集墙钟，**三者都要在报告里可见**；周期窗口**按归属日过滤**；迟到/回补按归属日归入对应周期，且**不得改写历史锚点**（human 锚点一经写入即冻结，原则一）。
- Q: 同周期多轮时，漂移该读哪一份快照（010 的读取口径是"每周期恰好一个文件"）？ → A: **快照是"周期物化"、不是"某一轮的产物"**。快照主键 =（评估器, 周期），沿用 010 路径形状（`core/calibration/drift_metrics.py:140-142` `snapshot_path`），其内容 = **该周期全部锚点**的分布；**漂移每周期读一份**（读取时刻取该周期**最后一次物化**，缺文件 ⇒ 该周期不参与窗口、缺口如实报，沿用 `read_snapshot` 返回 `None` 的既有语义，`:145-151`）；漂移产物**必须**记录所读快照的**指纹与该周期锚点数**，使"读的是哪一份"可追溯。同周期多轮若使快照内容变化（迟到/回补的锚点后到）⇒ **必须记账**（台账行登记锚点数与快照指纹），**禁止静默改写**（"内容变了但无人知道"次数恒为 0，SC-002 机检）。
- Q: 半开区间切换后与既有周级窗口的可比性怎么留痕？ → A: **口径必须进产物、变更必须留痕**：产物**必须**写出 `window_semantics = half_open` 与 `period_days`；跨"口径变更日"的窗口**比较**必须在报告里**显式标注**该变更日（`note` 字段），**禁止**静默比较两段不同口径的窗口；历史已落盘产物与已冻结结论**零回改**（原则一/二），变更只对新窗口生效。
- Q: "同周期多轮零覆盖"与"同一（活动, 周期）重复回流幂等拒绝"是同一件事吗？ → A: **两条规则并存、各管一层、不得互相吞并**：① **快照层（按事件）**——唯一性键 =（活动, 周期），同键再次回流 ⇒ **幂等拒绝**（零变更、整批不中断），故"同一活动同一天的第二次采集"是**拒绝**而非覆盖；② **外环产物层（按轮）**——**同一周期内的多轮**各自的台账行与信度报告**必须并留存**（文件名带轮标识）、**零覆盖**（"后写覆盖前写"次数恒为 0）。"同一活动跨多日"是**不同周期** ⇒ 合法追加新快照；"同周期多轮"指**外环轮次**，不是同一活动在同一周期的重复采集。两条**分别**机检（SC-002）。
- Q: "归属日"到底从哪儿来（现有模型只有 `platform_timestamp: float`，`agents/promo/platform/base.py:79`）？ → A: **必须由平台接口显式给出的"指标日期"字段承载**——适配器**必须**在快照中暴露该日期（字段名以代码读取点为权威，plan 定），**缺失即显式失败**并给出原因（"平台未提供指标归属日"），该条**不落锚点**、不参与周期归属；**禁止**以拉取/采集时刻兜底（兜底会把缺口 E 重新引入）。`platform_timestamp` 保持"平台时间戳（真值产生时刻）"语义，**与归属日不等同**（两者相同只是巧合，报告须并列可见）。若平台侧确实不提供归属日 ⇒ 记入开放问题 1 由运营侧确认；未确认期间**不得**发明，如实标注"未标定"。

### 用户故事 1 - 日级指标回流与外环日级运转（优先级：P1）🎯 MVP

运营按日把短剧投放的平台指标回流进系统：每天一批真实指标落成 `human` 锚点（**写入即冻结为常数**，原则一），外环按**日**产出校准与漂移结论；日级窗口的覆盖与连续可机检——**断档如实报缺口，不插值补齐**；样本不足时如实标"样本不足"，不硬判、不编数。

**为什么是这个优先级**: G4 行第一句的内容就是"日级指标回流、外环频率日级运转"，G4 行第一条关键验收也建立在它之上。而它今天的**名不副实**是本次勘查发现的最硬的机制缺口：周期标签取 ISO 周、漂移窗口按周计，日级运转会互相覆盖（见 Clarifications 第 2 条）——量纲口径已裁决（第 7 条），**必须**落到产物与**运转断言**上。没有这一层，后面两条用户故事都没有日级真实数据作载体。

**独立测试**: 用夹具平台指标 + 固定时钟跑日级运转可完整测试：`period_days: 1` 生效后，**同一日级周期内多轮**的台账/快照/报告**互不覆盖**且写入即冻结；周期标签由 cadence 派生为**日期**（周级形态仍取 ISO 周，历史产物逐字节不变）；漂移窗口单位为**天**（`window: 3` = 3 天）；窗口为半开区间 `[start, start + period_days)`（`end - start == period_days`）；日级窗口机检对"连续 15 天"夹具通过、"15 天真实但缺 2 天"夹具**不通过**且断档逐段报出（不插值）；同一活动跨多日各采一次**合法且零覆盖**、同一（活动, 周期）重复回流幂等拒绝、既有锚点改写在存储层被拒；样本不足时台账只写"样本不足"备注、不产偏差值。

**验收场景**:

1. **Given** 短剧形态配置声明 `calibration.period_days: 1`, **When** 生成周期标签与产物路径, **Then** 标签由 cadence **派生**（日级 ⇒ 日期；周级 ⇒ ISO 周）、漂移窗口单位与 cadence **同量纲**（日级 `window: 3` = 3 天、周级 = 3 周）、窗口为半开区间 `[start, start + period_days)`；**同一周期内多轮**落盘到**不同**的台账行/快照/报告，零覆盖
2. **Given** 一份日级真实指标, **When** 回流, **Then** 落成 `human.platform_metrics@1.0.0` 锚点，周期归属按其**归属日**（平台指标所描述的日期）判定，且**归属日、采集墙钟、平台时间戳三者都在报告中可见**
3. **Given** 同一投放活动跨多日各采一次指标, **When** 回流, **Then** 每次落一份按**采集日**分片的快照，唯一性键为**（活动, 周期）**（`node_id` 不再是终态唯一标识），多次采集**合法且零覆盖**
4. **Given** 同一（活动, 周期）的重复回流, **When** 再次写入, **Then** 同键幂等拒绝（零变更），既有锚点**改写在存储层被拒**（冻结为常数）
5. **Given** 日级运行记录（真实来源）, **When** 机检 ≥2 周窗口, **Then** **同时**满足覆盖 ≥ `min_window_days` 与最长断档 ≤ `gap_tolerance_days` 方通过；仅累计够天数但有断档**不得**通过，缺口区间与最长断档天数**逐段如实报出**
6. **Given** 断档期间的日级运转, **When** 产出校准/漂移结论, **Then** 断档与样本不足如实标注（漂移判"样本不足"而不硬判），**不得**插值补齐、不得以模拟数据顶替真实日
7. **Given** 平台指标迟到或回补, **When** 回流, **Then** 按其**归属日**归入对应周期并**如实标注**（采集日与归属日不一致时两者都可见），**不得**静默改写已冻结的历史锚点

### 用户故事 2 - C 路径真实投放接入（优先级：P2）

运营把真实投放渠道接进系统：先在配置里**如实登记**渠道与凭证环境变量名（**本特性不发明平台名与凭证**），凭证缺失即**装配期显式拒绝启动**（不静默降级为模拟）；投放调用**必须**先过**按环节分档的前置预算门禁**（超限即拒绝且零入账），并在首次接入时按**最小规模**验证协议与计费口径；投放后产出**平台账单对账**差异报告。校准未通过**不得扩量**。

**为什么是这个优先级**: 宪章原则三的第一句就是这门禁，且 019 已把机制交付好——本特性只是把**媒体渠道这个新渠道面**接上去（019 明文把媒体渠道结转给 G4）。它排在 P1 之后是因为日级回流的**前提**正是"有真实投放产生真实指标"，但机制层的接入动作独立可测，故仍是独立切片。渠道命名空间已裁决（Clarifications 第 10 条）：`budget` 段按渠道分组、放开单渠道硬拒绝，属对 019 的**兼容性扩展**（既有断言按扩展更新、**不削弱**）。

**独立测试**: 用 Mock 平台后端 + 夹具账单可完整测试：凭证缺失即装配拒绝（不回落模拟）；超限投放申请被**调用前拒绝**、平台调用 0 次、零入账；最小规模投放后产出校准记录（含协议与计费口径偏差）；无合格校准记录的扩量请求被拒并留痕；账单导入 → 差异报告每项带分类与口径备注、不可解释项 100% 告警。

**验收场景**:

1. **Given** 投放渠道已登记且按环节声明预算档, **When** 一轮投放申请额超出剩余额度, **Then** **调用前拒绝**、平台调用 0 次、成本入账 0、原因落盘

3. **Given** 首次接入真实投放, **When** 以最小规模跑通, **Then** 产出**协议与计费口径校准记录**（配置价目/实测花费/偏差/口径备注/样本量/时间），低于样本下限即 `passed=false`
4. **Given** 校准未通过或记录过期, **When** 请求扩量, **Then** 拒绝并留痕，拒绝理由点名命中的是哪一条（无记录/过期/样本不足）
5. **Given** 一份平台账单, **When** 导入并对账, **Then** 逐项金额比对、差异**分类**、实测偏差与口径备注齐备；**无分类即视为不可解释**并告警；报告必须引用账单批次（网关记账**不得**作唯一依据）
6. **Given** 多个渠道并存（LLM 渠道 + 投放渠道）, **When** 审计, **Then** 每次真实投放调用都经门禁（静态/契约断言常驻，不得绕过），每渠道**按配置声明的渠道集合分派额度与账本**（同一档位不跨渠道串用）；**旧扁平形状的 `budget` 段仍可读**（按迁移规则显式归入其声明的渠道，不静默误判为另一个渠道）

### 用户故事 3 - 校准结论迁移回灌电影线（优先级：P3）

评估工程师把短剧线积累的评估器校准结论（信度/偏差、漂移结论）按**显式声明的迁移口径**回灌电影线作为先验：每条迁移结论必须带**可比性条件**与判定（可迁移 / 不可迁移 + 原因），迁移动作留痕可回溯（提案 → 人工采纳/搁置，与 010 的提案机制同构）；**可比性不成立时如实说明，数字不冒充证据**。

**为什么是这个优先级**: G4 行的第二条关键验收就是它，但它是**结论的再利用**——必须等 P1 的真实回流积累出可迁移的结论、P2 把真实投放接上之后才成立，天然排在最后。

**独立测试**: 用两形态夹具校准台账（含可比/不可比两组）跑迁移：可迁移结论产出带可比性条件的迁移件；不可比结论**拒绝迁移**并如实登记原因；把短剧数字直接写成电影线证据的路径**不存在**（机检）；迁移件的改写尝试被拒（append-only）。

**验收场景**:

1. **Given** 短剧线的校准结论（信度/偏差/漂移）, **When** 生成迁移件, **Then** 每条带**来源标识**（形态/评估器 `id@version`/周期/样本量）、**可比性条件**与判定
2. **Given** 某条结论的可比性条件不成立（如形态差异使分布不可比）, **When** 迁移, **Then** **拒绝迁移**并如实登记原因（不得静默丢弃、不得降级为"参考"）
3. **Given** 迁移件, **When** 审计, **Then** 短剧线数字**不得**出现在电影线证据面（"模拟/异形态数值冒充本形态证据"机检恒为 0），迁移件 append-only、不可改写
4. **Given** 一份迁移件, **When** 采纳, **Then** 走人工两键（提案 → 人工确认），且不改变任何既有节点的 `eval_breakdown` 与得分（原则一/二）
5. **Given** 无短剧线结论可迁移（真实回流待运营）, **When** 产出迁移报告, **Then** 如实标注"**无可迁移结论（来源缺失）**"并提供继续观察条件，**不得**以模拟回流结论冒充实证

### 边界情况

- **"日级"名不副实（本次勘查发现的真实缺口；量纲口径已裁决，见 Clarifications 第 7 条）**：`configs/shortdrama.yaml:399` 声明 `period_days: 1`，但周期标签取 `period_end` 的 **ISO 周**（`core/calibration/rounds.py:28` `iso_week_label`，用于 `:69`），台账 `BiasRecord.period`、快照文件名（`core/calibration/ledger.py:84`）、信度报告文件名（`core/calibration/report.py:55`）全部继承该标签，且均以 `write_text` 落盘；漂移检测的周期口径同样是 ISO 周（`core/calibration/drift_metrics.py:54` `_WEEK = timedelta(days=7)`，标签正则 `:53`）⇒ **同一 ISO 周内的日级多轮会覆盖同一份快照/报告，且漂移的"窗口 3"实际是 3 周而非 3 天**（`configs/shortdrama.yaml:408` 的注释写的是"日级外环 → 3 天窗口"）。**处理（已裁决）**：周期标签**必须**由 cadence（`period_days`）派生——**周级 ⇒ ISO 周、日级 ⇒ 日期**（**不得**再一律取 ISO 周）；漂移窗口的**单位与 cadence 同量纲**（日级 `window: 3` = **3 天**、周级 = 3 周）并写进产物；**同一周期多轮零覆盖**（机检：同周期内**多轮的台账行/信度报告并留存**、"后写覆盖前写"出现次数恒为 0；**快照为周期物化**——内容变化必须记账、**静默改写次数恒为 0**——边界见 Clarifications 第 12/14 条）；"外环日级"**必须有运转断言**，**不得**只断言配置数字（`tests/unit/test_form_switch.py:188-194` 现行断言只验数字，须扩展）。周级路径标签不变 ⇒ 既有周级产物与历史节点**零回改**（原则一/二）。

### 功能需求

- **FR-001**: 系统必须提供**按日的指标回流面**：日级采集可配置、可重复执行、**按"采集日"分片**留痕——**每个日级周期一份快照**，唯一性键为 **（活动, 周期）**（`node_id` **不再**是终态唯一标识）；**同一投放活动跨多日各采一次必须合法且不覆盖**；回流面必须能复用 019 的运行记录来源纪律（`real` / `simulated` / `fallback`，`core/billing/runlog.py:28`）并**机读可区分**模拟与真实。这是对既有实现的**兼容性扩展**（既有"一次活动一次快照"的历史行仍可读、不得被误判为另一次采集；兼容规则见"边界情况"第 3 条）
- **FR-002**: 日级回流证据件必须**时间索引、可机检**：窗口判定**必须同时满足覆盖与连续**——真实回流天数 ≥ 配置下限 **且** 任一段断档天数 ≤ 配置容差（与 019 的 `budget.runs.min_window_days` / `gap_tolerance_days` 同构，`configs/shortdrama.yaml:600-602`、`core/billing/runlog.py:226`）；累计够天数但有断档**不得**判定通过；有断档**必须**逐段如实报缺口（区间 + 最长断档天数），**禁止**插值补齐；证据件必须按**外环量纲派生的周期标签**分片（日级 ⇒ 日期、周级 ⇒ ISO 周，见 FR-003），且覆盖与窗口按**归属日**聚合（见 FR-006）
- **FR-003**: **周期量纲必须由形态声明的 cadence 派生（与"一律取 ISO 周"脱钩）**：周期标签**必须**由 `calibration.period_days` 派生——**周级 ⇒ ISO 周、日级 ⇒ 日期**（`configs/shortdrama.yaml:399` 的 `period_days: 1` 现状只影响窗口计算、**不影响**标签，见"边界情况"第 1 条），且标签必须贯穿台账/快照/报告/漂移四处；漂移窗口的**单位与 cadence 同量纲**（见 FR-005）；**同一周期内多轮必须各自留痕、零覆盖**（机检：同周期内多轮的台账行/信度报告**并留存**，"后写覆盖前写"出现次数恒为 0；快照为**周期物化**，内容变化必须记账、静默改写次数恒为 0——边界见"边界情况"第 3 条）；周期窗口**统一为半开区间** `[start, start + period_days)`（按日历日），`end - start == period_days` **必须**显式声明并机检，**禁止**含首尾口径（现状 `ops/calibrate.py:43` + `core/calibration/selection.py:28` 使缺省窗口为 `period_days + 1` 天，须按此修正）；窗口口径**必须写进产物**（`window_semantics = half_open` + `period_days`），跨"口径变更日"的比较**必须**在报告 `note` 里显式标注该变更日，**禁止**静默比较（见 Clarifications 第 13 条）
- **FR-004**: **`human` 锚点一经写入即冻结为常数**（原则一）：平台回流数据写入锚点后，任何改写/覆盖**必须**被拒；同键重复回流**必须**幂等拒绝（零变更、整批不中断）；多日回流**只追加**新锚点，**禁止**回头修历史锚点；锚点必须携带其**归属日**（平台指标所描述的日期）与**采集墙钟**两项标识——归属日**必须**来自平台接口显式给出的指标日期字段，缺失即显式失败、该条不落锚点（见 FR-006）
- **FR-005**: 日级校准与漂移判定必须**随 cadence 同量纲**：漂移的滑动窗口**单位必须与周期 cadence 一致**（日级 `window: 3` = **3 天**、周级 = 3 周；现状 `core/calibration/drift_metrics.py:54` 恒定按周，`configs/shortdrama.yaml:408` 的"3 天窗口"注释与实际不符，须修正）且窗口量纲必须写进漂移产物；**漂移每周期读一份快照**（周期物化语义，读取时刻取该周期最后一次物化；缺文件 ⇒ 该周期不参与窗口、缺口如实报），产物**必须**记录所读快照的指纹与该周期锚点数；样本不足**必须**如实标注"样本不足"、**不得**硬判；断档期间**不得**产偏差值或漂移结论
- **FR-006**: 回流的**周期归属必须由显式的"归属日"决定**——取**平台指标所描述的日期**，**不是**采集时刻，且**必须**由平台接口**显式给出的指标日期字段**承载（字段名以适配器读取点为权威；**缺失即显式失败**并给出原因"平台未提供指标归属日"，该条不落锚点、不参与周期归属；**禁止**以拉取/采集时刻兜底）；周期窗口**按归属日过滤**（`core/calibration/selection.py:108` 的过滤键须相应改造）；`platform_timestamp` **保持**"平台时间戳（真值产生时刻）"语义、**与归属日不等同**，平台真值锚点的 `created_at` **保持**平台时间戳、回流节点 `created_at` **保持**采集墙钟，**归属日 / 采集墙钟 / 平台时间戳三者都必须在报告里并列可见**；迟到/回补按其归属日归入对应周期并如实标注（与 019 的"时序错位"分类同一归因思路），**不得**静默改写已冻结的历史锚点、不得让归属口径随实现漂移。平台侧确无该字段 ⇒ 记入开放问题 1 由运营侧确认，未确认期间**不得**发明、如实标"未标定"
- **FR-007**: **C 路径真实投放渠道必须登记进 019 的渠道注册**（`budget.channels`）并使真实投放调用**受同一门禁约束**；为此**必须**给 019 的 `budget` 段补**渠道命名空间**并**放开单渠道硬拒绝**：`tiers` 由扁平环节键改为**按渠道分组**（`channels.<id>.tiers.<环节>`），`sole_channel()` 的硬拒绝改为"**按配置声明的渠道集合分派额度**"。这是对 019 既有实现的**兼容性扩展**（**不是**削弱）：019 的既有断言按扩展更新、**不削弱**；**旧扁平形状仍可读**（按迁移规则显式归入其所声明的渠道，**不得**静默误判为另一个渠道，歧义即报错）；**禁止**为投放另造一套旁路门禁
- **FR-008**: 投放调用**必须**受**前置预算门禁**：按投放环节分档的额度且**按渠道分派**、调用**前**校验、超限即拒绝且**零入账**（被拒的那一笔不入账、已发生的花费照记）；**禁止**先花后报、禁止排队、禁止降级为模拟；与 015 既有的**进程内按轮上限**（`agents/promo/config.py:70-72`、`agents/promo/loop.py:400-418`）**共同生效且口径可区分**——**015 的按轮上限是估算门禁、019 的门禁是跨进程文件账本 + 厂商账单口径，二者不得混同、不得互相替代**
- **FR-009**: 投放**必须**产出**平台账单对账**：账单规范化导入（来源、批次、币种、周期、原始行摘要、计费口径备注；未识别格式**报错**、同批次重复导入被拒）→ 逐项比对**内部记账 vs 平台账单** → 差异**分类**（口径差异/未入账/时序错位/折扣与返券/币种汇率/未结账）、**实测偏差**与**口径备注**；**每条差异必须带分类**，无分类即不可解释并**告警**；网关/内部记账**禁止**作为"成本已核实"的唯一依据（报告必须引用账单批次）
- **FR-010**: 首次接入**必须**按**最小规模**验证协议与计费口径并产出**校准记录**（配置价目/实测花费/偏差/口径备注/样本量/时间；低于样本下限即 `passed=false`）；最小规模入口**必须适用于投放渠道**（不得假定 019 的 LLM 冒烟入口，`specs/019-real-channel-billing/spec.md:102`）；**校准未通过（或无记录、记录过期、样本不足）不得扩量**，扩量请求**必须**引用合格校准记录，否则拒绝并留痕
- **FR-011**: **凭证就绪矩阵**必须显式：渠道登记的凭证环境变量名**以适配器代码为权威**（`PROMO_PLATFORM_BASE_URL` / `PROMO_PLATFORM_API_KEY`，`agents/promo/platform/http_real.py:151-155`），**不得**发明平台名与凭证；声明真实平台而凭证缺失**必须**装配期显式拒绝启动并指出缺哪个变量（零落盘、零扣费、**绝不**静默回落模拟）；凭证不经本特性落盘、不进产物
- **FR-012**: **校准结论迁移**必须成为交付：迁移件必须携带**来源标识**（形态 / 评估器 `id@version` / 周期 / 样本量 / 来源件引用）、**迁移口径**与**可比性条件**及其判定；可比性不成立时**拒绝迁移**并如实登记原因；迁移动作留痕 append-only、可回溯（提案 → 人工采纳/搁置，与 010 的提案/确认机制同构，`:131-151` 原则六的人工两键纪律）；**禁止**把短剧线数字冒充电影线证据，且迁移**不得**改动任何既有节点的 `eval_breakdown` 与得分（原则一/二）
- **FR-013**: **诚实分层必须机检**：本特性交付**机制与离线复现**（Mock 平台 + 夹具账单/指标，零真实花费、零外部网络、零凭证）；"**短剧线真实数据回流 ≥2 周**"属**运营侧墙钟 + 凭证**前提，产物与报告**必须**写成"机制已就绪 / 真实回流待运营"并给出机检到的真实覆盖天数与缺口；"模拟被标为真实"的次数恒为 0，**未满足前提时禁止**输出"真实数据回流已达成"一类结论；**渠道失败禁止**静默回落模拟并照常计费（回落须显式声明并标注来源）
- **FR-014**: 全部新增参数（周期量纲与窗口口径、回流日期归属口径、渠道登记与凭证矩阵、预算分档、迁移口径与可比性条件）**必须**形态配置化、**两形态均须声明**、**缺项即报错、不取码内默认**；**不得**新增形态分支代码；必须提供 CLI 与离线端到端演示（退出码语义与既有工具一致，演示零真实花费）；**不得**把模拟回流标成真实、**不得**做多租户/公网服务化，**不得**顺带做 G5 的多形态插件验证或 B 路径真实生成对接

### 关键实体 *（如果功能涉及数据）*

- **日级回流记录（DailyMetricIngest，新增）**: 投放活动标识 + **归属日**（平台指标所描述的日期）+ 采集时刻（墙钟）+ 指标快照引用 + 来源（`real` / `simulated` / `fallback`）；**唯一性键 = （活动, 周期）**（`node_id` 不再是终态唯一标识）；周期窗口按**归属日**聚合；日级窗口机检的唯一依据；append-only
- **日级回流窗口（DailyCoverageWindow，复用 019 口径）**: 覆盖天数 + 逐段断档（区间/天数）+ 最长断档 + 配置下限/容差 + 通过判定与归因；**按归属日聚合**，`covered_days` 只计真实来源，禁止插值
- **周期量纲口径（PeriodGranularity，新增）**: 由 cadence（`period_days`）**派生**的标签口径（**周级 ⇒ ISO 周、日级 ⇒ 日期**）+ **漂移窗口单位同量纲** + 窗口**半开区间** `[start, start + period_days)` + 台账/快照/报告/漂移四处产物的标签一致性 + **同周期多轮零覆盖**；由形态配置声明，缺项即报错
- **平台锚点（AnchorScore，复用 010）**: `source=platform_truth` + `reviewer` 记渠道 + `score` + **归属日**（平台指标所描述的日期）+ `created_at`（**保持**平台时间戳）；写入即冻结为常数（原则一）
- **投放渠道登记（ChannelSpec，复用 019 并扩展）**: 渠道 id + 真实调用面的装配引用 + 凭证环境变量名 + 账单导入面 + **按渠道分组的额度命名空间**（`channels.<id>.tiers.<环节>`）；**投放渠道必须在 `budget.channels` 登记**，与 LLM 渠道并存时按**配置声明的渠道集合**分派（旧扁平形状仍可读并显式归一，不误判）
- **分档额度（BudgetTier，复用 019 并扩展）**: 渠道 + 环节 → 额度上限 + 时间窗（`run`/`day`/`period`）+ 余量 + 拒绝计数；命名空间为 `channels.<id>.tiers.<环节>`，**同一档位不得跨渠道串用**
- **协议与计费口径校准记录（CalibrationRecord，复用 019）**: 渠道 + 配置价目 + 实测花费 + 偏差 + 口径备注 + 样本量 + 时间 + 有效期；扩量的先决条件（无记录/过期/样本不足一律拒绝）
- **平台账单与对账报告（VendorBill / ReconciliationReport，复用 019）**: 批次/来源/币种/周期/口径备注；逐项比对 + 差异分类 + 实测偏差 + 未解释项 + 告警；append-only、不可改写
- **凭证就绪矩阵（CredentialMatrix，新增）**: 渠道 → 凭证变量名（以代码读取点为权威）→ 就绪状态 → 缺失时的拒绝语义；**不落盘凭证值**
- **校准结论迁移件（CalibrationTransfer，新增）**: 来源形态 + 评估器 `id@version` + 周期 + 样本量 + 来源件引用 + 迁移口径 + **可比性条件与判定** + 采纳状态与留痕；可比性不成立即拒绝迁移并记原因；append-only

## 假设

- **真实投放的凭证、平台名与预算档属运营侧输入**（立项书 §8 `:280`："运营侧必须有人对接真实渠道（凭证、预算、平台合规），否则 G3/G4 无法推进"）。本特性**不发明**平台名、凭证变量名与额度数字；未给定期间如实登记"未标定"并按最小规模档运行
- **C 路径的适配器代码已在位**（`agents/promo/platform/http_real.HttpRealPlatform`，协议实现 + 本地 stub 端到端验证，`docs/pilot-upgrade-manifest.json` 的 `protocol_implementation`）；本特性做的是**对接与校准**（凭证、协议校验、计费口径核对、门禁接入），**不重写**适配器协议，也不改 `core/platform_http.py` 的既有口径
- **019 已交付门禁与对账机制**（`core/billing/`：`budget` / `bill` / `reconcile` / `calibration` / `runlog` 五模块）；本特性把**媒体渠道这个新渠道面**接上去，**不重做**计费机制，但需对 019 的 `budget` 段与单渠道装配做**兼容性扩展**——渠道命名空间（`channels.<id>.tiers.<环节>`）+ 放开 `sole_channel()` 硬拒绝、改为按声明渠道集合分派，**旧扁平形状仍可读**且不误判（见 Clarifications 第 10 条、"边界情况"第 8 条）
- **"真实回流 ≥2 周"是运营侧墙钟依赖**：与三期 WS3 的影子期 ≥2 周同性质（立项书 §4 `:208`、§9 `:293`）——机制与离线复现可先交付并经机检，真实窗口待运营积累
- **日级回流的表示面已裁决 = 同一投放活动按"采集日"分片**：每个日级周期一份快照，唯一性键为 **（活动, 周期）**（`node_id` 不再是终态唯一标识），**同一活动跨多日各采一次合法且不覆盖**；既有"一次活动一次快照"的历史行仍可读、不被误判为另一次采集（见 Clarifications 第 9 条、"边界情况"第 3 条）
- **迁移只做"结论迁移"，不做模型/权重自动迁移**：短剧线的校准结论作为电影线的**先验与参考**，权重再拟合仍走 010 的提案 → 人工确认路径；**禁止**自动改权重、自动改评估器版本（原则一）
- **测试与演示使用 Mock 平台后端 + 夹具指标/账单**，零真实花费、零外部网络、零凭证；真实投放与真实回流属运营动作，需人工确认账户与预算，**不得**由自动进化路径触发（`docs/二期升级路径-真实生成与投放.md:180`）
- 三期不做项不变：不做 G5 多形态插件验证、不做 B 路径真实生成厂商对接、不做多租户、不做公网服务化
