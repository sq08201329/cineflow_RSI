### Session 2026-09-25（范围裁决——以下为人的裁决，规格负责忠实编码）

- Q: C 路径真实投放怎么接？ → A: **走 019 已交付的门禁，不另造机制**。投放调用属"真实渠道调用"⇒ **必须**受**预算门禁 + 账单对账**双重约束（原则三 `:73-79`），且**首次接入按最小规模**验证协议与计费口径后才可扩量。**本特性不发明平台名与凭证**——它们是运营侧输入，如实登记（`docs/二期升级路径-真实生成与投放.md:180`："真实投放属运营动作，需人工确认账户与预算"）。
- Q: "日级指标回流"与"外环日级运转"要补的到底是什么？ → A: **补机制与证据，不是改数字**。`configs/shortdrama.yaml:399` 已声明 `calibration.period_days: 1`（对比 `configs/movie.yaml:392` 的 `7`），但**日级只在配置里，不在产物里**：周期标签一律取 ISO 周（`core/calibration/rounds.py:28`、`:69`），漂移窗口按周计（`core/calibration/drift_metrics.py:53-54`），台账/快照/报告的落盘路径均含该标签（`core/calibration/ledger.py:84`、`core/calibration/report.py:55`）⇒ 同一 ISO 周内的多轮日级运转会**互相覆盖**同一份快照与报告。本特性把"按日配置"变成"真的按日运转"。
- Q: 校准结论怎么"回灌"电影线？ → A: **必须成为本特性的一条交付**（迁移口径、可比性条件、不可迁移时如实说明），沿用 `docs/影视全Agents公司技术方案.md:186` 的"按迁移学习思路平移到电影线作为先验"。**禁止**把短剧线的数字直接冒充电影线的证据（形态不同、体量与分布不同，可比性不成立时只能如实登记）。
- Q: ≥2 周真实回流的证据件长什么样？ → A: **时间索引、可机检、断档如实报**，与 019 的窗口口径**同构**（`core/billing/runlog.py:226` 的覆盖 ∧ 连续双条件：`covered_days ≥ min_window_days` **∧** `max_gap_days ≤ gap_tolerance_days`；`covered_days` 只计真实来源、缺口逐段列出、**禁止**插值补齐）。
- Q: 本次能交付到什么程度（关键取舍）？ → A: **诚实分层**。真实投放需要**平台账号、凭证、真实预算与合规审查**——全部属运营侧，**未安排**（`docs/三期立项书.md:280`）。故本特性交付的是**机制与离线复现**（现在可交付、可经机检、零真实花费），而"**短剧线真实数据回流 ≥2 周**"这一验收属**运营侧墙钟 + 凭证**前提 ⇒ 规格必须写成"**机制已就绪 / 真实回流待运营**"。**禁止**用模拟数据的回流冒充真实回流（`source` 取值域与覆盖判定共同守住这条线）。
- Q: 本特性不做什么？ → A: **不做** G5 的多形态插件验证；**不做**真实生成侧（B 路径）厂商对接（其对接属 G2 的结转项与运营侧输入）；**不把模拟回流标成真实**；**不做**多租户/公网服务化（三期不做项不变）。

### 用户故事 1 - 日级指标回流与外环日级运转（优先级：P1）🎯 MVP

运营按日把短剧投放的平台指标回流进系统：每天一批真实指标落成 `human` 锚点（**写入即冻结为常数**，原则一），外环按**日**产出校准与漂移结论；日级窗口的覆盖与连续可机检——**断档如实报缺口，不插值补齐**；样本不足时如实标"样本不足"，不硬判、不编数。

**为什么是这个优先级**: G4 行第一句的内容就是"日级指标回流、外环频率日级运转"，G4 行第一条关键验收也建立在它之上。而它今天的**名不副实**是本次勘查发现的最硬的机制缺口：周期标签取 ISO 周，日级运转会互相覆盖（见 Clarifications 第 2 条）。没有这一层，后面两条用户故事都没有日级真实数据作载体。

**独立测试**: 用夹具平台指标 + 固定时钟跑日级运转可完整测试：`period_days: 1` 生效后，同一 ISO 周内连续多轮的台账/快照/报告**互不覆盖**且写入即冻结；日级窗口机检对"连续 15 天"夹具通过、"15 天真实但缺 2 天"夹具**不通过**且断档逐段报出（不插值）；锚点重复回流同键幂等拒绝、既有锚点改写在存储层被拒；样本不足时台账只写"样本不足"备注、不产偏差值。

**验收场景**:

1. **Given** 短剧形态配置声明 `calibration.period_days: 1`, **When** 生成周期标签与产物路径, **Then** 标签的量纲为**日**（与 ISO 周脱钩），同一周内多轮落盘到**不同**的台账行/快照/报告，零覆盖
2. **Given** 一份日级真实指标, **When** 回流, **Then** 落成 `human.platform_metrics@1.0.0` 锚点，指标的**日期归属**按其显式声明的口径判定（平台指标日或采集日，二者不得含糊混用）
3. **Given** 同一指标的重复回流, **When** 再次写入, **Then** 同键幂等拒绝（零变更），既有锚点**改写在存储层被拒**（冻结为常数）
4. **Given** 日级运行记录（真实来源）, **When** 机检 ≥2 周窗口, **Then** **同时**满足覆盖 ≥ `min_window_days` 与最长断档 ≤ `gap_tolerance_days` 方通过；仅累计够天数但有断档**不得**通过，缺口区间与最长断档天数**逐段如实报出**
5. **Given** 断档期间的日级运转, **When** 产出校准/漂移结论, **Then** 断档与样本不足如实标注（漂移判"样本不足"而不硬判），**不得**插值补齐、不得以模拟数据顶替真实日
6. **Given** 平台指标迟到或回补, **When** 回流, **Then** 归属日按声明的口径登记并**如实标注**，不静默改写已冻结的历史锚点

### 用户故事 2 - C 路径真实投放接入（优先级：P2）

运营把真实投放渠道接进系统：先在配置里**如实登记**渠道与凭证环境变量名（**本特性不发明平台名与凭证**），凭证缺失即**装配期显式拒绝启动**（不静默降级为模拟）；投放调用**必须**先过**按环节分档的前置预算门禁**（超限即拒绝且零入账），并在首次接入时按**最小规模**验证协议与计费口径；投放后产出**平台账单对账**差异报告。校准未通过**不得扩量**。

**为什么是这个优先级**: 宪章原则三的第一句就是这门禁，且 019 已把机制交付好——本特性只是把**媒体渠道这个新渠道面**接上去（019 明文把媒体渠道结转给 G4）。它排在 P1 之后是因为日级回流的**前提**正是"有真实投放产生真实指标"，但机制层的接入动作独立可测，故仍是独立切片。

**独立测试**: 用 Mock 平台后端 + 夹具账单可完整测试：凭证缺失即装配拒绝（不回落模拟）；超限投放申请被**调用前拒绝**、平台调用 0 次、零入账；最小规模投放后产出校准记录（含协议与计费口径偏差）；无合格校准记录的扩量请求被拒并留痕；账单导入 → 差异报告每项带分类与口径备注、不可解释项 100% 告警。

**验收场景**:

1. **Given** 投放渠道已登记且按环节声明预算档, **When** 一轮投放申请额超出剩余额度, **Then** **调用前拒绝**、平台调用 0 次、成本入账 0、原因落盘
2. **Given** 声明真实投放而平台凭证缺失, **When** 装配, **Then** **显式报错拒绝启动**（指出缺哪个环境变量、零落盘/零扣费），**禁止**静默回落模拟后端
3. **Given** 首次接入真实投放, **When** 以最小规模跑通, **Then** 产出**协议与计费口径校准记录**（配置价目/实测花费/偏差/口径备注/样本量/时间），低于样本下限即 `passed=false`
4. **Given** 校准未通过或记录过期, **When** 请求扩量, **Then** 拒绝并留痕，拒绝理由点名命中的是哪一条（无记录/过期/样本不足）
5. **Given** 一份平台账单, **When** 导入并对账, **Then** 逐项金额比对、差异**分类**、实测偏差与口径备注齐备；**无分类即视为不可解释**并告警；报告必须引用账单批次（网关记账**不得**作唯一依据）
6. **Given** 投放渠道已登记, **When** 审计, **Then** 每次真实投放调用都经门禁（静态/契约断言常驻，不得绕过），且**多渠道并存时额度与账本按渠道正确分派**

### 用户故事 3 - 校准结论迁移回灌电影线（优先级：P3）

评估工程师把短剧线积累的评估器校准结论（信度/偏差、漂移结论）按**显式声明的迁移口径**回灌电影线作为先验：每条迁移结论必须带**可比性条件**与判定（可迁移 / 不可迁移 + 原因），迁移动作留痕可回溯（提案 → 人工采纳/搁置，与 010 的提案机制同构）；**可比性不成立时如实说明，数字不冒充证据**。

**为什么是这个优先级**: G4 行的第二条关键验收就是它，但它是**结论的再利用**——必须等 P1 的真实回流积累出可迁移的结论、P2 把真实投放接上之后才成立，天然排在最后。

**独立测试**: 用两形态夹具校准台账（含可比/不可比两组）跑迁移：可迁移结论产出带可比性条件的迁移件；不可比结论**拒绝迁移**并如实登记原因；把短剧数字直接写成电影线证据的路径**不存在**（机检）；迁移件的改写尝试被拒（append-only）。

**验收场景**:

1. **Given** 短剧线的校准结论（信度/偏差/漂移）, **When** 生成迁移件, **Then** 每条带**来源标识**（形态/评估器 `id@version`/周期/样本量）、**可比性条件**与判定
2. **Given** 某条结论的可比性条件不成立（如形态差异使分布不可比）, **When** 迁移, **Then** **拒绝迁移**并如实登记原因（不得静默丢弃、不得降级为"参考"）
3. **Given** 迁移件, **When** 审计, **Then** 短剧线数字**不得**出现在电影线证据面（"模拟/异形态数值冒充本形态证据"机检恒为 0），迁移件 append-only、不可改写
4. **Given** 一份迁移件, **When** 采纳, **Then** 走人工两键（提案 → 人工确认），且不改变任何既有节点的 `eval_breakdown` 与得分（原则一/二）
5. **Given** 无短剧线结论可迁移（真实回流待运营）, **When** 产出迁移报告, **Then** 如实标注"**无可迁移结论（来源缺失）**"并提供继续观察条件，**不得**以模拟回流结论冒充实证

### 边界情况

- **"日级"名不副实（本次勘查发现的真实缺口，本特性必须修）**：`configs/shortdrama.yaml:399` 声明 `period_days: 1`，但周期标签取 `period_end` 的 **ISO 周**（`core/calibration/rounds.py:28` `iso_week_label`，用于 `:69`），台账 `BiasRecord.period`、快照文件名（`core/calibration/ledger.py:84`）、信度报告文件名（`core/calibration/report.py:55`）全部继承该标签，且均以 `write_text` 落盘；漂移检测的周期口径同样是 ISO 周（`core/calibration/drift_metrics.py:54` `_WEEK = timedelta(days=7)`，标签正则 `:53`）⇒ **同一 ISO 周内的日级多轮会覆盖同一份快照/报告，且漂移的"窗口 3"实际是 3 周而非 3 天**（`configs/shortdrama.yaml:408` 的注释写的是"日级外环 → 3 天窗口"）。**处理**：周期量纲必须由配置声明并贯穿到标签与所有产物路径；同周期多轮**不得**互相覆盖（写入即冻结）。
- **周期窗口的边界口径**：`ops/calibrate.py:43` 的缺省 `period_start = 今天 − period_days`，而 `core/calibration/selection.py:28` `_period_window` 把 `period_end` 加一天（含首尾）⇒ 缺省窗口实际跨 `period_days + 1` 天；日级下即"2 天窗"。规格要求窗口口径**显式声明并机检**，不得让"周期天数"与"实际窗口天数"相差一天而无人察觉。
- **日级回流的表示面（既有模型的承载上限）**：现有回流是**每次投放活动一次快照**——`MetricSnapshot` 为单快照（`agents/promo/platform/base.py:71`、`platform_timestamp:79`），运营行 `promo_campaigns.metrics` 注明"回流后写入一次"（`agents/promo/db.py:44`），`node_id` "回填即终态不再变"（`:33`），回流只处理 `status == "delivered"` 的行（`agents/promo/ingest.py:58`）并随即置为 `ingested`（`:130`）⇒ **同一投放活动无法连续多日各采一次指标**。日级 ≥2 周的真实回流因此必须显式选定表示（同一活动多日分片采集，或按日投放分片），"日"必须可机读地落进证据件。**本规格只要求机制与口径明确，不预选实现**（见开放问题 3）。
- **指标日期与锚点时刻的错位**：回流节点的 `created_at` 取**采集墙钟**（`agents/promo/ingest.py:117` `time.time()`），而 010 的周期窗口按节点 `created_at` 过滤候选（`core/calibration/selection.py:108`）；平台真值锚点的 `created_at` 却取**平台时间戳**（`agents/promo/anchors.py:22-28`，`:66`），缺失才以采集时刻兜底。**迟到/回补的指标**会让"指标归属日"与"采集日"落在不同的日级周期里。归属口径必须显式声明并写进产物（与 019 对账的"时序错位"分类同源思路），**不得**静默改写已冻结的历史锚点。
- **断档不插值**：日级运转出现空日时，缺口必须逐段如实列出（区间 + 天数），**禁止**插值、补零或以上一日的指标顶替；"累计够天数但有断档"**不得**判定通过（与 019 `core/billing/runlog.py:226-311` 的同构口径：`covered_days` 只计真实来源、`continuous` 与 `meets` 并列呈现）。
- **模拟回流冒充真实**：模拟平台的指标与真实平台的指标在产物上必须**机读可区分**（复用 `RUN_SOURCES = ("real", "simulated", "fallback")` 的取值纪律，`core/billing/runlog.py:28`）；"模拟被标为真实"的次数必须恒为 0；全模拟可跑（演示、单测、CI），但**不得**据此声称"短剧线真实数据回流已达成"。
- **凭证缺失即拒绝启动，而非静默降级**：声明真实平台而 `PROMO_PLATFORM_BASE_URL` / `PROMO_PLATFORM_API_KEY` 缺失（`agents/promo/platform/http_real.py:151-155` 为读取点、`:143` 为缺凭证文案）必须在**装配期显式失败**并指出缺哪个变量（`docs/pilot-upgrade-manifest.json` 的 `switch_mechanism.credential_policy`），发生在落树/扣费之前。
- **多渠道并存的结构性张力（本次勘查发现的真实约束）**：019 的门禁面**硬约束单渠道**——`core/billing/budget.py:357` `sole_channel()` 明写"`budget.channels` 必须恰好声明一个渠道，实际 …：装配面不猜用哪个（多渠道需先补齐按渠道分派的装配口径）"，`ops/billing.py:102-110` 的 CLI 同样经它取渠道；而 `budget.tiers` 是**扁平的环节 → 额度**映射（`core/billing/budget.py:275`），未按渠道分命名空间。把投放渠道接进门禁必须**同时补齐按渠道分派的装配与额度口径**，否则"投放受门禁"落不了地。**规格只要求补齐与机检，不预选实现**（见开放问题 4）。
- **与既有"按轮上限"的关系**：015 的投放上限是**进程内按轮**的（`agents/promo/config.py:70-72` `budget_cap_usd = exploration_per_round_usd × promo_pilot_ratio`，前置校验在 `agents/promo/loop.py:400-418`，花费读自运营表 `_round_spent` `:240`）。它是**估算门禁**，不是 019 的跨进程账本 + 厂商账单口径。两者必须**共同生效且口径可区分**，**不得**把其一当成另一条的替代（原则三要求的是后者）。
- **预算超限即拒绝且零入账**：被门禁拒绝的投放**不得**申请、**不得**记成本（零成本分支：拒绝的那一笔不入账，已发生的花费照记）；**禁止**先花后报、拒绝而非排队、而非降级为模拟。
- **认证失败与配额限制**：必须与"预算超限"区分开、各有独立错误分类（否则对账无法归因）。
- **真实投放的合规审查**：立项书 §7 把"真实投放的合规（版权/肖像/广告法）"列为**高**风险（`:271`）；既有宣发合规门禁（敏感词/规格）在位，但**版权链决策属业务侧**。合规审查未完成即**不得**扩量，且这一前提**不得**在代码或配置里被发明或绕过。
- **human 锚点写入即冻结**：锚点写入（`core/calibration/anchors.py` 的 `insert_anchor` 唯一接口）后任何改写/覆盖**必须**被拒（存储层触发器，原则一/二）；同键重复回流幂等拒绝、整批不中断。
- **迁移口径不可比时如实登记**：形态不同 ⇒ 分布、体量、平台与受众均不同；可比性条件必须**先声明、后判定**，不成立即**拒绝迁移**并登记原因，**不得**降格为"仅供参考"的数字蒙混过关。
- **平台与凭证不由本特性发明**：**禁止**在配置、代码或报告中发明平台名、凭证环境变量名、预算档数字；它们全部属运营侧输入，未给定期间如实登记"未标定"。
- **会因此变红的既有测试与夹具（必须同步更新，不得为过测试而放宽断言）**：周期标签量纲与产物路径是 010/012 的**既有契约面**——`tests/unit/test_anchor_snapshots.py`（夹具周期标签写死 `_PERIOD = "2026-W39"`，`:23`）、`tests/unit/test_drift_detect.py`（当前周期 `_CURRENT = "2026-W39"`、基线 `2026-W34..W38`，`:32`/`:120-133`）、`tests/contract/test_calibration_contracts.py`（C1~C9 端到端，含"权重生效后历史节点逐字节一致"与"昂贵动作调用计数为 0"两条机检，`:1-10`）。**关键实证**：今天的"日级"测试只断言**配置里的数字**，不断言**运转**——`tests/unit/test_form_switch.py:188-194` 的 `test_外环日级` 仅断言 `short.period_days == 1 and short.period_days < movie.period_days`。故新增的日级运转断言必须**新立**，**不得**把它当作"日级已运转"的证据；既有周级路径与历史产物**零回改**（原则一/二）。
- **回归面口径**：本特性的"写入即冻结"与"零覆盖"断言必须与 010 的 append-only 台账、DB 锚点触发器、`tests/contract/test_calibration_contracts.py` 的历史逐字节一致机检**并列成立**，不得以改写既有断言换取新行为通过。

### 关键实体 *（如果功能涉及数据）*

- **日级回流记录（DailyMetricIngest，新增）**: 投放活动标识 + 指标归属日 + 采集时刻 + 指标快照引用 + 来源（`real` / `simulated` / `fallback`）；日级窗口机检的唯一依据；append-only
- **日级回流窗口（DailyCoverageWindow，复用 019 口径）**: 覆盖天数 + 逐段断档（区间/天数）+ 最长断档 + 配置下限/容差 + 通过判定与归因；`covered_days` 只计真实来源，禁止插值
- **周期量纲口径（PeriodGranularity，新增）**: 周期的粒度（日/周/…）与标签格式 + 窗口含首尾边界口径 + 台账/快照/报告/漂移四处产物的标签一致性；由形态配置声明，缺项即报错
- **平台锚点（AnchorScore，复用 010）**: `source=platform_truth` + `reviewer` 记渠道 + `score` + `created_at`（平台时间戳或采集时刻，口径显式）；写入即冻结为常数（原则一）
- **投放渠道登记（ChannelSpec，复用 019 并扩展）**: 渠道 id + 真实调用面的装配引用 + 凭证环境变量名 + 账单导入面；**投放渠道必须在 `budget.channels` 登记**且与 LLM 渠道并存时按渠道分派
- **分档额度（BudgetTier，复用 019）**: 投放环节的额度上限 + 时间窗（`run`/`day`/`period`）+ 余量 + 拒绝计数；按渠道分派后同一档位不得跨渠道串用
- **协议与计费口径校准记录（CalibrationRecord，复用 019）**: 渠道 + 配置价目 + 实测花费 + 偏差 + 口径备注 + 样本量 + 时间 + 有效期；扩量的先决条件（无记录/过期/样本不足一律拒绝）
- **平台账单与对账报告（VendorBill / ReconciliationReport，复用 019）**: 批次/来源/币种/周期/口径备注；逐项比对 + 差异分类 + 实测偏差 + 未解释项 + 告警；append-only、不可改写
- **凭证就绪矩阵（CredentialMatrix，新增）**: 渠道 → 凭证变量名（以代码读取点为权威）→ 就绪状态 → 缺失时的拒绝语义；**不落盘凭证值**
- **校准结论迁移件（CalibrationTransfer，新增）**: 来源形态 + 评估器 `id@version` + 周期 + 样本量 + 来源件引用 + 迁移口径 + **可比性条件与判定** + 采纳状态与留痕；可比性不成立即拒绝迁移并记原因；append-only

- **SC-005**: 投放账单对账**差异可解释率 100%**（每条差异带分类与口径备注）；不可解释项 100% 告警落盘；把网关/内部记账当作"成本已核实"唯一依据的次数恒为 **0**（报告必引用账单批次）
- **SC-006**: 最小规模先行约束：无合格校准记录（无记录 / 过期 / 样本不足）的扩量请求 **100% 拒绝并留痕**，拒绝理由点名命中的是哪一条
- **SC-007**: 校准结论迁移的判定完备率 **100%**——每条迁移件必须带可比性条件与判定（可迁移 / 不可迁移 + 原因）；不可迁移结论的**误迁移次数恒为 0**；迁移件改写/省略尝试 **100% 被拒**（append-only），迁移**不改变**既有节点得分与 `eval_breakdown`（逐字节一致）
- **SC-008**: `human` 锚点**冻结**：锚点写入后的改写/覆盖尝试 **100% 被拒**；同键重复回流 100% 幂等拒绝（零变更）；多日回流只追加、零回改
- **SC-009**: 单元测试覆盖率 ≥ **85%**（口径不降，含 web）；对抗测试（合并阻塞）、无偏性（发布阻塞）、Immutable 审计与成本回归（每日）四道常驻门禁**不放松**；零形态分支与"不新增旁路门禁"静态断言常驻通过

## 假设

- **真实投放的凭证、平台名与预算档属运营侧输入**（立项书 §8 `:280`："运营侧必须有人对接真实渠道（凭证、预算、平台合规），否则 G3/G4 无法推进"）。本特性**不发明**平台名、凭证变量名与额度数字；未给定期间如实登记"未标定"并按最小规模档运行
- **C 路径的适配器代码已在位**（`agents/promo/platform/http_real.HttpRealPlatform`，协议实现 + 本地 stub 端到端验证，`docs/pilot-upgrade-manifest.json` 的 `protocol_implementation`）；本特性做的是**对接与校准**（凭证、协议校验、计费口径核对、门禁接入），**不重写**适配器协议，也不改 `core/platform_http.py` 的既有口径
- **019 已交付门禁与对账机制**（`core/billing/`：`budget` / `bill` / `reconcile` / `calibration` / `runlog` 五模块）；本特性只把**媒体渠道这个新渠道面**接上去，不重做计费机制
- **"真实回流 ≥2 周"是运营侧墙钟依赖**：与三期 WS3 的影子期 ≥2 周同性质（立项书 §4 `:208`、§9 `:293`）——机制与离线复现可先交付并经机检，真实窗口待运营积累
- **日级回流的表示面需选定**（同一投放活动多日分片采集，或按日投放分片）：既有模型为"一次活动一次快照"（见"边界情况"），本规格要求机制与口径明确，**不预选实现**（见开放问题 3）
- **迁移只做"结论迁移"，不做模型/权重自动迁移**：短剧线的校准结论作为电影线的**先验与参考**，权重再拟合仍走 010 的提案 → 人工确认路径；**禁止**自动改权重、自动改评估器版本（原则一）
- **测试与演示使用 Mock 平台后端 + 夹具指标/账单**，零真实花费、零外部网络、零凭证；真实投放与真实回流属运营动作，需人工确认账户与预算，**不得**由自动进化路径触发（`docs/二期升级路径-真实生成与投放.md:180`）
- 三期不做项不变：不做 G5 多形态插件验证、不做 B 路径真实生成厂商对接、不做多租户、不做公网服务化
