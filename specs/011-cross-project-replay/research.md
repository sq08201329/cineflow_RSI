# 阶段 0 调研：跨项目发现树合并回放（011-cross-project-replay）

> 每个决策 = 分歧点 → 备选 → 结论 → 依据。规格：[spec.md](spec.md)（含 2026-09-21 澄清两条）。

## 决策 1：存放位置——core/replay 扩展（业务无关）

- **结论**：池化机制（构建/匹配/统计/谱系查询）全部落在 `core/replay/` 扩展模块——
  `merged_pool.py`（构建 + 快照）、`cross_match.py`（跨项目匹配 + 冲突）、
  `hit_stats.py`（命中分布 + 稀释告警）、`cross_lineage.py`（跨项目谱系查询）
- **依据**：原则五——池化是树/回放基建（业务无关），不属任何单个 Agent；与 002 的
  SimulatorPool 同层（扩展而非替换）。

## 决策 2：版本分组的粒度——按"评估器版本集"分组，回放选当前版本集

- **分歧**：跨版本树怎么组织？
- **结论**：池内树按**评估器版本集**（config_snapshot 中评估器组合的快照哈希）分组；
  回放时选择"与当前部署评估器版本集一致"的组——跨版本不混池（语义不可比）；
  同版本集不同形态的 config 差异如实标注不影响匹配
- **依据**：原则一——评估器版本是得分语义的前提；同版本集是同语义的最小单位
  （比"逐评估器版本"粗、比"不分组"细，避免版本碎片化成单树池）。

## 决策 3：冲突即 UNKNOWN 的诊断路径（澄清 Q1 落地）

- **结论**：`cross_match.py` 在规范化精确匹配（结构键 + 版本集）命中多棵且得分不同
  → UNKNOWN + `ScoreConflict` 诊断（命中的树清单、各得分、project_id 归属）；
  冲突记录进命中分布的 `conflicts` 字段，供 010 校准与 F7 漂移检测消费
- **依据**：澄清决议——保守口径；冲突是"可复现假设不成立"的证据，必须留痕。

## 决策 4：命中占比判定 + 树数占比参考（澄清 Q2 落地）

- **结论**：`hit_stats.py` 产出 per-project 与合并口径的命中/UNKNOWN 统计；
  **判定 = 命中占比**（项目命中数 / 总命中数）超阈告警；树数占比作参考维度同报告；
  单项目构成（占比 1.0）必然超阈，如实标注"单项目构成"
- **依据**：澄清决议——稀释是信号来源主导性，命中来源比物理数量更直接。

## 决策 5：前置条件与可重现

- **结论**：同 (Agent, 形态) 树 ≥ `min_trees`（配置，默认 3）才可构建合并池；
  不足即拒绝并注明；池构建**可重现**（同输入同树集合与顺序——按 (时间戳, project_id)
  字典序稳定排序）；构建快照（`PoolSnapshot`）文件化落盘
- **依据**：立项书 F6 前置条件；可重现是回放可复现的前提（池内容漂移则 τ 验收失效）。

## 决策 6：分树与一致性验收

- **结论**：train/validation 分树在合并池按时间**全局排序**（跨项目，tie-break
  project_id）；最近树只做 validation（005 口径）；**一致性验收** = 同树在单项目池与
  合并池回放的得分序列一致（合并不改变命中规则，只扩充候选集）
- **依据**：002/005 分树纪律的跨项目推广；"同树得分一致"是"合并不改变回放语义"的
  可证伪断言。

## 决策 7：做梦开关默认关闭 + 快照留痕

- **结论**：配置 `replay.pooling.enabled_for_dreaming: false`（默认）；开启时做梦用
  合并池，关闭/前置条件不足时用单项目池并注明；开关状态与前置判定入 `PoolSnapshot`
- **依据**：规格 FR-011——稀释未经批准不影响进化方向；保守默认 + 显式留痕。

## 决策 8：快照与谱系的存储

- **结论**：`PoolSnapshot` 文件化（`replay/pools/{agent}/{form}/{pool_id}.json`，git 版本化，
  同 005/010 文件化惯例）；谱系查询走 001 三维索引的跨项目扩展（只读，无新表）
- **依据**：派生数据文件化（可重算）；谱系数据已在 001 落库，查询是读路径扩展。
