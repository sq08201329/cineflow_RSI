# 功能规格说明：跨项目发现树合并回放（池化复用）

**功能分支**: `011-cross-project-replay`

**创建日期**: 2026-09-21

**状态**: 草稿

**输入**: 用户描述："二期立项书 F6：跨项目发现树合并回放——多个项目的发现树按 (Agent, 形态) 分组合并进同一个模拟器池，回放时跨项目命中（同结构键 + 同评估器版本的历史节点得分可复用），扩大经验覆盖、减少 UNKNOWN。谱系三维索引 (项目, Agent, 策略版本) 支持跨项目查询（policy_version → tree_ids → child_policy_versions 跨项目链路）。稀释控制：默认按 (Agent, 形态) 分组池化，跨形态合并需显式配置；某项目树在合并池中占比超阈告警。前置条件：池内同 Agent 树 ≥ 3 棵。验收：合并池与单项目池在同树回放上得分一致；跨项目命中的回放可复现；谱系跨项目链路可查；合并口径无偏性 τ≥0.95。"

**约束来源**: 项目宪章 v1.1.0（原则一：评估器版本冻结——**跨项目池化复用的前提是同评估器版本**，不同版本的树按版本分组；原则二：谱系全链路可查；原则三：回放零生成；原则五：配置化——池化分组/阈值/显式跨形态全走 configs；原则六：池化稀释是如实暴露的风险，告警而非掩盖）。业务依据 `docs/影视全Agents公司技术方案.md` §3.1（三维索引支撑跨项目回放）。立项依据 `docs/二期立项书.md` WS2-F6（前置条件 ≥3 棵同 Agent 树；风险：稀释 → 分组 + 告警）。依赖功能 001（三维索引）、002（回放/规范化匹配/UNKNOWN/分树）、009（"结构键"匹配语义——池化复用的匹配基础）、010（周校准的锚点按 (Agent, 形态) 归属）。

## Clarifications

### Session 2026-09-21

- Q: 跨项目同结构键同评估器版本但命中多棵树且得分不同（冲突）时如何处理？ → A: **冲突即 UNKNOWN**（不得分、不编造），冲突如实进诊断告警——得分不一致说明"可复现"假设在该树上不成立，保守口径是诚实边界
- Q: 稀释告警的"占比"指什么？ → A: **命中占比**（该项目贡献的命中数 / 总命中数）为判定口径；树数占比作参考维度同时呈现——稀释是"信号来源被单一项目主导"，主导性体现在命中来源上

## 用户场景与测试 *（必填）*

### 用户故事 1 - 跨项目池化构建与分组（优先级：P1）🎯 MVP

回放工程师构建合并模拟器池：按 **(Agent, 形态)** 分组，把多个项目（≥2 个项目）的发现树
读入同一池（读多项目的发现树存储）；每棵树保留项目归属（`project_id`）与时间戳；
**评估器版本一致性检查**：不同评估器版本的树按版本分组（跨版本不混池——否则得分不可比）；
**前置条件**：同 Agent 同形态的树 ≥ 3 棵（不足即拒绝，立项书 F6 前置条件）；池构建
可重现（同输入同池内容）。规范化匹配键不变（**结构键**——009 定案），跨项目同结构
同评估器版本 → 命中。

**为什么是这个优先级**: 池化构建是 F6 的本体——没有可重现、可分组、可防版本混淆的
合并池，后续的跨项目回放、稀释控制、谱系查询都没有可信的基础。

**独立测试**: 构造 ≥2 个项目 × 各 ≥2 棵树的夹具：分组正确、版本分组正确、前置条件
拒绝、同输入同池（可重现）、跨项目同结构命中逐断言；不接回放对比与谱系查询即可交付
"池可合并"的价值。

**验收场景**:

1. **Given** 项目 A 与项目 B 各 ≥2 棵同 Agent 同形态树, **When** 构建合并池, **Then** 池含全部树（归属可追溯），分组 = (Agent, 形态)
2. **Given** 评估器版本不同的树, **When** 构建, **Then** 按版本分组（跨版本不混池）；同版本树可合并
3. **Given** 同 Agent 同形态树 < 3 棵, **When** 构建, **Then** 拒绝并注明（前置条件不足）
4. **Given** 同输入, **When** 构建两次, **Then** 池内容一致（可重现，树集合与顺序确定）
5. **Given** 项目 A 与项目 B 存在**同结构键同评估器版本**的节点, **When** 查询匹配, **Then** 跨项目命中（复用历史得分，不再 UNKNOWN）

### 用户故事 2 - 池化回放与稀释控制（优先级：P2）

回放工程师用合并池回放：observed/probe 规范化匹配（结构键 + 评估器版本在池内全部
项目树中查找）；回放过程**零生成**（审计断言）；**稀释控制**——按项目归属分桶统计
命中分布（per-project 命中率与合并口径双报告）；某项目**命中占比**在合并池中超阈（配置）
→ **如实告警**（不掩盖：立项书风险缓解）；跨形态合并未显式配置即拒绝（默认 (Agent, 形态）
分组）；train/validation 分树在合并池按时间排序（最近树只做 validation，跨项目按时间
全局排序）。

**为什么是这个优先级**: 回放可用性与稀释风险是池化的两个面——既要"跨项目命中扩大
覆盖"的收益，也要"稀释信号如实暴露"的诚实边界（原则六）。

**独立测试**: 构造合并池夹具：跨项目命中统计双口径、稀释超阈告警、跨形态未显式拒绝、
分树时间全局排序逐断言。

**验收场景**:

1. **Given** 合并池（≥2 项目）, **When** 回放某策略, **Then** 跨项目命中发生，per-project 与合并口径命中分布双报告产出
2. **Given** 某项目树占比 > 阈值（配置）, **When** 构建/回放, **Then** 稀释告警产出（如实标注占比与阈值，不阻止但显式可见）
3. **Given** 未显式开启跨形态, **When** 尝试把短剧形态树并入电影形态池, **Then** 拒绝并注明（跨形态合并需显式配置）
4. **Given** 合并池跨项目树, **When** 分 train/validation, **Then** 按时间全局排序，最近树（跨项目）只做 validation
5. **Given** 回放全程, **When** 审计, **Then** 生成/渲染/网关调用计数恒为 0

### 用户故事 3 - 跨项目谱系查询与合并验收（优先级：P3）

谱系负责人做跨项目查询与验收：三维索引支持跨项目链路（policy_version → 它产出的树
（跨项目）→ 它的子策略版本（跨项目））；**合并验收**：同一棵树在单项目池与合并池中
回放，得分必须一致（合并只是扩充候选集，不改变命中规则）；合并口径的无偏性验收
（合并池回放 vs 真实重跑，Kendall τ ≥ 0.95，发布阻塞）；做梦层**可选启用**合并池
（配置开关，默认仍单项目池——防止池化稀释未经批准就影响进化方向）。

**为什么是这个优先级**: 谱系跨项目可查是公司资产的完整面（原则二）；合并验收把
"池化不改变回放语义"变成可证伪的断言；做梦可选启用是稀释风险的另一道闸门。

**独立测试**: 跨项目谱系链路查询、同树双池回放得分一致、合并口径 τ ≥ 0.95、
做梦开关默认关闭逐断言。

**验收场景**:

1. **Given** 跨项目策略谱系, **When** 查询 policy_version, **Then** 报表给出跨项目产出的树与子版本（JSON 可机读，项目归属标注）
2. **Given** 同一棵树, **When** 在单项目池与合并池分别回放同策略, **Then** 该树的回放得分序列一致（合并只扩充候选集）
3. **Given** 合并池, **When** 无偏性验收, **Then** 合并口径 τ ≥ 0.95；注入偏差 100% 拒绝
4. **Given** 做梦层, **When** 未显式启用合并池, **Then** 仍用单项目池（配置开关默认关闭，开关状态入快照）

### 边界情况

- 只有一个项目：合并池降级为单项目池（如实注明，非错误）；前置条件（≥3 棵）仍适用
- 跨项目同结构键但**不同评估器版本**：不命中（评估器版本是匹配的组成，跨版本不复用）
- 跨项目同结构键同版本但**得分冲突**：UNKNOWN 不得分 + 诊断告警（澄清决议：保守口径，不编造）
- 某项目树为 0（合并池由单一项目构成）：稀释告警标注"单项目构成"（命中占比 1.0 必然超阈，如实呈现）
- 跨项目树时间重叠（同时间戳多棵）：按 (时间戳, project_id) 字典序稳定排序（可重现）
- 做梦开关开启但前置条件不满足：做梦仍用单项目池并在快照注明"合并池未启用：前置条件不足"
- 池化后 UNKNOWN 率不降反升（异常）：如实记录并告警（不自动回退，供人工判断）
- 跨项目树的 config_snapshot 差异（同版本评估器但形态配置微调）：如实进谱系标注，
  不影响匹配（评估器版本相同即语义一致）

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供合并池构建器：按 (Agent, 形态) 分组读入多项目发现树；每棵树保留 project_id 与时间戳；评估器版本一致性检查（跨版本按版本分组、不混池）
- **FR-002**: 前置条件必须执行：同 Agent 同形态树 ≥ 3 棵（配置可上调）；不足即拒绝并注明
- **FR-003**: 池构建必须可重现：同输入产同池（树集合与顺序确定）；构建快照落盘（分组/版本/树清单/前置条件）
- **FR-004**: 跨项目匹配必须成立：规范化精确匹配（**结构键** + 评估器版本）在池内全部项目树中查找；命中即返回该历史节点得分（复用不再 UNKNOWN）；跨版本不命中；**多棵命中且得分不同（冲突）→ UNKNOWN 不得分**，冲突如实进诊断告警（不编造、不取均值、不取最新——诚实边界）
- **FR-005**: 池化回放必须零生成（审计断言：生成/渲染/网关调用计数恒 0）
- **FR-006**: 稀释控制必须实现：per-project 与合并口径命中分布双报告；**判定口径 = 命中占比**（该项目贡献的命中数 / 总命中数），树数占比作参考维度同时呈现；命中占比超阈（配置）如实告警（不阻止但显式可见）
- **FR-007**: 跨形态合并必须显式配置：默认 (Agent, 形态) 分组；未显式开启即拒绝并注明
- **FR-008**: train/validation 分树必须按时间全局排序（跨项目）；最近树只做 validation
- **FR-009**: 谱系跨项目查询必须支持：policy_version → 跨项目 tree_ids → child_policy_versions（JSON 可机读，项目归属标注）
- **FR-010**: 合并验收必须执行：同树在单项目池与合并池回放的得分序列一致；合并口径无偏性 τ ≥ 0.95（发布阻塞）+ 注入偏差 100% 拒绝
- **FR-011**: 做梦层必须可选启用合并池：配置开关默认关闭（仍单项目池）；开关状态与前置条件判定入快照；前置条件不满足时如实注明"未启用"
- **FR-012**: 池化分组/阈值/显式跨形态/做梦开关必须全部配置化；稀释告警与 UNKNOWN 率异常如实记录（不自动回退）

### 关键实体 *（如果功能涉及数据）*

- **合并池（MergedPool）**: 按 (Agent, 形态) 分组的跨项目模拟器池——树清单（project_id + 时间戳 + 评估器版本）、构建快照、前置条件判定
- **版本分组（VersionGroup）**: 评估器版本一致的树集合——跨版本不混池的载体
- **命中分布（HitDistribution）**: per-project 与合并口径的命中/UNKNOWN 统计——稀释控制的输入
- **稀释告警（DilutionAlert）**: 项目命中占比超阈的如实告警——命中占比、树数占比（参考）、阈值、构成说明
- **跨项目谱系报表（CrossProjectLineage）**: policy_version → 跨项目 tree_ids → child_policy_versions 的链路（项目归属标注）
- **构建快照（PoolSnapshot）**: 池构建的不可变记录——分组、版本、树清单、前置条件、做梦开关状态

## 假设

- "结构键"匹配语义以 009 定案为准（策略可复现的结构键 + 评估器版本）；池化复用正是
  该语义的跨项目推广——同结构同版本 → 历史得分可复用
- 评估器版本一致的跨项目树，其得分语义一致（评估器版本冻结是前提）；config_snapshot
  的细微差异（形态配置微调）如实标注不影响匹配
- 做梦默认单项目池是保守默认（稀释未经批准不影响进化方向）；启用合并池是配置决策
- 跨项目树的"项目"由 001 的三维索引（project_id）承载；本特性不新增项目概念
- 池化对 010 周校准的影响：锚点与信度按 (Agent, 形态) 归属不变（010 台账按评估器版本
  分层，与池化版本分组一致）
- 合并池的回放性能不做新优化（沿用 002 池的实现；树规模在立项书前置条件下可控）
