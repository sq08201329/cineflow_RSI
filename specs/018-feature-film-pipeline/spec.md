## Clarifications

### Session 2026-09-24

- Q: 本特性的"在真实渠道下跑通"可达范围是什么？ → A: **分层**（本特性最关键的口径）。今天真实可用的只有 **LLM 腿**（019 已交付前置预算门禁、账单对账、运行记录，`core/billing/`）；**平台侧（分镜/视觉/声音/剪辑/宣发）真实适配器已在位但未交付使用**——`docs/pilot-upgrade-manifest.json` 的 B 路径（视频/音频生成，14 个凭证环境变量）与 C 路径（真实投放，2 个）状态均为 `not_delivered`。故本特性的"真实渠道" = **LLM 腿真实 + 平台侧按配置（默认模拟）**，且**每环的真实/模拟标注必须机读可见**；"真实生成渠道"的账号与凭证登记为**运营侧前置输入**（本规格不发明凭证名、平台名，也不假装已具备）。
- Q: 七环节串链的落点在哪？ → A: **链首插入 `dev`**，形成 `dev → script → storyboard → visual → sound → editing → promo`。扩展点是那条**必须同步的字面量清单**（阶段元组、阶段表、`AgentConfigs`、运行时装配含建表 schema、预检的四处清单、样片包的产物 kind 登记与内容类型），**漏一处即红**（详见"边界情况"第 1 条与 FR-001）。017 的既定选择是"不插入"（`specs/017-dev-agent-degraded/spec.md` 澄清第 3 条），插入动作归本特性。
- Q: 跨环节交接契约现在定到字段级映射吗？ → A: **只定契约与验收，字段级映射留 plan**。契约口径沿用既有先例的**同名字段子集**读法：`FieldParity` 的"下游同名键集 == (上游 − 丢弃) ∪ 派生"（`agents/pilot/handoffs.py` 的 `FieldParity`，当前 `:35-75`），丢字段必须显式声明；本特性按 FR-016 把守恒等式扩展为 `下游读取集 == renames(上游 − 丢弃) ∪ 运行级 ∪ 派生`（三类来源 + `dropped` 独立集 + 取数依据，见 FR-004/SC-003）。上游 = 017 的选题产出导出面（`export_slate`，`agents/dev/export_slate.py:37`；导出面字段集已在 017 侧单侧锁定），下游 = 剧本阶段的输入（题材/约束/角色）。
- Q: 长片体量怎么落？ → A: **最小可行长片**——长片体量**按形态配置缩档但不改链路**（立项书 §7 的缓解措施），真实作品与排练分离。缩档档位必须声明且机读，**不得**为长片新造第二套链，也不得把排练产物标为真实作品。
- Q: 样片包的可复现口径变不变？ → A: **不变**。仍是 `PACKAGE_FILES` 五件套（`agents/pilot/package.py:31`）+ `verify_package` 校验（`:105`）+ 同输入同配置重跑逐字节一致。新增的标注与画像字段必须同样确定性（无墙钟、无路径），否则可复现性退化。
- Q: 性能画像的证据从哪来？ → A: **复用运行记录，不新造基建**：各环节起止时间（`core/orchestration/models.py:242-243` 的 `started_at`/`finished_at`）+ 体量指标（镜头数/片段数/成片时长/页数）+ 形态配置声明的阈值。**固定时钟（确定性档）的运行不得用作性能证据**——那组时间戳是常量，只能证明可复现，不能证明快慢；二者必须分开如实标注。「专用基准环境下的绝对标定」属三期 WS3 第 3 项（`docs/三期立项书.md:127`），不在本特性。
- Q: 分镜渲染器的 4 位序号编码（≤16 镜/组）与长片体量冲突，怎么解？ → A: **索引码泛化为 R×C 块网格（容量 `2**(R·C)`），不固定 4 位**（保留"每镜一码"的确定性口径；**不取**"按镜组切分"——那会引入组间边界语义，**不取**"最小可行长片限镜数"——那会让 G2 的"长片体量"名存实亡）。约束 `2**C ≤ render.width`（每列块 ≥1px）与 `2**(R·C) ≥ 该形态派生镜头数`；`rows`/`cols` 入形态配置、缺项即报错；产物格式变更随 plan 定；**网格参数进入任一评估器的实现哈希，按原则一升版本是强定义务**（**仅改配置网格取值也必须升版本**；同 id 同 version 不得改行为）；既有已落盘工件为**内容寻址**，**不受影响**，**禁止**静默改写历史节点。
- Q: 剧本阶段的输入到底取自运行级输入还是上游交接？ → A: **有 `dev` 阶段时取自 `dev → script` 交接结果；无 `dev` 阶段（如既有短剧试水链）回落 run 级 `pilot_inputs`**。两条来源必须**显式声明**（标明生效的是哪一条），**禁止静默择一**；生效来源须随机读可见。
- Q: 场景数是码内默认（`_DEFAULT_SCENE_COUNT = 4`），与"缩档只改配置"矛盾，怎么办？ → A: **场景数入形态配置**（新键名由 plan 定），**缺项即报错、不取码内默认**；`agents/pilot/stages.py:97` 的 `_DEFAULT_SCENE_COUNT` **不得**继续作为默认值来源。这是"缩档只改配置"（FR-013/FR-014、宪章原则五）的必要条件。
- Q: 最小可行长片的档位用什么形式表达？ → A: 由**形态配置声明的"排练档"**表达：**链路与环节不变，仅时长/镜数/规模按档缩减**；**真实作品用形态原值**（不缩档）。**档位取值属运营侧输入**（配置声明 + 未标定登记），本规格**不发明数字**。
- Q: 真实生成渠道（平台侧 B/C 路径）的厂商对接怎么安排？ → A: **运营侧前置输入**（凭证 / 平台名 / 预算档）——本特性不发明、也不假装具备；B/C 路径仍为 `not_delivered` 期间**禁止**"真实渠道全链路已跑通"这类表述（与 FR-011 / SC-004 同一口径，此处复核为一致）。
- Q: `configs/movie.yaml` 的 `screenplay.target_duration_min: 90`（分钟）与 `editing.target_duration_s: 120`（秒，即 2 分钟成片）自相矛盾，且计划里的体量常量（`range(4)` 场景数、`range(12)` 每场景行数）是码内常量、`ops/demo_pilot.py` 又在脚本里改临时配置副本缩档——这组"movie 形态跑不通"的问题怎么裁？ → A: **A + 排练档**（三件事同批，不是取舍）：① **修 movie 形态的口径矛盾按长片语义（是修 bug，不是取舍）**——`editing.target_duration_s` **必须等于** `screenplay.target_duration_min × 60`（movie ⇒ **5400 秒**；现值 120 秒是从短剧形态抄来的 bug——shortdrama 的 120 秒 ↔ 2 分钟本就自洽），规格写明这条不变量，不一致即**拒绝启动并点名两处实测值**；**体量常量**（`range(4)` 场景数、`range(12)` 每场景行数）**入形态配置**（与场景数同批，缺项即报错、不取码内默认）；**时长粒度**：秒级声明（浮点秒，可表达 30 秒演示档）+ 浮点分钟（`0.5` 合法）+ 折算容差 `1e-6`；② **"最小可行长片"以配置声明的"排练档"表达**（FR-013 既有口径不变：**链路与环节不变，仅时长/镜数/规模缩档**；**真实作品用形态原值**）；③ **移除脚本内改配置缩档**——`ops/demo_pilot.py` 现在在脚本里改临时配置副本来缩档（与"缩档只改配置"直接冲突），必须改为**只经形态配置**；同时把该演示里配置加载器计数的**字面量断言改为派生断言**（该字面量恒假，属既有缺陷；**计数随实现派生，规格不写数字**）。**索引容量另裁（同轮）**：索引码**不固定 4 位**，泛化为 **R×C 块网格**（容量 `2**(R·C)`，约束 `2**C ≤ render.width` 且 `2**(R·C) ≥ 该形态派生镜头数`），`rows`/`cols` 入形态配置——movie 原值派生 **2700 镜** ⇒ 容量 ≥ 12 位。**数字（排练档取值与性能阈值）属运营侧输入，本规格不发明**。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 七环节全链路跑通与最小可行长片（优先级：P1）🎯 MVP

制片线跑一轮长片编排：**开发**（立项组合，链首）→ 剧本 → 分镜 → 视觉 → 声音 → 剪辑 → 宣发。七个环节按同一条 DAG 依次执行，每环调用对应 Agent 的既有 loop 入口（零新增落树路径）；任一环失败即整轮失败、不产半包。全链路跑完产出**可复现样片包**（五件套），体量按形态配置声明的**"排练档"**（= 最小可行长片档；真实作品用形态原值）缩档——**缩的是数字，不是链路**。

**为什么是这个优先级**: G2 行第一句就是"七 Agent 串链……跑通一部长片体量项目"。没有这条链，后面的交接契约、成本账目、性能门禁都没有承载物；它也是把 017 的选题产出真正接到生产主线的唯一动作。

**独立测试**: 全模拟后端 + 固定时钟跑一轮，断言运行记录为七环节全 `done`、样片包五件套齐备且过 `verify_package`、同输入重跑逐字节一致；把 `dev` 从阶段表移除（模拟漏同步）即红。

**验收场景**:

1. **Given** 一条七环节阶段表, **When** 装配 DAG, **Then** 拓扑序恰为 `dev→script→storyboard→visual→sound→editing→promo`，且每环依赖前一环（阶段元组与阶段表一致，不一致即红）
2. **Given** 合规运行输入, **When** 跑一轮, **Then** 运行记录七环节全 `done`，产出样片包五件套，`verify_package` 通过
3. **Given** 同一输入与配置, **When** 独立工件根重跑一次, **Then** 五件套逐字节一致（含量新增的标注与画像字段）
4. **Given** 任一环节失败, **When** 编排收口, **Then** 整轮失败、**不装配样片包**（不产半包），失败点与其后阶段的 `skipped` 状态如实落记录
5. **Given** 全模拟后端, **When** 读取样片包, **Then** 每环来源标注为 `simulated`，且**不得**出现任何"真实渠道全链路已跑通"的表述
6. **Given** 上一轮在途中中断, **When** 断点续跑, **Then** 已完成环节零重跑、输入/配置指纹不一致即拒绝（沿用 015 口径，链首多一环不改变该语义）

### 用户故事 2 - 选题产出 → 剧本输入的跨环节交接契约（优先级：P2）

选题负责人跑完选题线，产出立项组合工件；编排把组合内**"本轮进入生产"**标记指向的那条选题，按**字段级交接声明**交给剧本环节：题材（`genre`）/约束（`constraints`）/角色（`characters`）三个可移交要点逐字段可追溯，凡上游有、下游不要的字段必须写进**丢弃声明**，凡下游新增的必须写进**派生声明**。标记悬空、越界或指向多条时，下游**拒绝启动**，不猜也不静默取第一条。

**为什么是这个优先级**: 这是 G2 行明确点名的第二项交付（"跨环节交接契约扩展（017 的选题产出 → 剧本输入）"），也是 017 留下的、唯一被显式挂到 G2 的跨特性债务（`docs/三期立项书.md:255`："字段级 `FieldParity` 声明留给 G2 立"）。没有它，七环节只是六环节前面挂了一段互不相认的选题。

**独立测试**: 用夹具立项组合工件（含悬空标记、越界标记、要点缺失、字段增删四种注入）跑交接：字段集守恒断言逐项通过；丢字段未声明即报错；标记非唯一/悬空时下游拒绝启动且原因点名；导出面 schema 变更只在单侧改即红。

**验收场景**:

1. **Given** 一份合规立项组合工件, **When** 交接, **Then** 产出剧本输入视图，`下游读取集 == renames(上游 − 丢弃) ∪ 运行级 ∪ 派生` 成立（来源分类 = `reads` 的**三类**：承接含**改名承接** / 运行级 / 派生；`dropped` 是与之**并列的独立集合**；**承接 ≠ 丢弃**），且导出面与下游字段集**双向可机读**
2. **Given** 上游导出面新增或删除字段, **When** 未同步更新交接声明, **Then** 断言失败（两侧必须同步：schema 版本、导出面快照、交接声明）
3. **Given** 组合内无"进入生产"标记或指向不存在条目, **When** 交接, **Then** **下游拒绝启动**（不静默取任一条、不用第一条兜底），错误信息点名具体违规
4. **Given** 被标记条目的可移交要点任一为空, **When** 交接, **Then** 拒绝并点名缺失字段（与 017 的 `rule.slate_structure` 判 0 口径同源，此处为交接侧的第二道防线）
5. **Given** 上游链路失败（`dev` 未产出工件）, **When** 下游被调度, **Then** 下游零调用、如实 `skipped`（不以上一轮残留产物顶替）
6. **Given** 交接已成立, **When** 审计, **Then** 剧本输入的每个字段都能回到上游字段或其派生声明（可追溯率 100%）
7. **Given** 存在 `dev` 阶段, **When** 剧本阶段被调度, **Then** 其输入取自 `dev → script` 交接结果；**Given** 链上无 `dev` 阶段（既有短剧试水链）, **Then** 回落 run 级 `pilot_inputs`——两条来源在运行时**显式声明**（生效来源随机读可见），**禁止静默择一**

### 用户故事 3 - 长片体量的性能与预算门禁 + 样片包成本与评估分量（优先级：P3）

运营与评审面拿到样片包与运行记录：**全链路成本账目**覆盖七环节（含 `FAILED` 调用，原则二），样片包 `cost.json` 三方一致（运行记录阶段成本 ⨯ 各 Agent 落盘账目 ⨯ 网关/账本记账）；**各环评估分量**（`evaluator_id@version` 与分量值）随包可查；**性能画像**给出各环节墙钟耗时与体量指标，并与形态配置声明的阈值对照判定"长片体量达标"；LLM 腿的额度按**环节分档**（019 口径）与全链路串联。

**为什么是这个优先级**: G2 行的验收列写的是"成本账目 + 各环评估分量 + 性能与预算门禁达标"——它们都建立在链路先跑通之上，天然排在 P1/P2 之后；但它们正是"这部长片到底花了多少、快不快、每环凭什么分数"的唯一证据面。

**独立测试**: 夹具运行记录与账目注入三类偏差（阶段成本 vs 落盘账目、合计 vs 逐项、网关记账口径），断言对账逐项报错；评估分量缺项即装配失败；性能画像对"固定时钟运行"拒绝给出达标结论；阈值未标定时输出"未标定"而非数字。

**验收场景**:

1. **Given** 七环节完成的运行, **When** 装配样片包, **Then** `cost.json` 覆盖七环节、逐项差额在容差内、合计等于逐项之和（`ledger_payload` 口径）且 `reconciled` 为真
2. **Given** 某环节调用失败（`FAILED`）, **When** 入账, **Then** 该环节成本照常计入（原则二），且账目与运行记录一致
3. **Given** 任一环节缺评估分量, **When** 装配, **Then** 拒绝装配（不得以"不适用"留空冒充分量齐备）
4. **Given** 一次真实时钟的运行, **When** 生成性能画像, **Then** 输出各环节耗时与体量指标，并给出与配置阈值的对照结论；**Given** 固定时钟运行, **Then** 明确标注"耗时为确定性常量、不构成性能证据"且不产出达标结论
5. **Given** 性能阈值未标定, **When** 出画像, **Then** 如实标注"未标定"，**不得**在配置或代码里发明数字
6. **Given** 全链路一次运行, **When** 审计 LLM 腿额度, **Then** 每环节的调用均经按环节分档的前置门禁（019 口径，超限即拒绝且零入账），且 dev 环节的档位在两形态均已声明（缺档即预检拒绝启动）

### 关键实体 *（如果功能涉及数据）*

- **七环节运行记录（RunRecord，复用）**: 运行标识 + 形态 + 配置/输入指纹 + 七环节状态（含起止时间、成本、产物引用、明细）+ 失败点；链首多一环不改变其语义
- **阶段定义（StageSpec，复用）**: 阶段标识 + 依赖 + 执行入口 + 输入契约（交接函数）+ 输出工件类型；本特性新增链首一段
- **跨环节交接声明（FieldParity，复用）**: 上游导出字段集 / 下游输入字段集 / 显式丢弃集 / 显式派生集 + 守恒等式与断言；本特性新增 `dev` → 剧本一条
- **选题产出导出面（SlateExport，017 交付）**: `schema_version` / `entries`（每条含方向标识、论证要点、分量、`genre`/`constraints`/`characters`、条目级标记）/ `production_marks` / `signal_sources`；变更须两侧同步
- **环节来源标注（StageChannelMarking，新增）**: 每环节使用的后端与来源（`real` / `simulated`）、取值来源（装配面声明）、LLM 腿的渠道与档案引用；禁止推断与谎报
- **性能画像（PerformanceProfile，新增）**: 各环节墙钟耗时 + 体量指标 + 阈值快照与达标结论 + "未标定/不构成证据"标注
- **环节评估分量（StageEvalBreakdown，新增）**: 每环节的 `evaluator_id@version` 与分量值（复用树节点的 `eval_breakdown` 口径，随样片包外化）
- **最小可行长片档（FeatureScaleProfile，新增）**: 形态配置声明的**"排练档"**体量档位（成片时长/页数/单镜时长/镜头数/**场景数**——含场景数配置键，缺项即报错）+ 与"形态原值（真实作品）"的对照 + "排练 vs 真实作品"标记；档位数字属运营侧输入，未标定即如实登记
- **剧本输入来源声明（ScriptInputSource）**: 剧本阶段生效的输入来源——`dev → script` 交接结果 或 run 级 `pilot_inputs`；取值随机读可见，禁止静默择一
- **账目对账（CostLedger，复用）**: 按阶段/来源/形态的合计 + 逐项对账行；从六环节扩到七环节并接三方口径
