## Clarifications

### Session 2026-09-20

- Q: 音画同步门禁的对齐基准输入是什么？ → A: 仅时序元数据（台词/音效起止时间戳清单），同步检测 = 音频事件时间 vs 元数据；声音 Agent 自包含，不依赖视觉工件；真实波形-画面对齐属剪辑 Agent（F2）接入时定义
- Q: 声音生成适配器按类型拆分还是单一适配器？ → A: 三个独立适配器（TTS/音效/音乐各一），各自双实现（确定性模拟 + 真实 API 骨架），共享同一套契约套件；成本按生成类型分账

## 用户场景与测试 *（必填）*

### 用户故事 1 - 声音探索执行与确定性模拟生成（优先级：P1）🎯 MVP

声音生产线运行一轮探索：当前策略对输入（台词文本 + 时序元数据 + 情绪基调；时序元数据 =
台词/音效起止时间戳清单，声音 Agent 自包含、不依赖视觉工件）产出
生成参数（配音音色/语速档位、音效密度、配乐情绪档位、备选条数、重试策略）→ 执行器
经预算门禁（单轮 ≤ 配置上限，事务扣减防双花、轮次幂等）调用生成适配器 → 产出音频工件
（wav，BLAKE3 内容寻址）与预估/实际成本入账。适配器双实现：确定性模拟生成器（参数
种子 → 程序化音频 → wav，逐字节可复现）为开发/CI 默认；真实 TTS/音乐 API 适配器骨架
（无凭证跳过契约用例）。生成中间态落可变运营表，工件与指标齐备后节点一次性完整
INSERT 进发现树（两段式落盘）。

**为什么是这个优先级**: 生成执行是闭环的物质基础——没有声音工件落树，评估器、回放、
进化全是空中楼阁。中等昂贵动作的预算纪律（原则三）也在此落地。

**独立测试**: 用确定性模拟生成器跑一轮探索：参数→wav 逐字节复现、预算门禁超界拒绝、
运营表中间态 → 节点一次性 INSERT、成本入账逐断言；不接评估器与做梦层即可交付
"声音工件可落树"的价值。

**验收场景**:

1. **Given** 台词与情绪基调输入 + 当前策略, **When** 执行一轮探索, **Then** 产出音频工件（wav 内容寻址）+ 成本入账 + 节点一次性 INSERT（两段式落盘）
2. **Given** 同一生成参数集, **When** 模拟生成器执行两次, **Then** 两个 wav 工件逐字节一致（哈希相等）
3. **Given** 单轮预算配置上限, **When** 策略请求超上限的生成量, **Then** 预算门禁拒绝超额部分，已执行部分成本照常入账
4. **Given** 同轮次重复触发执行, **When** 幂等检查, **Then** 不重复扣费、不重复落节点
5. **Given** 模拟与真实适配器, **When** 跑同一套契约套件, **Then** 模拟全过、真实无凭证按用例跳过（接口语义同等受约束）

### 用户故事 2 - 四评估器与合成评分（优先级：P2）

评估工程师为声音节点打分：硬规则双门禁——`rule.loudness_compliance`（对白响度
-27 LUFS ±2，违规即总分 0）与 `rule.av_sync`（音画同步误差 ≤ 阈值，配置）；代理模型
双分量——`proxy.asr_transcript`（ASR 转写与台词比对，字错率映射为得分）与
`proxy.emotion_music_match`（情绪-配乐匹配度分类器）；合成评分 = 门禁 + 加权求和
（权重形态配置），入库前定点归一（6 位小数，004 决策）。全部评估器版本冻结
（`evaluator_id@version` + 实现哈希），deterministic=True 方可入回放打分。

**为什么是这个优先级**: 评估器组合是声音环节的"信号源"（技术方案核心命题）——信号
质量决定后续进化是否可信；但评估依赖 US1 的工件落树。

**独立测试**: 构造已知声学属性的 wav 夹具（响度合规/违规、同步偏移、台词含错字、
情绪匹配/背离）：四评估器得分、门禁语义、定点归一、版本哈希逐断言；不依赖闭环即可
交付"声音节点可打分"的价值。

**验收场景**:

1. **Given** 响度超出 -27 LUFS ±2 的工件, **When** 评估, **Then** 门禁判 0，总分直接为 0（gate 语义）
2. **Given** 音画同步误差 ≤ 阈值与 > 阈值两组工件, **When** 评估, **Then** 前者通过后者门禁判 0，阈值来自配置
3. **Given** 台词与 ASR 转写含已知错字率, **When** proxy.asr_transcript 评估, **Then** 得分与错字率映射口径一致（误差 < 1e-6）
4. **Given** 同一工件重复评估, **When** 比较得分, **Then** 定点归一后逐位一致（确定性 + 6 位小数）
5. **Given** 评估器注册, **When** 检查版本元信息, **Then** 实现哈希入版本号，非确定性评估器拒绝注册

### 用户故事 3 - 闭环接入做梦层与一致性验收（优先级：P3）

做梦工程师把声音 Agent 接入自动进化：新树冻结入池（train/validation 分树沿用 005
口径）→ 做梦层生成声音策略候选（策略代码 = 声音风格探索策略）→ 沙箱全池回放打分
（reward = pareto_auc − λ·并行惩罚，口径复用）→ 人工审批 → 次日部署。**一致性验收
（发布阻塞）**：回放打分 vs 真实重跑得分的 Kendall τ ≥ 0.95；产出首轮进化曲线。

**为什么是这个优先级**: 自动进化是立项书 F1 的"闭环"含义与里程碑验收线，但依赖
US1/US2 的工件与信号就位；无偏性 τ 是宪章发布门禁，不过即不接入。

**独立测试**: 用模拟生成器 + 评估器组合跑"回放 vs 真实重跑"对照（002 无偏性套件口径）：
τ ≥ 0.95 达标断言 + 注入偏差的拒绝用例；做梦一轮产出进化曲线。

**验收场景**:

1. **Given** 声音模拟器池 ≥2 棵树, **When** 无偏性验收, **Then** 回放与真实重跑得分序列 Kendall τ ≥ 0.95
2. **Given** 注入偏差的评估器, **When** 无偏性验收, **Then** 100% 被拒绝（不接入发布）
3. **Given** 一轮做梦（声音策略候选）, **When** 沙箱全池回放, **Then** reward 口径与 promo/visual 一致，零生成审计断言通过
4. **Given** 首轮进化完成, **When** 查看产出, **Then** 进化曲线落盘（首轮基线记入，验收口径同 005）

### 边界情况

- 生成调用部分失败：失败条目成本照常入账（原则二），该备选记 FAILED 状态，不阻断轮次
- 台词为空或纯音效段（无配音）：ASR 比对跳过并注明，响度门禁按音效档标准（配置分档）
- 静音/极短音频：响度测量与同步检测给出"不适用"注明而非伪造得分
- 情绪分类器低置信：得分照出但 diagnostics 标注置信度，不进盲评 top-k 候选
- 模拟生成器与真实 API 的格式差异：契约套件只约束接口语义（参数/工件/成本字段），不约束音质
- 预算耗尽 mid-round：已执行部分落盘入账，轮次以实际产出收口并注明
- 台词文本与时序元数据不匹配（上游输入错误，如台词时间戳重叠/越界）：执行前校验拒绝，不产生任何成本

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供声音探索执行器：输入 = 台词文本 + 时序元数据（台词/音效起止时间戳清单）+ 情绪基调 + 当前策略；输出 = 音频工件（wav 内容寻址）+ 成本入账 + 发现树节点
- **FR-002**: 生成适配器必须按类型拆分：TTS / 音效 / 音乐三个独立适配器，各自双实现（确定性模拟生成器——参数种子 → 程序化音频 → wav 逐字节复现；真实 API 适配器骨架）；三者共享同一套契约套件（真实无凭证按用例跳过）
- **FR-003**: 预算门禁必须执行：单轮生成 ≤ 配置上限（形态配置，可按类型分档），事务扣减防双花，轮次幂等；超界部分拒绝，已执行部分成本照常入账（含 FAILED 条目）；成本必须按生成类型（TTS/音效/音乐）分账
- **FR-004**: 两段式落盘必须执行：生成中间态落可变运营表，工件与指标齐备后节点一次性完整 INSERT；发现树不开可变口子
- **FR-005**: 硬规则评估器必须实现：`rule.loudness_compliance`（-27 LUFS ±2，gate）与 `rule.av_sync`（音频事件时间与时序元数据的偏差 ≤ 阈值，gate，阈值配置化；不含波形-画面对齐——真实画面对齐属剪辑 Agent 范畴）；gate 违规总分直接为 0
- **FR-006**: 代理评估器必须实现：`proxy.asr_transcript`（ASR 转写 vs 台词字错率映射得分）与 `proxy.emotion_music_match`（情绪-配乐匹配度分类）；低置信标注 diagnostics
- **FR-007**: 合成评分必须 = 硬规则门禁 + 加权求和（权重形态配置），入库前定点归一（6 位小数）；评估器全部版本冻结（实现哈希入版本号、deterministic=True）
- **FR-008**: 声音树必须接入回放模拟器池（observed/probe、规范化精确匹配、UNKNOWN 语义复用 002），回放零生成（审计断言）
- **FR-009**: 无偏性验收必须执行：回放 vs 真实重跑 Kendall τ ≥ 0.95 方可接入发布；注入偏差必须被拒（发布阻塞门禁）
- **FR-010**: 做梦层必须支持声音策略进化：候选策略代码（声音风格探索策略）静态检查 → 沙箱全池回放 → reward 口径复用（pareto_auc − λ·并行惩罚）→ 人工审批 → 部署指针（v1.1.0 人工抽检条款下，一期既有 approve 流程不变）
- **FR-011**: 全部生成调用必须经预算与成本入账；LLM 调用（如有辅助文案）必须过网关；模拟器池按时间分 train/validation（最近树永远只做 validation）
- **FR-012**: 周期、k 值、响度/同步阈值、评估器权重、预算上限必须全部形态配置化（configs/*.yaml）；声音 Agent 必须纳入 010 周校准的盲评范围（proxy 层有人评锚点需求）

### 关键实体 *（如果功能涉及数据）*

- **声音生成作业（SoundGenJob）**: 一条生成任务的运营中间态——生成类型（TTS/音效/音乐）、参数集、状态、预估/实际成本、工件引用；两段式落盘的可变侧，成本按类型分账
- **音频工件（AudioArtifact）**: wav 内容寻址引用——BLAKE3 哈希、时长、采样率、声道
- **声音节点（SoundNode）**: 发现树节点（TreeNode 全字段）——prompt = 台词/情绪输入、observation_context、eval_breakdown（四评估器分量）
- **声音风格策略（SoundPolicy）**: 被进化对象——音色/语速/音效密度/配乐情绪档位/备选条数/重试策略的决策代码（OptimalPolicy.solve() 形态）
- **评估器组合（SoundEvaluatorSet）**: 双 gate + 双 proxy 的注册与版本快照

## 假设

- 真实 TTS/音乐 API 不接凭证：适配器骨架 + 确定性模拟双实现，真实接入是凭证配置动作（同 003/004 诚实边界）
- 上游输入（台词文本、时序元数据、情绪基调）以夹具/配置文件提供；声音 Agent 自包含，不依赖视觉 Agent 工件；真实波形-画面对齐与跨 Agent 输入契约在剪辑 Agent（F2）、分镜 Agent（F3）接入时定义，本特性只定义声音侧输入 schema
- 声音评估器组合不含 judge 层（技术方案 §2.2 声音行仅硬规则 + 代理模型）；人评锚点经 010 周校准按"后续新 Agent"口径纳入盲评范围
- 音乐/音效的版权审核链不在本特性（技术方案风险登记册事项，待单独立项）
- 自动进化沿用 005 既有 approve 流程；宪章 v1.1.0 的自动部署（F9）尚未交付，本特性不做部署自动化
- 声音的响度/同步测量以成熟算法（如 ITU-R BS.1770 响度）的确定性实现为准，具体库选型属 plan 阶段；模拟生成器的"程序化音频"只需声学属性可控（响度/时长/谐波结构可注入），不追求真实音质
