# 功能规格说明：LLM 模型档案与角色路由（多厂商 / 分角色 / 价目随配置冻结）

**功能分支**: `016-llm-model-routing`

**创建日期**: 2026-09-22

**状态**: 草稿

**输入**: 用户描述："把 LLM 接入从'一对环境变量只能连一家'升级为**配置化的模型档案 + 角色路由**：①**模型档案**——每家一个档案，声明端点、凭证环境变量名、价目与价目口径备注（价格因厂商而异且会变，故**绝不内置价目表**）；②**角色路由**——角色（生成 / judge / 做梦候选 / 文案 …）→ 档案的映射，使'便宜模型写候选、强模型当 judge'成为配置；③**中立凭证变量**——各档案声明自己的环境变量名（如 `CINEFLOW_DEEPSEEK_API_KEY`），避免与环境中无关的 `OPENAI_*` 冲突（现状已出现过把平台自带的第三方 key 误判为就绪）。验收：换厂商 = 加档案；分角色用不同模型 = 改映射；价格变化 = 改配置且**历史节点成本口径不被改写**（随 config_snapshot 冻结）；档案/映射/价目缺失即报错。"

**约束来源**: 项目宪章 v1.1.0（**原则一**：评估器/口径版本冻结——**价目属成本口径，必须随配置快照冻结，禁止内置进代码**，否则历史成本不可复现、审计重算会漂移；原则三：一切 LLM 调用必须经网关（统一计费/缓存/重试），模型路由**必须**发生在网关内而非业务代码；原则五：配置化——端点/价目/角色映射全走 `configs/*.yaml`；原则六：诚实边界——**网关记的账不是厂商账单**，价目口径与估算局限必须如实标注）。业务依据 `docs/影视全Agents公司技术方案.md` §2.1（L3 judge 委员会）、§3.4（成本计量）。依赖功能 003（LLM 网关最小版：计费/缓存/重试）、009/014（缺口即报错的配置纪律）、015（`pilot.llm_backend` 与冒烟器、凭证核查器与升级清单）。

## Clarifications

### Session 2026-09-22

- Q: 调用"角色"是固定枚举集还是自由字符串？ → A: **固定枚举集**（按既有调用点归纳：`generation` / `judge` / `dreaming_candidates` / `copywriting` 等）；配置中出现枚举外的角色即报错；仅**枚举内**的未映射角色才回落默认档案——防止"judge 拼错 → 静默降到便宜模型"这类事故
- Q: 单档案时"默认档案"是否必须显式声明？ → A: **单档案可省略**（自动认定该唯一档案为默认，报告显式标注"自动认定"）；**多档案必须显式声明**默认档案，缺则报错

## 用户场景与测试 *（必填）*

### 用户故事 1 - 模型档案与价目（配置化，随快照冻结）（优先级：P1）🎯 MVP

运维/评测负责人配置模型档案：在形态配置里为每个要用的模型声明一个**档案**——档案标识、
端点（URL，或读环境变量的端点名）、**凭证环境变量名**、**价目**（每 1k prompt /
completion tokens）与**价目口径备注**（如"峰时缓存未命中上限，保守高估"）。系统按档案
解析后端与价目：**档案缺失、价目缺失、端点缺失即报错**（不静默用默认价/零成本）；
**只有一个档案时行为等价于现状**（零配置迁移成本）。价目随运行以 **config_snapshot
冻结进树**：此后运维改价目**只影响新节点**，历史节点成本口径不被改写（可审计复算不变）。

**为什么是这个优先级**: 它是另外两个故事的基座；更关键的是——**价目一旦内置进代码，
历史成本就不可复现**，这条纪律必须先立住，否则后面所有成本结论都失去审计资格。

**独立测试**: 夹具配置（单档案 / 多档案 / 缺价目 / 缺端点 / 零价目本地模型）：解析、
报错、冻结与"改价目不污染历史"逐断言；不接角色路由即可交付"档案与价目可声明、可冻结"。

**验收场景**:

1. **Given** 配置声明单档案（端点 + 凭证环境变量名 + 价目）, **When** 网关初始化, **Then** 按该档案解析后端与价目；行为与现状等价（既有测试全绿）
2. **Given** 配置声明多档案（如 `deepseek-flash` / `deepseek-pro` / `local-qwen`）, **When** 解析, **Then** 每档案的端点/凭证变量名/价目独立生效（互不串用）
3. **Given** 档案缺价目或缺端点, **When** 初始化, **Then** 启动即报错（不静默零成本、不回落默认价）
4. **Given** 本地自建模型声明价目 0, **When** 初始化, **Then** 允许（显式声明零边际成本），但必须在快照中如实记录"零价目 = 自建/零边际成本"
5. **Given** 某轮运行已落树, **When** 运维修改配置里的价目后重跑审计, **Then** 历史节点成本与快照口径一致（**不被新价目改写**）
6. **Given** 档案的价目备注（如"峰时上限"）, **When** 查看快照/报告, **Then** 备注随价目一同冻结（口径可追溯）

### 用户故事 2 - 角色路由（优先级：P2）

评测负责人配置角色映射：把**角色**（生成 / judge / 做梦候选 / 文案 等）映射到档案——
例如"judge 用强模型、做梦候选用便宜的本地模型"。网关按**调用角色**选择后端的档案
（端点 + 凭证 + 价目），业务代码**不感知厂商**（仍只调网关）；未映射的角色回落到**默认
档案**（显式声明，禁止隐式取第一个）；映射指向不存在的档案即报错。运行时同一轮内多档案
并存：**成本按档案分别入账**，账目可分解到"哪个角色、哪个模型花了多少"。

**为什么是这个优先级**: 这是"每家价格不一样"的正解——用配置表达"贵的地方少用、便宜的地方多用"，而不是把价目写死进代码；也让"只切 LLM"时能精确控制哪些调用走真实模型、哪些留在 Mock。

**独立测试**: 夹具配置（角色映射齐 / 部分缺 / 指向不存在档案）：路由选择、回落、
报错、成本分解逐断言。

**验收场景**:

1. **Given** 角色映射 `{judge: deepseek-pro, dreaming_candidates: local-qwen}`, **When** 分别以对应角色调用网关, **Then** 命中各自档案（端点/凭证/价目）且成本按档案折算
2. **Given** 未映射的角色, **When** 调用, **Then** 回落到**显式声明的默认档案**；**单档案配置可省略默认声明**（自动认定该唯一档案，报告显式标注"自动认定"）；**多档案未声明默认即报错**
3. **Given** 映射指向不存在的档案 **或配置出现枚举外的角色名**, **When** 初始化, **Then** 报错（不静默跳过、不静默换档案、不静默降级到默认档案）
4. **Given** 一轮运行中多角色调用, **When** 查看成本账目, **Then** 可分解到"角色 × 档案"（同档案多角色可合并展示，但来源可追溯）
5. **Given** 业务代码, **When** 静态检查, **Then** 无任何厂商名/端点/模型名的硬编码（路由只在网关与配置）

### 用户故事 3 - 中立凭证与可操作性（优先级：P3）

运维接线凭证：各档案声明**自己的环境变量名**（如 `CINEFLOW_DEEPSEEK_API_KEY` /
`CINEFLOW_LOCAL_LLM_BASE_URL`），系统按声明读取——**不再依赖 `OPENAI_*` 这一对全局名**
（现状的后果：环境里存在无关的第三方 `OPENAI_API_KEY` 时会被误判为就绪）。凭证核查器、
LLM 冒烟器、升级清单与"清单 ⇄ 代码"机检锁随之同步：核查器**如实区分**"档案声明的变量
已设置 / 未设置 / 设置了但连不通"，并在报告中**标注该变量属于哪个厂商档案**（不再有
`OPENAI_*` 的假阳性歧义）。同时把"网关记账 ≠ 厂商账单"与价目口径的局限（峰谷/缓存
命中率无法在单一费率表表达）如实呈现在报告与文档里。

**为什么是这个优先级**: 它决定这套东西**用起来会不会坑人**——凭证错配是运维事故的高频来源（本项目已经真实撞过一次）；诚实标注估算局限是原则六的要求。

**独立测试**: 夹具环境变量（中立名设置/未设置/回落到旧名）：核查器报告、错误信息、
机检锁一致性逐断言。

**验收场景**:

1. **Given** 档案声明 `CINEFLOW_LLM_API_KEY` 且已设置, **When** 初始化, **Then** 读该变量成功；环境中的 `OPENAI_API_KEY` **不参与**（不再被误判）
2. **Given** 档案声明的变量未设置, **When** 核查, **Then** 报告"未设置 + 所属档案 + 该档案用途"（可操作）
3. **Given** 变量已设置但端点连不通, **When** `--probe`, **Then** 与"未设置"明确区分（沿用既有探测分型）
4. **Given** 配置与文档, **When** 跑机检锁, **Then** 清单里登记的变量名 == 代码/配置实际读取的名字（漂移即红）
5. **Given** 成本报告, **When** 查看, **Then** 含价目口径备注与"记账非账单"的显式声明（不与厂商账单混淆）

### 边界情况

- 同一档案被多个角色引用：合法（成本按档案合并展示，但角色来源保留）
- 同一角色在不同形态配置里指向不同档案：合法（形态差异只体现在配置值）
- 档案价目为 0（自建模型）：合法，但快照必须标注"零边际成本"，且**不得**被解读为"免费调用"（仍有自建成本）
- 凭证在配置里以明文 URL（非环境变量名）声明：允许（自建/本地端点常见），但快照必须记录该 URL 的 host（**不记录密钥**）
- 运行中档案指向的端点不可用：按既有错误分型（瞬态可重试 / 永久失败）处理，**禁止**静默回落到其他档案
- 角色映射循环或自指（档案 A 的 judge 指向档案 B 的 judge）：不允许——映射是角色 → 档案的单层跳转，检测到多层即报错
- 配置里声明了未被任何角色引用的档案：允许（预置），但启动时在报告中列出"未被引用的档案"（提示可能是笔误）
- 旧配置（只有 `screenplay.model` + `model_prices` 的扁平写法）：**必须**可平滑迁移（要么自动映射为单档案，要么给出明确的迁移报错），不得静默失效

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须支持**模型档案**声明（每条：档案标识、端点或其环境变量名、凭证环境变量名、prompt/completion 每 1k tokens 价目、价目口径备注）；档案缺端点/缺凭证名/缺价目即报错（不静默零成本、不回落默认价）
- **FR-002**: **价目与端点必须随 config_snapshot 冻结进树/账目**；运维后续改价目**只影响新节点**；历史节点成本口径不被改写（审计复算一致性可断言）
- **FR-003**: 系统必须支持**角色 → 档案**映射（单层跳转）；**角色为固定枚举集**（按既有调用点归纳，如 `generation` / `judge` / `dreaming_candidates` / `copywriting`）——配置中出现**枚举外角色即报错**；未映射的**枚举内**角色回落到**显式声明的默认档案**；映射指向不存在档案、或出现多层/自指即报错
- **FR-004**: 模型路由**必须**发生在网关内（业务代码只调网关，不感知厂商/端点/模型名）；静态断言：业务代码无厂商名/端点/模型名字面量与分支
- **FR-005**: 成本必须按**档案**折算（tokens × 该档案价目），账目可分解到"角色 × 档案"；同档案多角色可合并展示但来源可追溯
- **FR-006**: 凭证必须按档案声明的**环境变量名**读取；不得依赖全局 `OPENAI_*`（可通过配置显式声明为某档案的变量名以兼容旧环境，但**默认不再隐式使用**）
- **FR-007**: 凭证核查器必须如实报告：每档案声明的变量是否设置 / 设置了但连不通（沿用既有探测分型）、该变量所属档案与用途；**不再产生"无关变量被误判为就绪"**的假阳性
- **FR-008**: LLM 冒烟器与升级清单必须与新机制同步：冒烟按档案/角色选择模型；**清单 ⇄ 代码/配置的变量与档案登记一致性机检**（漂移即红）
- **FR-009**: 成本报告与文档必须如实标注：**网关记账 ≠ 厂商账单**；价目口径备注（如峰时上限/错峰更低/缓存命中未表达）随价目冻结并在报告中可见
- **FR-010**: 单档案配置必须与现状行为**等价**（既有测试全绿）；旧扁平配置（`model` + `model_prices`）必须可平滑迁移（自动映射或明确报错，不得静默失效）
- **FR-011**: 未被任何角色引用的档案：允许但需在启动报告中列出（提示可能笔误）；零价目档案：允许但必须标注"零边际成本"
- **FR-012**: 端点不可用/限流等错误必须沿用既有分型（瞬态可重试 / 永久失败），**禁止**静默回落到其他档案

### 关键实体 *（如果功能涉及数据）*

- **模型档案（ModelProfile）**: 档案标识 / 端点（URL 或环境变量名）/ 凭证环境变量名 / 价目（prompt、completion 每 1k tokens）/ 价目口径备注 / 零价目标记
- **角色映射（RoleRouting）**: 角色（**固定枚举集**）→ 档案标识（单层）；默认档案（单档案可省略、自动认定并标注；多档案必须显式声明）；枚举外的角色名即报错
- **路由决策（RouteDecision）**: 一次调用选中的档案 + 命中原因（角色映射 / 默认回落）+ 快照引用
- **成本条目（CostEntry）**: 角色 / 档案 / tokens / 折算成本 / 价目备注引用——可分解账目的最小单位
- **凭证就绪项（CredentialItem）**: 档案 / 变量名 / 状态（未设置 / 已设置 / 连不通）/ 用途说明
- **档案快照（ProfileSnapshot）**: 随 config_snapshot 冻结的档案集合（含价目与备注；不含密钥，端点仅记 host）

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收：换厂商 = **仅改配置**（加档案 + 改映射），零代码改动（静态断言无厂商/端点字面量）；分角色路由生效且成本可分解到"角色 × 档案"
- **SC-002**: 价目冻结可证伪：修改配置价目后，**历史节点成本与快照口径一致率 100%**（审计复算无漂移）
- **SC-003**: 缺档案/缺价目/缺凭证名/映射指向不存在档案/**出现枚举外角色**：**100% 启动即报错**（无静默回落、无零成本假账、无"judge 拼错降级"）
- **SC-004**: 凭证假阳性归零：环境存在无关 `OPENAI_API_KEY` 时，核查器**不**将其判为任何档案就绪（如实标注来源）
- **SC-005**: 单档案情形与现状等价：既有网关/成本/缓存/重试测试**全绿**（行为无回归）
- **SC-006**: 机检锁通过率 100%（清单 ⇄ 代码/配置的变量与档案名一致），且**故意改坏即红**（可证伪）
- **SC-007**: 单元测试覆盖率 ≥ 85%（core + agents + dreaming + web 口径不降）

## 假设

- 协议仍是 **OpenAI 兼容**（`/chat/completions`）：非兼容协议（如 Anthropic 原生、gRPC 类）不在本特性——那是"新增协议实现"，需另立特性
- 价目仍是**单一费率**模型（prompt/completion 各一个价）；峰谷、缓存命中率、阶梯定价**不在本特性**——以价目备注如实登记局限（要精确表达需两维价目表，属后续）
- "自动按价格择优路由"**不做**：路由是显式声明（可预测、可审计），不做运行时比价决策（YAGNI）
- 厂商账单对账属运营：本特性只保证"记账口径可追溯 + 局限如实标注"
- 迁移：旧扁平配置（`screenplay.model` + `model_prices`）由系统自动映射为单档案，映射结果与规则在报告中可见（不做静默兼容）
- 做梦候选生成、judge 委员会、文案生成等**角色划分以既有调用点为依据**（按代码现有语义归角色，不新造角色概念）
