## 用户场景与测试 *（必填）*

### 用户故事 1 - 树节点成本带角色 × 档案归属落盘（优先级：P1）🎯 MVP

一轮多 Agent 运行结束后，每个树节点的成本记录除既有六字段总量外，还带**按（角色， 档案）分组**的 LLM 腿分解（calls / prompt_tokens / completion_tokens / cost_usd），且分解之和与总量一致。新产生的落盘 JSON 含新键；历史行零回改、读回不报错。

**Why this priority**: 这是缺口的根——数据面不带归属，任何报告层都做不出可回溯分解。只交付本故事即有 MVP：分解数据已落盘可查（SQL/JSON 直查），满足 016 FR-005 的"来源可追溯"。

**Independent Test**: 跑一条固定种子的多 Agent 运行，直查 `tree_nodes.cost` JSON：新行含分解键且 分解Σ == 总量；读回一条历史行（无新键）⇒ 默认还原、不报错、分解视图标「未标定」。

**Acceptance Scenarios**:

1. **Given** 一轮含多角色 LLM 调用的运行，**When** 查看任一新生成节点的成本记录，**Then** 可见按（角色， 档案）分组的 LLM 分解，且各分组之和等于该节点 `llm_calls` / `llm_tokens` 总量（容差仅浮点尾差）。
2. **Given** 一条 022 之前落盘的历史节点行，**When** 系统读回，**Then** 不报错，分解字段按缺省还原，任何展示面标注「未标定」而非 0 或空。
3. **Given** 运行中某节点仅有生成 API 调用（无 LLM 调用），**When** 查看其分解，**Then** LLM 分解为空集，生成 API 成本标「不适用」，总量字段口径不变。

### 用户故事 2 - 报告/查询层按角色 × 档案分组可查看（优先级：P2）

运营/分析者在既有成本查看面（web 查询、样片包成本件或等效报告产物）上，能按"角色 × 档案"维度查看一轮或一周期的成本分解；同档案多角色可合并展示，但来源（角色）可追溯。

**Why this priority**: 数据面带归属后，让既有消费点（现按 stage / (agent, ISO 周) 分组）多一个分解维度即完成 016 US2 场景 4 的完整闭环。独立可交付：US1 已可直查，本故事是可见性增强。

**Independent Test**: 对同一轮运行，在查询面按角色 × 档案分组的结果与网关口径（同档案多角色合并值）逐格一致；与总量对账（分解Σ == 阶段总量）。

**Acceptance Scenarios**:

1. **Given** 一轮运行已落盘带归属的成本，**When** 在查询面按（角色， 档案）分组，**Then** 每格数值与网关 `cost_breakdown()` 同键值一致，且全部分组之和等于该轮 LLM 总量。
2. **Given** 查询范围含历史节点（无归属），**When** 分组展示，**Then** 其成本归入「未标定」组单列，**不得**摊入任何（角色， 档案）分组。

### 边界情况

- **单节点内多角色调用**（同一节点既有 generation 又有 judge 调用）：分解为**多分组并存**（非单归属）；Σ 一致性断言（Σ ≤ 总量、无缓存命中时取等，FR-002）逐节点机检。归属键的**表示形态**（嵌套映射 / 分组列表）留给 plan 裁决，规格只管"可分解、Σ 一致、可追溯"。
- **全缓存命中节点**（节点内 LLM 调用全部命中网关本地缓存）：零计费、不进分解，展示面标「缓存命中（零计费）」——与历史行的「未标定」（原始 JSON 键缺席）严格区分，不得混标。
- **调用未带角色/档案**（理论外路径）：禁止静默归 0——按本仓"缺项 100% 报错"纪律，写入侧缺归属即报错；读出侧仅历史行允许缺省（标「未标定」）。
- **回放旧产物**：002 回放不比 TreeNode 字节；但 dreaming 轨迹 JSON（`dreaming/history/**`）内嵌 `total_cost`，新键只出现在新产物，旧轨迹读回按键取值不受影响——以断言机检。
- **成本回归/无偏性既有门禁**：`ops/cost_regression.py` 等按键取 `generation_api_cost_usd`，新字段不得改变既有键的值与语义。
- **非 LLM 腿归属**：生成 API / 人工 / 墙钟不分解（见 Clarifications Q4），展示面须显式标「不适用」，不得留空白歧义。

## 需求 *（必填）*

### 功能需求

- **FR-001**: 树节点成本记录 MUST 在既有六字段之外，携带 LLM 腿的（角色， 档案）分解：每分组含 calls / prompt_tokens / completion_tokens / cost_usd，与网关 `cost_breakdown()` 口径一致。
- **FR-002**: 每个节点的分解之和 MUST **不超过**该节点 `llm_calls` / `llm_tokens` 总量（**本地缓存命中的调用零计费、不进分解**，与网关 `_breakdown` 同口径，命中解释差值）；无缓存命中时取等（容差仅浮点尾差）；Σ 超和即写入侧报错，禁止带病落盘。
- **FR-003**: 新字段 MUST 为带默认值的扩展：历史落盘行读回不报错、零回改；分解展示面中历史节点 MUST 标「未标定」，禁止插值/回填/归 0 冒充。
- **FR-004**: 写入侧调用缺角色或档案归属 MUST 报错（沿用"缺项 100% 报错"纪律）；读出侧仅历史行允许缺省。
- **FR-005**: 既有六字段的值与语义 MUST 不变；既有消费点（stage 级对账、(agent, ISO 周) 分组、成本回归、无偏性门禁）行为 MUST 不变。
- **FR-006**: 查询/报告层 MUST 支持按（角色， 档案）分组查看分解；同档案多角色可合并展示，但来源角色可追溯；「未标定」成本 MUST 单列、不摊入任何分组。
- **FR-007**: 016 契约 C6 与宪章原则二的成本字段口径 MUST 按扩展更新修订，与实现一致。
- **FR-008**: MUST 有常驻断言机检：五件套逐字节比对不受新字段影响；旧轨迹/旧行读回兼容；分解 Σ 一致。

### 关键实体 *（如果功能涉及数据）*

- **成本记录（CostRecord）**：节点级成本入账。既有六字段（总量口径不变）+ 新增 LLM 分解（按（角色， 档案）分组）。
- **角色（role）**：固定枚举集（generation / judge / dreaming_candidates / copywriting 等，以网关口径为准）。
- **档案（profile_id）**：模型档案标识，价目随配置冻结（016 既有口径）。
- **「未标定」标注**：历史节点无归属时的展示口径，属数据状态而非数值。

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 任取一轮新运行，100% 树节点的 LLM 成本可分解到（角色， 档案），且逐节点分解Σ == 总量（机检断言）。
- **SC-002**: 016 US2 场景 4 闭环：查询面分组结果与网关 `cost_breakdown()` 同键逐格一致；全组之和 == 该轮 LLM 总量。
- **SC-003**: 历史行读回 0 报错、0 回改；含历史节点的查询中「未标定」组单列，占比可如实报出。
- **SC-004**: 五件套逐字节比对、成本回归、无偏性（τ≥0.95，40 用例）、覆盖率（≥85%）、契约两腿等既有门禁全绿，零删除零放宽。
- **SC-005**: 016 契约 C6 文字与实现一致（规格分析 analyze 不再报契约-实现矛盾）。
