**功能分支**: `004-visual-loop`

**创建日期**: 2026-09-18

**状态**: 草稿

**输入**: 用户描述："实现一期里程碑周 9~10 交付物：agents/visual 视觉 Agent 闭环——五个评估器（rule.format_compliance / proxy.aesthetic / proxy.identity_consistency / proxy.flicker / judge.cinematic）+ 线上探索（视频片段生成，昂贵动作仅在线上）+ 树冻结入池回放。验收：回放打分与真实重跑一致性验收。"

**约束来源**: 项目宪章（原则一/二/三/五/六直接相关）；工程细节参照 `docs/CineFlow开发文档.md` §2.3（视觉评估器清单）、§7（movie 形态权重）。依赖功能 001（树/评估器/合成评分）、002（回放/沙箱）、003（LLM 网关/闭环形态/运营表）。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 视觉线上探索闭环（优先级：P1）

视觉工程师触发一轮线上探索：当前策略版本产出片段生成参数组合（分辨率/时长/风格提示词/
镜头数）→ 经视频生成适配器生成候选片段（**昂贵动作，仅允许在此阶段发生**）→ 五个
评估器逐片段打分（硬规则合规为门禁，不合格直接 0 分）→ 按形态配置权重合成得分 →
节点落发现树，生成 API 调用与花费完整入账；单轮生成花费**强制不超过形态配置上限**，
超限拒绝；轮次以 ID 幂等。

**为什么是这个优先级**: 视觉是代理评估信号最强的环节（技术方案 §2.2），是一期内环
验证先锋；五个评估器的确定性实现是回放可信的前提（宪章原则一）。

**独立测试**: 用确定性模拟生成器跑通一轮闭环：参数 → 片段 → 五评估器 → 合成 → 落树
→ 成本对账；不依赖回放与验收报告即可交付"视觉探索数据开始积累"的价值。

**验收场景**:

1. **Given** 一轮探索的生成预算上限 $500, **When** 策略申请的生成调用花费超限, **Then** 拒绝执行并记录原因
2. **Given** 分辨率/帧率不合规的片段, **When** 评估, **Then** rule.format_compliance 得 0 分，合成总分为 0（门禁语义）
3. **Given** 一轮探索完成, **When** 审计成本, **Then** 树内节点成本合计与生成适配器账目 100% 一致，生成调用数与花费逐笔可查
4. **Given** 同一轮次 ID 重复触发, **When** 二次执行, **Then** 不重复调用生成 API、不重复扣费，返回首轮结果
5. **Given** 某一评估器对某片段崩溃, **When** 闭环继续, **Then** 该节点记 FAILED（成本入账），其余片段照常评估

---

### 用户故事 2 - 树冻结入池与回放（优先级：P2）

平台工程师把视觉探索产出的树冻结入模拟器池；回放时五个评估器的冻结版本与权重快照
随树可查；策略 probe 命中真实生成节点，得分即冻结值，全程零生成。

**为什么是这个优先级**: 视觉树的规模与成本远高于宣发，回放池化是"做梦"省算力的
主战场；机制复用 002/003，本故事验证"视频工件 + 五评估器"场景下的适配正确性。

**独立测试**: 对 US1 产出的树执行回放：命中真实节点、UNKNOWN 语义、零生成断言；
聚焦"大工件 + 多评估器"数据的回放适配。

**验收场景**:

1. **Given** 一轮视觉探索产出并冻结的树, **When** 加入模拟器池, **Then** 冻结校验通过，配置快照含五评估器版本组合与权重
2. **Given** 池内含真实生成节点, **When** 策略 probe 命中, **Then** 返回冻结得分与虚拟成本，生成调用恒为 0
3. **Given** 视频工件, **When** 节点落盘, **Then** 工件经内容寻址存储去重，树节点只持哈希引用

---

### 用户故事 3 - 回放打分与真实重跑一致性验收（优先级：P3）

评估工程师对视觉闭环做一致性验收（里程碑验收线）：同一批工件由冻结版本评估器**重算**
得分，与树中落盘值**逐字节一致**（确定性证明）；真实轨迹与回放轨迹的得分序列对接
无偏性门禁（τ ≥ 0.95）；产出一致性验收报告（JSON），结论为通过/拒绝。

**为什么是这个优先级**: 它是本里程碑的验收线（dev doc §9 周 9~10），证明"评估器
确定性 + 回放无偏"在视觉链路上成立——做梦层接入前的最后一道信任门槛。

**独立测试**: 对已知工件集运行验收：重算一致率必须为 100%；故意注入非确定性
（如乱序帧采样变体）必须被判拒绝。

**验收场景**:

1. **Given** 一轮视觉树的全部已评估节点, **When** 用冻结版本评估器重算同工件, **Then** 得分逐字节一致率 100%
2. **Given** 注入非确定性变体（重算结果漂移）, **When** 验收, **Then** 判定拒绝并列出漂移节点
3. **Given** 验收完成, **When** 查看报告, **Then** JSON 含一致率、漂移清单、τ 值与判定结论

---

### 边界情况

- ffmpeg 不可用或片段无法解码：评估器报错而非崩溃，节点记 FAILED（成本入账）
- 生成任务超时/平台失败：重试上限后节点 FAILED，轮次继续其余候选
- judge 委员会某提示词调用失败：网关重试后仍失败则该节点 FAILED，不做部分投票合成
- 单镜头片段（无跨镜头对）：identity_consistency 对单镜头返回满分并注明（无可比对）
- 全黑/全白等退化片段：flicker 与 aesthetic 必须返回合法 [0,1] 值而非崩溃/NaN
- 评估器浮点结果：得分入库前按定点精度归一（避免 0.30000000000000004 类抖动破坏重算一致性）
- 模拟生成器与真实适配器行为漂移：适配器契约测试双实现同跑
- 视频工件体积大：落对象存储内容寻址，节点只持哈希（002 契约安全边界不变）
- 同轮次两个候选的生成参数完全相同：模拟生成器逐字节复现产生同一工件哈希——两节点共享同一工件引用（内容寻址去重，预期行为），各自独立评估与入账

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供视觉线上探索执行器：一轮 = 策略产出生成参数 → 适配器生成片段 → 五评估器打分 → 合成 → 落树，轮次 ID 幂等（复用 003 的两段式落盘形态）
- **FR-002**: 视频生成必须经适配器接口（提交任务/查询状态/取回工件）；模拟实现确定性（参数哈希为种子）；真实实现契约同构、凭证配置注入；视频生成是昂贵动作，只允许在线上探索发生（宪章原则三）
- **FR-003**: 生成 API 调用次数与花费必须逐笔入账（CostRecord.generation_api_*），单轮生成花费 ≤ 形态配置上限（`budget.exploration_per_round_usd`），超限拒绝
- **FR-004**: `rule.format_compliance` 必须校验分辨率/时长/帧率/编码合规（ffmpeg probe），不合规得 0 分（合成门禁）
- **FR-005**: `proxy.aesthetic` 必须以冻结版本对片段打美学分；实现版本（含模型/参数哈希）写入评估器版本号
- **FR-006**: `proxy.identity_consistency` 必须计算人脸/主体嵌入的跨镜头余弦距离并映射 [0,1]
- **FR-007**: `proxy.flicker` 必须检测帧间亮度直方图抖动与频域伪影并映射 [0,1]
- **FR-008**: `judge.cinematic` 必须以 3 个固定提示词成对比较投票（经 LLM 网关），胜率转 [0,1]；提示词版本进评估器版本号；LLM 调用全部过网关计费
- **FR-009**: 五评估器必须全部满足注册规范（`evaluator_id@version`、确定性声明）并按形态权重合成（configs `evaluator_weights.visual`，rule 为 gate）
- **FR-010**: 视觉树必须可冻结入池（复用 002），配置快照含五评估器版本组合与权重
- **FR-011**: 一致性验收必须产出报告：重算逐字节一致率（必须 100%）、漂移节点清单、τ 值与判定结论（JSON）
- **FR-012**: 评估器得分入库前必须定点归一（固定小数精度），保证重算逐字节一致可达成

### 关键实体 *（如果功能涉及数据）*

- **视频片段（VideoClip）**: 一次生成的产出——生成参数、编码规格、工件哈希引用；内容寻址去重
- **生成任务（GenJob）**: 一次生成调用——参数、状态机（提交/进行/完成/失败）、花费；可变运营状态（复用 003 形态）
- **视频生成适配器（VideoGenAdapter）**: 生成平台能力抽象——提交任务、查询状态、取回工件；模拟与真实双实现
- **帧采样序列（FrameSamples）**: 评估器的解码中间产物——帧索引与像素数据的确定性采样（采样规则进评估器版本）
- **一致性报告（ConsistencyReport）**: 验收产出——逐节点重算对照、一致率、漂移清单、τ 值、判定结论

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 五评估器对同工件重算得分逐字节一致率 100%（确定性证明，验收线）
- **SC-002**: 注入非确定性变体的验收 100% 判拒绝
- **SC-003**: 端到端一轮闭环（模拟生成器，3 个候选片段）< 5 分钟完成
- **SC-004**: 生成预算超限申请 100% 被拒
- **SC-005**: 单元测试覆盖率 ≥ 85%（core + agents 口径）
- **SC-006**: 单评估器崩溃不中断闭环：其余物料 100% 照常完成评估与落盘
- **SC-007**: judge 提示词变更必须导致注册键变更（版本冻结可机检）

## 假设

- 真实视频生成 API 不接凭证：适配器接口 + 确定性模拟实现先行（同 003 的诚实边界）
- 美学评分与主体嵌入一期为**确定性启发式实现**（如图像统计/感知哈希嵌入），实现哈希进版本号；真实模型权重接入是配置动作（模型文件哈希写入版本），不改代码路径
- ffmpeg 经 `imageio-ffmpeg` 依赖提供（免系统安装）；一期片段为数秒级短片段
- "真实重跑一致性"一期以"冻结版本评估器对同工件重算"模拟（真实生成平台不可复现的场景由适配器契约约束）
- judge 委员会经 003 的 LLM 网关 Mock 后端运行（确定性）；真实 judge 模型接入是凭证配置动作
- 做梦层自动进化与跨项目回放池化不在本期（沿用宪章已知边界）
