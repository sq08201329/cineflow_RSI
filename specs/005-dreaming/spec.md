# 功能规格说明：做梦层与谱系报表（策略自动进化）

**功能分支**: `005-dreaming`

**创建日期**: 2026-09-19

**状态**: 草稿

**输入**: 用户描述："实现一期里程碑周 11~12 交付物：dreaming/ 做梦层——LLM 生成 M 套候选策略代码（默认 128）、静态检查、沙箱内全模拟器池回放打分、reward = pareto_auc − λ·并行惩罚、train/validation 防过拟合、胜出策略人工 approve 后次日部署 + 谱系报表（policy_version → tree_ids → child_policy_versions 全链路）。验收：连续 5 轮进化 reward 曲线无塌缩。"

**约束来源**: 项目宪章（原则一~六全部相关）；工程细节参照 `docs/CineFlow开发文档.md` §4（策略接口/版本管理）、§5（做梦层）。依赖功能 001（树/评估器）、002（回放/沙箱/静态检查/策略版本）、003（LLM 网关/闭环）、004（视觉闭环）。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 候选生成与沙箱打分（优先级：P1）

做梦工程师发起一轮做梦：系统读取当前最优策略代码、模拟器池中最近 K 轮回放报告与
评估器诊断摘要 → 经候选生成器产出 M 套候选策略代码（默认 128，形态配置）→ 每套先过
静态检查（接口签名、import 白名单、禁网络/文件 IO，违规者**不得进入回放**）→ 合格
候选逐一在沙箱中对**全模拟器池**回放 → 每套产出 reward（pareto_auc − λ·并行惩罚）
与排名。全部 LLM 调用过网关计费；做梦过程自身零生成 API 调用（只回放历史）。

**为什么是这个优先级**: 这是做梦机制的本体——"零成本试错 × 大规模候选"是整套系统
的核心价值主张（算力杠杆的来源）。防过拟合与审批是它的下游。

**独立测试**: 用确定性变异生成器（开发/CI 占位）+ 既有 promo/visual 模拟器池夹具
跑一轮做梦：候选数、静态拦截率、reward 排序正确性逐断言；不依赖审批与报表即可交付
"候选可自动打分排名"的价值。

**验收场景**:

1. **Given** 当前最优策略与池配置 M=128, **When** 发起一轮做梦, **Then** 产出 128 套候选，每套经静态检查后合格者进入回放
2. **Given** 候选中包含违规代码（import socket / 文件 IO / 签名错误）, **When** 静态检查, **Then** 100% 拦截且不回放、不记分
3. **Given** 合格候选完成全池回放, **When** 计算 reward, **Then** 每套的 reward = pareto_auc − λ·并行惩罚，λ 来自形态配置
4. **Given** 一轮做梦全程, **When** 审计, **Then** LLM 调用全部经网关入账，生成 API 调用恒为 0
5. **Given** 候选代码哈希重复, **When** 生成, **Then** 自动去重（同版本号不重复回放）

---

### 用户故事 2 - 防过拟合与人工审批（优先级：P2）

做梦工程师查看候选筛选：模拟器池按时间分 train/validation 树（**最近一棵树永远只做
validation**）；候选若在 train 上第一但 validation 跌出前 20%，判过拟合**丢弃**。
胜出策略生成审批单（与当前最优的 diff、双池 reward 对比），**人工 approve 后**才成为
次日部署的当期策略；审批记录（谁、何时、结论、理由）落盘入谱系；线上探索配置保留
ε=0.1 随机预算。未 approve 的策略不得成为当期策略。

**为什么是这个优先级**: 回放过拟合是方案的两条红线之一（技术方案 §4.3），人工
approve 是一期保留的最后闸门（宪章原则六）。没有它，自动进化不可信。

**独立测试**: 构造已知过拟合候选（train 记忆型）与泛化候选，验证筛选判定；审批单
生成/批准/拒绝三路径，未批准策略部署为零。

**验收场景**:

1. **Given** 池内 ≥2 棵树, **When** 分树, **Then** 最近一棵树只在 validation 集
2. **Given** 候选 train 第一但 validation 跌出前 20%, **When** 筛选, **Then** 判过拟合丢弃并注明
3. **Given** 胜出候选产生, **When** 未获人工 approve, **Then** 当期策略不变，该版本不出现在部署指针
4. **Given** 人工 approve, **When** 审批通过, **Then** 审批记录（审批人/时间/理由）落盘，策略版本建立父子谱系
5. **Given** 线上探索配置, **When** 读取, **Then** ε=0.1 随机预算保留（配置校验）

---

### 用户故事 3 - 谱系报表与进化曲线验收（优先级：P3）

项目负责人查看谱系报表：任一策略版本可全链路追溯（policy_version → 它产出的树 →
它的子策略版本 → …）；进化曲线按轮次展示 reward 序列；里程碑验收：**连续 5 轮进化
reward 曲线无塌缩**（塌缩 = 连续 N 轮 reward 低于基线比例阈值，阈值来自配置），
验收报告 JSON 产出。

**为什么是这个优先级**: 谱系是公司核心资产的可审计证明（宪章原则二），进化曲线是
里程碑验收线；依赖前两故事的产出。

**独立测试**: 用 5 轮确定性做梦演示数据生成谱系报表与曲线：谱系链路完整、塌缩检测
对注入塌缩序列 100% 告警、对正常序列不误报。

**验收场景**:

1. **Given** 多轮做梦产出的策略谱系, **When** 查询任一版本, **Then** 报表给出其父版本、产出的树、全部子版本（JSON 可机读）
2. **Given** 连续 5 轮正常进化数据, **When** 验收, **Then** 曲线产出且无塌缩告警（里程碑验收线）
3. **Given** 注入塌缩的 reward 序列, **When** 验收, **Then** 100% 判塌缩告警并指明起始轮次

---

### 边界情况

- M 套候选全部静态检查失败：本轮做梦判失败并告警（不部署任何候选），诊断落盘
- 候选回放全部 UNKNOWN（新参数档无历史覆盖）：reward 为 0，报告提示扩大线上探索（宪章原则三语义）
- validation 集为空（首轮做梦只有一棵树）：过拟合判定跳过并注明"首轮无 validation"
- 候选回放超时/崩溃：该候选记 0 分并注明，不影响其余候选
- 审批拒绝：轮次正常结束，当期策略不变，拒绝记录落盘
- 连续两轮胜出同一版本（无改进）：如实记录，进化曲线允许平台期但触发观察备注
- 随机 ε 预算产出的树：照常入池入谱系，标记 source=epsilon_random

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供做梦执行器：输入 = 当前最优策略代码 + 最近 K 轮回放报告 + 评估器诊断摘要；输出 = M 套候选的 reward 排名与胜出者
- **FR-002**: 候选生成必须经 CandidateGenerator 接口：LLM 实现走网关计费（提示词含当前策略 + 诊断摘要）；确定性变异实现供开发/CI（明确标注为 LLM 占位）；M 默认 128、K 与 λ 来自形态配置
- **FR-003**: 候选必须 100% 过静态检查（复用 002：import 白名单、禁网络/文件 IO、接口签名校验）才可进入回放；违规候选不回放、不记分
- **FR-004**: 合格候选必须在沙箱中对全模拟器池回放（复用 002 run_policy）；回放失败的候选记 0 分并注明原因
- **FR-005**: reward 必须 = `pareto_auc(best_score_curve, probe_count) − λ · (effective_sequential_rounds / max(probe_count, 1))`，λ 默认 0.5
- **FR-006**: 防过拟合必须执行：池按时间分 train/validation（最近一棵树永远只做 validation）；train 第一但 validation 跌出前 20% 判过拟合丢弃
- **FR-007**: 胜出策略必须经人工 approve 才可成为当期部署策略；审批单含 diff 与双池 reward 对比；审批记录（审批人/时间/结论/理由）落盘；未 approve 不部署
- **FR-008**: 每期策略版本必须落盘 `policies/history/{agent_id}/{version}.py`（BLAKE3 前 12 位）并记录父子谱系（parent_version）
- **FR-009**: 谱系报表必须支持任一策略版本的全链路查询：父版本、产出树清单、子版本集合，JSON 可机读
- **FR-010**: 进化曲线必须逐轮记录 reward 序列；塌缩检测（连续 N 轮低于基线比例阈值，N 与阈值来自配置）触发告警
- **FR-011**: 线上探索必须保留 ε=0.1 随机策略预算（配置校验）；随机版本照常入谱系
- **FR-012**: 做梦过程 LLM 调用全部过网关入账；回放环节生成 API 调用恒为 0（审计断言）

### 关键实体 *（如果功能涉及数据）*

- **做梦轮次（DreamRound）**: 一轮做梦的完整记录——输入摘要、候选清单、筛选过程、胜出者、审批结论
- **候选策略（Candidate）**: 一套生成的策略代码——源码、版本号（BLAKE3 前 12 位）、静态检查结果、回放轨迹、reward 分解
- **候选生成器（CandidateGenerator）**: 候选来源抽象——LLM 实现（网关计费）与确定性变异实现（开发/CI）
- **奖励分解（RewardBreakdown）**: pareto_auc、并行惩罚、λ、最终 reward
- **审批记录（ApprovalRecord）**: 一期人工闸门——胜出版本、审批人、时间、结论、理由；落盘入谱系
- **谱系报表（LineageReport）**: 策略版本的全链路视图——父版本、产出树、子版本、各轮 reward
- **进化曲线（EvolutionCurve）**: 逐轮 reward 序列与塌缩判定

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 一轮做梦（M=128 候选、全池回放）在开发环境 < 30 分钟完成
- **SC-002**: 静态检查对违规候选 100% 拦截（违规候选 0 进入回放）
- **SC-003**: 注入的过拟合候选 100% 被判丢弃；泛化候选不误判
- **SC-004**: 连续 5 轮进化演示：reward 曲线产出且无塌缩告警（里程碑验收线）；注入塌缩序列 100% 告警
- **SC-005**: 未经人工 approve 的策略成为当期部署策略的次数为 0（审批门禁可机检）
- **SC-006**: 谱系报表对任一版本给出完整链路（父/树/子），缺失字段为 0
- **SC-007**: 单元测试覆盖率 ≥ 85%（core + agents + dreaming 口径）

## 假设

- 一期候选生成的真实 LLM 不接凭证：LLMGenerator 契约 + 确定性变异占位实现（MutatorGenerator），真实接入是凭证配置动作（同 003/004 的诚实边界）
- 人工 approve 为本地审批单文件 + CLI 确认（一期无 Web UI，前端二期）
- "次日部署"= 更新当期策略指针配置（`configs/` 或谱系记录中的 current 指针），不涉及线上发布系统
- 5 轮进化验收以变异器 + 模拟器池演示数据运行（真实线上探索的节奏属运营）
- 做梦层一期只服务已闭环的 promo/visual 两个 Agent；开发 Agent 不自动进化（宪章原则六既定）
- 跨项目回放池化与 judge 漂移自动检测不在本期（宪章已知边界）
