## Clarifications

### Session 2026-09-21

- Q: "回放 reward 超过现部署版本"是否要求无偏性验收通过？ → A: **无偏性作为前置**——未通过则证据包整体判"证据不足"（与 007 的对比报告前置一致）；不作为并列第四要件（要件列表不膨胀，语义更准确）
- Q: 人工事后抽检的默认策略？ → A: **渐进抽检**——前 N 次（配置，默认 5）自动部署全量复核，之后按比例（配置，默认 1/5）抽检；样本少时全量复核信息价值最高，与影子模式"先用证据换信心"同思路
- Q: 自动部署的触发时机？ → A: **做梦轮次收口后自动评估**（此刻证据齐备，与技术方案 §4.1"次日部署"内环语义一致）；模式为 manual/shadow 时同一入口只记录不部署——一处入口三种行为

## 用户场景与测试 *（必填）*

### 用户故事 1 - 证据门槛评估与判定（优先级：P1）🎯 MVP

系统对候选策略计算**证据包**并判定是否满足自动接班条件。证据包三要件（宪章）：
① **回放 reward 超过现部署版本**（同池同口径对比，011 池化口径）；② **validation 排名
不跌出前 20%**（005 防过拟合口径，最近树只做 validation）；③ **judge 漂移检测通过**
（012 的 `deploy_evidence_verdict` 对全部相关 judge 版本返回 allow）。**三者缺一即不满足**
——证据缺失（如无 validation 集、无漂移数据）按"不满足"处理（**宁可拦截**）；
**禁止自动进化的 Agent**（009 的 `no_auto_evolve_agents`：screenplay/dev）一律判定不满足。
每次判定产出**证据快照**（三要件取值 + 判定 + 理由），不可改写。

**为什么是这个优先级**: 门槛判定是 F9 的全部风险所在——放行错了就是让漂移或过拟合的
策略自动接班；"缺证据即拦截"与"禁止名单优先"是这套机制的安全底线。

**独立测试**: 构造候选 × 证据组合矩阵（全满足 / 各单要件不满足 / 证据缺失 / 禁止名单）：
判定与理由逐断言；不接影子模式与抽检即可交付"门槛可机检"的价值。

**验收场景**:

1. **Given** 候选策略（回放 reward 高于现部署 + validation 前 20% + 漂移全通过）, **When** 判定, **Then** 满足（可自动接班），证据快照含三要件取值
2. **Given** 回放 reward 低于或等于现部署, **When** 判定, **Then** 不满足（理由注明该要件）
3. **Given** validation 排名跌出前 20%, **When** 判定, **Then** 不满足（005 口径）
4. **Given** 任一相关 judge 的漂移状态为 suspect/confirmed_drift, **When** 判定, **Then** 不满足（F7 拒绝语义）
5. **Given** 证据缺失（无 validation 集 / 无漂移数据 / 无池化回放结果）**或前置无偏性未通过**, **When** 判定, **Then** 不满足并注明"证据不足"（宁可拦截，不推测）
6. **Given** 候选属于禁止自动进化的 Agent（screenplay/dev）, **When** 判定, **Then** 不满足（宪章原则六，与 009 一致）

### 用户故事 2 - 影子模式（优先级：P2）

部署模式默认 `manual`（全人工 approve，现状不变）。开启 `shadow`：**门槛判定照跑、
部署指针不切换**——系统记录"若自动模式已开启，会放行哪些候选、拦截哪些候选及其理由"，
产出**对照报告**（与同期人工决策的差异：系统会放行但人工拒绝的、人工放行但系统会拦截的）；
**影子期硬门禁**：累计运行时长 ≥ 配置下限（默认 2 周，立项书要求）且覆盖候选数 ≥ 配置
下限，方可申请开启 `auto`；**影子期未满即请求开启 auto → 拒绝**（机检）。对照报告与
影子期计时留痕不可改写。

**为什么是这个优先级**: 影子模式是宪章写死的上线前置——它把"门槛是否标定得当"从
上线后的赌注变成上线前的证据；对照报告中"系统会放行但人工拒绝"的案例正是门槛太松的
直接信号。

**独立测试**: 影子期时长/候选数不足时开启 auto → 拒绝；影子运行 N 轮后对照报告字段
齐全（放行/拦截/差异分类）；影子期不切指针（机检）。

**验收场景**:

1. **Given** 部署模式 = manual（默认）, **When** 做梦产出胜出候选, **Then** 仍走人工 approve（现状不变，指针不自动切换）
2. **Given** 部署模式 = shadow, **When** 候选判定通过, **Then** **不切换指针**，记录"影子放行"事件 + 对照数据
3. **Given** 影子期时长 < 下限（或候选数 < 下限）, **When** 请求开启 auto, **Then** 拒绝并注明缺口（时长/候选数）
4. **Given** 影子期满足下限, **When** 生成对照报告, **Then** 报告含：影子放行数/拦截数/各拦截理由分布/**与人工决策的差异分类**（系统放行人拒、人放行系统拦、一致）
5. **Given** 影子期运行, **When** 审计, **Then** 部署指针变更次数为 0（影子不部署）

### 用户故事 3 - 自动部署、人工事后抽检与回滚（优先级：P3）

部署模式 = `auto`（**仅当影子期满足下限**）：候选满足门槛 → **自动更新部署指针** +
证据快照与部署事件留痕（谱系 `source=auto`）+ 通知；**人工事后抽检**（配置抽检比例与
周期：**前 N 次全量复核，之后按比例**）——抽检由人复核已自动部署的策略，**抽检否决 → 立即回滚到
前一部署版本 + 恢复全人工审批模式（模式回 `manual`）+ 标记"门槛需重新标定"**（在重新
标定并经影子验证前不得再开启 auto）；抽检通过 → 记录通过留痕。部署后出现漂移
（F7 状态转 suspect/confirmed_drift）→ 触发**回滚评估**（不自动回滚，按 012 的处置
留痕流程；回滚评估结论如实记录）。

**为什么是这个优先级**: 这是 F9 的"自动化"正题，但它排在门槛与影子之后——没有前两者，
自动部署就是无人看守的放行闸门；否决回滚是宪章写死的安全阀。

**独立测试**: 自动部署执行（指针更新 + 留痕 + source=auto）；抽检触发比例；否决回滚
三件事全生效（回滚 + 模式回 manual + 待重标定标记）；抽检通过留痕；部署后漂移触发
回滚评估记录。

**验收场景**:

1. **Given** 模式 = auto 且候选满足门槛, **When** 执行, **Then** 部署指针更新 + 证据快照留痕 + 谱系 `source=auto`（历史节点零修改）
2. **Given** 自动部署发生（前 N 次之内 / 之后）, **When** 抽检任务产生, **Then** 前 N 次全部产生复核任务、之后按配置比例产生（渐进策略生效，机检）
3. **Given** 抽检否决, **When** 处理, **Then** ①指针**立即回滚**到前一版本 ②模式回 `manual` ③标记"门槛需重新标定"——三件事同时生效（机检）
4. **Given** 抽检通过, **When** 处理, **Then** 通过留痕（人/时间/结论）；模式保持 auto
5. **Given** 自动部署后某 judge 转 suspect, **When** 检查, **Then** 产生回滚评估记录（不自动回滚，按 012 处置流程）
6. **Given** 模式回 manual 后, **When** 请求再次开启 auto, **Then** 要求重新标定 + 重跑影子期（拒绝直接开启）

---

### 边界情况

- 同一周期多个候选满足门槛：按 reward 择优部署其一，其余如实记录（不批量连推）
- 回滚目标版本工件缺失（历史策略文件被清理）：回滚失败必须显式报错并**保持人工审批**
  （绝不停留在"不确定状态"）
- 影子期跨越部署模式变更（manual → shadow → 反复）：影子计时按模式区间累计，切换留痕
- 证据包中某要件为"不适用"（如某 Agent 无 judge 层——006 sound/003 promo）：该要件视为
  不适用并在快照注明；但**不得**因此放宽其他要件（配置可声明"无 judge 的 Agent 需人工
  approve"——默认要求人工）
- 门槛重标定期间（标记存在）：auto 一律拒绝，即使影子期已满
- 抽检长期未执行（无人工响应）：如实告警（不自动视为通过）
- 部署指针被外部手工修改（绕过系统）：下次自动部署前检测指针与留痕不一致 → 拒绝并告警
  （防绕过）

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须计算候选策略的**证据包**：**前置 = 无偏性验收通过**（未通过则整体判"证据不足"）；三要件：①回放 reward 对比（vs 现部署版本，同池口径）②validation 排名（005 口径，最近树只做 validation）③judge 漂移 verdict（F7 `deploy_evidence_verdict` 对全部相关 judge 版本）；输出含各要件取值、来源引用与判定结论
- **FR-002**: 门槛判定必须"三者同时满足"（宪章原则六）：任一不满足 → 不满足；**前置（无偏性验收）未通过或证据缺失按不满足处理**（注明"证据不足"，宁可拦截）；**禁止自动进化的 Agent（009 名单）一律不满足**
- **FR-003**: 每次判定必须产出**证据快照**（不可改写）：候选版本、三要件取值与来源、判定与理由、时间
- **FR-004**: 部署模式必须为显式状态机：`manual`（默认，现状不变）→ `shadow` → `auto`；模式变更留痕（人/时间/理由）
- **FR-005**: 影子模式必须：门槛判定照跑但**不切换部署指针**；记录影子放行/拦截事件；产出**对照报告**（放行数/拦截数/理由分布/与人工决策差异分类）
- **FR-006**: 影子期硬门禁：累计时长 ≥ 配置下限（默认 2 周）且覆盖候选数 ≥ 配置下限，方可开启 auto；**未满即请求开启 auto → 拒绝并注明缺口**（机检门禁）
- **FR-007**: 自动部署必须：**触发 = 做梦轮次收口后自动评估**（模式为 manual/shadow 时同一入口只记录不部署——一处入口三种行为）；满足门槛 → 更新部署指针 + 证据快照与部署事件留痕（谱系 `source=auto`）+ 历史节点零修改；同周期多候选按 reward 择一
- **FR-008**: 人工事后抽检必须**渐进**：前 N 次（配置，默认 5）自动部署**全量复核**，之后按比例/周期抽检（配置，默认 1/5）；抽检通过 → 留痕；**抽检否决 → 三件事同时生效**：①指针立即回滚到前一版本 ②模式回 `manual` ③标记"门槛需重新标定"
- **FR-009**: 重标定期间（标记存在）：auto 一律拒绝（即使影子期已满）；重新开启 auto 必须重新标定 + 重跑影子期
- **FR-010**: 部署后漂移（F7 状态转 suspect/confirmed_drift）必须产生**回滚评估记录**（不自动回滚，按 012 处置流程留痕）
- **FR-011**: 每次自动部署与回滚必须为谱系事件（005 谱系口径），留痕不可改写；指针与留痕不一致时（外部绕过）下次自动部署前必须拒绝并告警
- **FR-012**: 门槛阈值、影子期下限（时长与候选数）、**抽检策略（前 N 次全量 + 之后的抽检比例/周期）**、模式状态必须全部配置化；**误入率**必须可度量（影子期与生产期各自的分子/分母定义入配置与报表）

### 关键实体 *（如果功能涉及数据）*

- **证据包（EvidenceBundle）**: 候选版本的证据集合——reward 对比/validation 排名/漂移 verdict/各要件来源引用与取值
- **证据快照（EvidenceSnapshot）**: 一次门槛判定的不可改写记录——判定（可自动 / 拦截）、理由、时间
- **门槛判定（GateVerdict）**: 三要件同时满足与否的结论 + 逐要件理由（含"证据不足"/"禁止名单"）
- **部署模式状态（DeployModeState）**: `manual`/`shadow`/`auto` 当前态 + 变更历史（人/时间/理由）+ 影子期计时累积 + 重标定标记
- **影子事件（ShadowEvent）**: 影子期"会放行/会拦截"的记录 + 对照分类（与人工决策差异）
- **对照报告（ShadowReport）**: 影子期汇总——放行/拦截数、理由分布、差异分类、误入率分子分母
- **部署事件（AutoDeployEvent）**: 自动部署留痕——候选版本、证据快照引用、前一版本、时间、谱系 source=auto
- **抽检记录（SpotCheckRecord）**: 人工抽检——覆盖的部署事件、结论（通过/否决）、人/时间/理由
- **回滚事件（RollbackEvent）**: 回滚留痕——从版本/回版本、触发源（抽检否决/漂移评估/手工）、时间、模式变更

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书周 10~11）：门槛判定可机检（组合矩阵全覆盖）+ **不满足门槛的自动部署次数为 0** + 影子期未满开启 auto 100% 被拒
- **SC-002**: 证据缺失场景 100% 判"不满足"（宁可拦截，无推测放行）；禁止名单 Agent 100% 不满足
- **SC-003**: 影子模式部署指针变更次数为 0（机检）；影子对照报告字段齐全率 100%
- **SC-004**: 抽检否决后三件事同时生效率 100%（回滚 + 模式回 manual + 重标定标记）
- **SC-005**: 自动部署留痕完整率 100%（证据快照 + 谱系 source=auto + 历史节点零修改）
- **SC-006**: 指针与留痕不一致（外部绕过）→ 100% 拒绝并告警
- **SC-007**: 误入率可度量（分子/分母定义明确且可从留痕重算）；单元测试覆盖率 ≥ 85%（core + agents + dreaming + web 口径不降）

## 假设

- 影子模式 ≥2 周是立项书与宪章要求：**本特性交付机制与门禁**，真实 2 周影子期的运行
  属运营（本特性提供计时、事件记录与对照报告，供 2 周后的人工决策使用）
- 自动部署的"部署"= 更新部署指针（005 语义）；真实发布系统对接不在本特性
- 门槛三要件中"judge 漂移检测通过"依赖 012 已交付的 `deploy_evidence_verdict`；
  **无 judge 层的 Agent**（promo/sound）默认仍要求人工 approve（配置可声明例外，
  但默认保守）
- 抽检由人工执行（CLI 通道；Web 看板只读，不开放抽检操作——宪章只读条款）
- 回滚 = 指针切回前一版本（策略文件与谱系已在 005 机制内，本特性不重建文件）
- 影子期与生产期的**误入率对比**是门槛标定的主要依据；本特性只保证度量口径存在且
  可重算，标定结论由人决策
- 本特性不改变做梦层候选生成与 005 的防过拟合筛选（它们是门槛的输入）
