### 用户故事 1 - 新形态以"配置 + 评估器插件"接入并离线跑通（优先级：P1）🎯 MVP

评估工程师接入一个新形态（广告或漫剧）：写一份 `configs/<new-form>.yaml`（形态声明 + 评估器组合与权重 + 全部已定口径），加一个**业务无关**的评估器插件（实现 + 注册声明）；系统按**配置声明的插件清单**装配评估器，同一套链代码在该配置上从配置读到可跑通的产出（评估 → 合成分数 → 留痕），全程离线。

**为什么是这个优先级**: G5 行的内容原文就是"广告/漫剧形态以**配置化评估器插件**接入（零代码改动验证）"，而"新形态接入 = 仅新增配置 + 评估器插件"是它的第一条关键验收。它排在 P1 是因为**今天这条路径根本不成立**（见"边界情况"第 1 条：评估器装配是硬编码在各 Agent 的 `build_*_evaluators`，配置里没有任何实现引用）——机制不存在，后面两条用户故事（静态断言、改动审计）都无从落地。

**独立测试**: 在临时目录放一份新形态配置 + 一个插件文件，离线完整测试：装配按配置里的 **`evaluators.plugins.<plugin_id>.{impl, version, params}`** 声明实例化并注册插件（`impl` = `module:attr`，由唯一装配点解析；**缺声明即装配期报错**）；评估器集合与 `evaluator_weights.<agent>` 键集一一对应（缺项/多项即拒绝装配）；插件参数全部来自 `params` 注入（缺项即报错、不取码内默认）；从配置跑到产出退出码 0；真实花费 0、外部网络调用 0、凭证读取 0。

**验收场景**:

1. **Given** 一份新形态配置（含 `form:` 与 `evaluators.plugins.<plugin_id>.{impl, version, params}` 声明）与一个业务无关的评估器插件, **When** 装配, **Then** 评估器集合**完全由配置声明的插件清单决定**（装配逻辑里零硬编码评估器、零形态字面量；插件目录本身不决定可用性），装配得到集合与 `evaluator_weights.<agent>` 键集**一一对应**（缺项/多项即拒绝装配）
2. **Given** 一个新形态配置, **When** 跑离线端到端, **Then** 从配置到产出（评估 → `eval_breakdown` 带 `evaluator_id@version` → 合成分数 → 留痕）**退出码 0**，且**零真实花费、零外部网络、零凭证**
3. **Given** 同一插件被两个形态配置声明, **When** 两形态各自装配, **Then** 两形态**共用同一份插件代码**（形态差异**只在配置值**，插件内不含任何形态判断），且同 id 同 version 在**同一注册中心**内重复注册即被拒（`core/evaluators/registry.py:35-38`）
4. **Given** 一个需要新参数的插件, **When** 声明其参数, **Then** 参数经**配置注入**（通用参数通道），**不得**为此改动任何既有 Agent 的配置类或装配函数
5. **Given** 插件声明缺失必需元数据（`evaluator_id`/`version`/`kind`/`deterministic`/`cost_per_call`）, **When** 装配, **Then** 显式报错拒绝（沿用 `core/evaluators/base.py:42` 的 `EvaluatorSpec` 校验与 `core/evaluators/registry.py:18` 的注册校验），**不取码内默认**

### 用户故事 2 - 零形态分支静态断言补面（优先级：P2）

质量工程师把"零形态分支"从**两形态硬编码**升级为**由配置派生的全覆盖断言**：形态名清单**一律由 `configs/` 目录里全部 `configs/*.yaml` 的 `form:` 取值自动派生**（新增一份形态配置即**自动**纳入禁令面，**禁止**任何人工常量清单）；字面量与判断分支**两层**都覆盖 `core/` + `agents/` **全覆盖**（含此前被显式排除的 `agents/pilot`，而它正是装配点）；今天散落的三份形态名副本**收敛为单一实现（副本数 ⇒ 1）**；扫描面锚点以**符号名**为准；既有断言的语义**只增不减**。

**为什么是这个优先级**: G5 的第二条关键验收就是"**静态断言无形态分支**"，且立项书 §7 把"多形态并行导致 core 被污染"列为**中**风险、缓解手段正是"静态断言（零形态分支）+ 形态插件契约测试（G5）"（`docs/三期立项书.md:276`）。它必须在 P1 的路径打开**之前**就把守卫补齐——否则新形态一旦接入，字面量与分支就有窗口悄悄进来。今天这道守卫有**三处真实缺口**（见"边界情况"第 3、4 条）：扫描面排除 `agents/pilot`、形态名清单写死为人工常量 `("shortdrama", '"movie"', "'movie'")`（`tests/unit/test_form_switch.py:413`）且副本三份、锚点只按行号（020 登记的行号**已漂移**）⇒ 新形态名**不会**被扫到。

**独立测试**: 故意注入取证——把新形态的字面量（如 `"ad"`）写进 `agents/pilot/backends.py`、把一个 `if form == ...` 写进任一 `core/`/`agents/` 模块，两条断言**必须各自变红**（注入即被捉率 100%，证明断言有牙齿不是空跑）；同时断言三份副本已**委派**到单一实现且任一处断言的语义**未被删除/削弱**。

**验收场景**:

### 用户故事 3 - 接入改动清单与五处登记点完备性（优先级：P3）

负责人把"零代码改动"从口号变成一份**可审计的清单**：一次新形态接入之后，跑一次机检即得到"本次一共改了哪些文件"的完整清单，并逐条判定是否越界（配置 / 插件 / 测试 / 文档 ⇒ 放行；改动 `core/`/`agents/`/`ops/`/`web/` 既有模块 ⇒ 越界）；同时机检该形态在**既有五处登记点**逐一登记完备（缺项即报错），且未新造第六处。

**为什么是这个优先级**: G5 验收是"**仅**新增配置 + 评估器插件"——"仅"这个字只有靠改动清单才可证伪；五处登记点是 020 建立、本特性**复用不新造**的资产，它把"漏登记"从"静默逃逸"变成"报错"。它排在最后是因为它**审计**前两条故事的产出，必须在路径打通、守卫补齐之后才有对象可审。

**独立测试**: 用一次**真实的新形态接入**（P1 的配置 + 插件）跑清单机检：清单覆盖 git 实际改动集（无遗漏、无自报漏项、一致率 100%）；对"既有模块被修改"的路径逐条报出并判越界（用一份**故意越界**的改动取证，判越界率 100%）；五处登记点逐处机检该形态已登记（抽掉任一处即报错）；无第六处登记点。

**验收场景**:

1. **Given** 一次新形态接入的改动, **When** 跑接入改动清单机检（基线 = 形态插件机制落地后、新形态接入前的提交）, **Then** 输出**完整**的改动/新增/删除文件清单并**逐条**给出分类与越界判定；**既有模块被修改的文件数恒为 0**；越界即非 0 退出码并逐条点名路径（"改了哪些文件、是否越界"必须可回答）
2. **Given** 有人在接入时顺手改了 `core/` 或 `agents/` 的既有模块, **When** 跑清单机检, **Then** **判越界率 100%**、退出码非 0、逐条报出路径与类别（不得静默放行、不得只报总数）
3. **Given** 一个新形态配置, **When** 跑五处登记点完备性机检, **Then** 五处**逐一**判定已登记（`tests/unit/test_form_switch.py` 顶层差异集、`tests/unit/test_config_integrity.py` 的 `CONFIG_CLASSES`/`REQUIRED_PATHS`、`tests/contract/test_pilot_contracts.py` 段差异集、`agents/pilot/pilot.py` 的 `config_completeness` 预检、`tests/conftest.py` 夹具）；缺任一处即报错并点名是哪一处；同时机检**登记完备**口径——每份 `configs/*.yaml` 的 `form:` 取值**两两唯一**、配置集合 **⊆** 已登记形态**派生集**、配置数 **≥2**（**下界保留**）——即 `tests/unit/test_form_switch.py:438-441` 的"恰好两份"断言按裁决 5 升级为该口径，**禁止**简单删除该断言
4. **Given** 新形态配置, **When** 跑配置完整性预检（`agents/pilot/pilot.py:377` 的 `config_completeness`，按**配置路径**通用、对新形态无需改代码即生效）, **Then** 020 的全部新增口径逐项被读到并校验（cadence / 窗口口径与生效日 / 渠道命名空间 / 归属日生效日 / 迁移口径 / 运行窗口下限与断档容差），**缺项即拒绝启动**、**不取码内默认**；"不适用"必须显式声明（留空即报错）
5. **Given** 本次特性自身对 `core/`/`agents/` 的机制改动（插件清单读取与通用装配）, **When** 跑清单机检, **Then** 该改动**不**被算作"接入改动"（清单基线取"机制落地后、接入前"）——**两件事不得混同**，否则判据自相矛盾

- **FR-001**: 系统**必须**提供**配置驱动的评估器插件装配面**，且**配置声明是插件的唯一注册面**：新增配置键 **`evaluators.plugins.<plugin_id>.{impl, version, params}`**（裁决 1）——`impl` 为 **`module:attr`** 形式的实现引用字符串，由**唯一装配点**用 `importlib` 解析；`version` **必须显式声明**（沿用 `id@version` 冻结口径，`core/evaluators/base.py:42`）；`params` 为**形态无关**参数（**通用参数通道**）；**缺声明即装配期报错、不取码内默认**，且**配置声明集 = 可用插件的全集**（插件目录决定不了可用性、配置声明才决定）。装配**必须**按该清单实例化并注册（`registry.register`，`core/evaluators/registry.py:59`），**不得**再以硬编码方式在既有装配函数里逐个 `new` 评估器（现状：`agents/visual/loop.py:207`、`agents/dev/evaluators/__init__.py:31`、`agents/screenplay/evaluators/__init__.py:40`、`agents/storyboard/evaluators/__init__.py:26`、`agents/sound/evaluators/__init__.py:24`、`agents/editing/evaluators/__init__.py:27`）。插件参数只经 `params` 注入，使"新增评估器所需的**新参数**"**零改动**既有 `agents/<agent>/config.py`。装配得到的评估器集合**必须**与 `evaluator_weights.<agent>` 键集**一一对应**（缺项/多项即拒绝装配，沿用 `agents/dev/evaluators/__init__.py:52-58` 的既有口径）。该键的性质**必须**是原则五要求的"**新增配置项**"（`.specify/memory/constitution.md:121`），**不得**是分支代码

- **FR-003**: **"零代码改动"的判据必须精确到可机检**：一次新形态接入所**改动/新增**的文件**只能**是——① 新增 `configs/<new-form>.yaml`；② **评估器插件**（新增评估器实现 + 其在配置里的注册声明，需满足 FR-002）；③ 测试与文档。**禁止**改动 `core/`、`agents/`、`ops/`、`web/` 下的**既有模块逻辑**（含删除或放宽既有断言）。判据**必须**按**类别**而非按路径前缀判定（裁决 2）：**业务无关的通用评估器落 `core/evaluators/plugins/`（新目录）**；**仅当插件语义确实与某 Agent 绑定时**才落 `agents/<agent>/evaluators/`，**且同样必须经 `impl` 引用在配置里声明**（**不得**靠"放在这个目录里就自动生效"）；两类新增文件均属"插件"类别；对**既有文件**的任何修改/删除一律判**越界**；**新形态接入不得改动任何既有 Agent 的装配函数**

### 关键实体 *（如果功能涉及数据）*

- **形态插件声明（FormPluginDeclaration，新增）**: 配置键 `evaluators.plugins.<plugin_id>` 的一项——`impl`（`module:attr` 实现引用，由唯一装配点用 `importlib` 解析）+ `version`（**必须显式**，沿用 `id@version` 冻结口径）+ `params`（**形态无关**参数映射）+ 由 `impl` 目标携带的 `evaluator_id`/`kind`/`deterministic`/`cost_per_call`；同 id 同 version 全局唯一（原则一）；**配置声明集 = 可用插件全集**；缺项即装配期报错、不取码内默认
- **插件装配清单（PluginManifest，新增）**: 形态 → 声明的插件清单 → **实际装配**得到的评估器集合（含 `id@version`）与 `evaluator_weights.<agent>` 键集的一一对应关系；装配漂移（缺项/多项）即拒绝
- **评估器插件（EvaluatorPlugin，新增）**: 一个**业务无关**的评估器实现——满足 `Evaluator` + `EvaluatorSpec`（`core/evaluators/base.py:91`/`:42`）、零形态 import、零形态字面量/分支、参数全由配置注入；落地 `core/evaluators/plugins/`（通用）或 `agents/<agent>/evaluators/`（语义与某 Agent 绑定时），但**两类都必须经 `impl` 声明才生效**；同一插件可被多个形态配置共用
- **接入改动清单（OnboardingChangeManifest，新增）**: 基线 ref + 改动/新增/删除的文件集 + 逐条类别（配置/插件/测试/文档/越界）+ 越界判定 + 退出码；与 git 实际改动集一致；append-only
- **零形态分支守卫（FormBranchGuard，扩展）**: **单一实现**（三份副本收敛后副本数 = 1）——扫描面（`core/` + `agents/` 全覆盖，**含 `agents/pilot`**，字面量与判断分支**两层**）+ 形态名清单（**由 `configs/` 目录里全部 `configs/*.yaml` 的 `form:` 取值自动派生**，**零人工常量清单**）+ 锚点（**符号名优先**）+ 例外口径（**只允许三条**：配置 `文件路径` / 测试夹具 / docstring 中性描述）；各既有断言**委派**到本实现、语义保留原位
- **登记点完备性（RegistrationCompleteness，新增）**: 新形态 × 五处既有登记点 → 逐处登记状态与缺项点名；**不新造第六处**
- **形态（Form，复用并扩展）**: `configs/*.yaml` 的 `form:` 值 + 配置路径 + 020 全部新增口径的声明（cadence / 窗口口径与生效日 / 渠道命名空间 / 归属日生效日 / 迁移口径 / 运行窗口下限与断档容差）+ **未标定标注**
- **未标定标注（UncalibratedNotice，复用 019/020 口径）**: 业务侧输入未定期间对"受众 / 指标口径 / 素材规格 / 预算档"的如实标注（在配置与产物中机读可见）；**未标定期间禁止**输出"该形态已标定/已投产"一类结论

## 假设

- **插件机制今天不存在，本特性必须先补机制**（见"边界情况"第 1、2 条）：评估器装配硬编码在六个 `build_*_evaluators` 装配点，配置里零实现引用、零参数通用通道 ⇒ "仅新增配置 + 插件"**今天不成立**；补齐机制是**本特性的核心交付**，其改动面（`core/` 与各 Agent 装配面）与"新形态接入零代码改动"是两件事（FR-013）
- **广告/漫剧形态的真实业务定义属业务侧输入**（受众、指标口径、素材规格、评估器组合的业务正确性）；未给定期间按**最小可行形态**接入并如实标注"未标定"，**不发明**任何业务数字与口径（FR-011、开放问题 1）
- **`form` 是不受枚举约束的自由字符串**（`core/orchestration/models.py:197`、`ops/pilot.py:250`），因此"新增一份配置即新增一个形态"在编排层**无需改代码**；本特性的改动集中在**装配面、参数面与静态守卫面**
- **注册中心与合成/权重读取面已通用**：`core/evaluators/registry.py`（键 = `id@version`）、`core/evaluators/base.py:42` 的 `EvaluatorSpec`、`core/evaluators/weights.py:18` 与 `core/evaluators/composite.py:37` 均为配置驱动，插件接入**无需改核心**（FR-012）
- **插件声明形状与落地目录已裁决、plan 不再重开**（裁决 1/2）：配置键 **`evaluators.plugins.<plugin_id>.{impl, version, params}`**，`impl` = `module:attr`（由**唯一装配点**用 `importlib` 解析）；通用件落 `core/evaluators/plugins/`，仅当语义与某 Agent 绑定时落 `agents/<agent>/evaluators/`，**两类都必须经 `impl` 声明才生效**（"插件目录决定不了可用性、配置声明才决定"）
