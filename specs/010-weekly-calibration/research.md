# 阶段 0 调研：外环周校准（010-weekly-calibration）

> 每个决策 = 分歧点 → 备选 → 结论 → 依据。规格：[spec.md](spec.md)。

## 决策 1：锚点评分（AnchorScore）的存储介质

- **分歧**：人评/平台真值锚点存 DB 还是文件？
- **备选**：(a) 新 DB 表 + INSERT-only 触发器；(b) 文件化 JSON（同 005 谱系惯例）
- **结论**：**(a) 新 DB 表 `calibration_anchors` + 双方言 INSERT-only 触发器**（迁移 0004）
- **依据**：FR-003 要求"更新/删除必须被**存储层**拒绝"——文件体系只能应用层自律，
  给不了这个保证；001 的双方言触发器模式已验证（SQLite 单测也能证明不可变），直接复用。
  台账/轮次/提案等**派生产物**仍文件化（决策 2），DB 只存不可变的原始锚点。

## 决策 2：派生产物的存储介质

- **分歧**：校准轮次、台账、信度报告、权重提案存哪里？
- **备选**：(a) DB 新表；(b) 文件化落盘
- **结论**：**(b) 文件化**——`calibration/rounds/{agent_id}/{round_id}.json`（轮次）、
  `calibration/ledger/{agent_id}/{evaluator_id}.jsonl`（append-only 台账）、
  `calibration/reports/{period}.json`（信度报告）、`calibration/proposals/{proposal_id}.json`（提案）
- **依据**：005 决策 3 的同一论据——与代码同 lifecycle、随 git 版本化、无迁移与双写漂移；
  这些都是可重算的派生数据（源 = 锚点表 + 树），文件化零风险。

## 决策 3：偏差与相关性的数学口径

- **分歧**：人评 vs 自动得分的偏差/相关怎么算？
- **备选**：(a) 均值偏移 + Pearson r；(b) Spearman；(c) 仅分类一致率
- **结论**：**(a) 均值偏移 + Pearson r**（连续分量）；**judge 类用 Kendall τ 序一致**
  （锚点排名 vs judge 胜率排名）
- **依据**：均值偏移回答"系统性偏高/偏低多少"（权重再拟合的输入），Pearson r 回答
  "排序与量级是否一致"（信度 ≥0.6 口径）；judge 产出是胜率不是分数，规格验收场景 5
  禁止当分数相减——序一致用 Kendall τ，**复用 002 `core/replay/unbiasedness.py` 的
  τ-b 实现**，零新造轮子。最小样本量（默认 3）以下不产偏差值（FR-004）。

## 决策 4：防自循环配对的实现

- **分歧**：如何知道锚点来源对应哪个评估器分量？
- **备选**：(a) 配置显式声明映射；(b) 按 evaluator_id 命名约定推断
- **结论**：**(a) 配置显式声明**——configs `calibration.self_pairing_exclusions`：
  `{"platform_truth": ["human.platform_metrics"]}`；人评盲评锚点无排除项（与全量配对）
- **依据**：命名约定脆弱（改 id 即静默破规则）；显式配置符合原则五"配置即形态"，
  且配对剔除是正确性规则，必须可被契约测试直接断言。

## 决策 5：权重再拟合算法（规格留 plan 定）

- **分歧**：候选新权重怎么从偏差数据拟合？
- **备选**：(a) 无约束最小二乘；(b) 约束岭回归（非负、和为一、向现权重收缩）；(c) 引入 scipy
- **结论**：**(b) 约束岭回归**，numpy 实现，**零新增依赖**
  （`min Σ(anchor_i − Σ_e w_e·s_ei)² + λ_ridge·‖w − w_current‖²`，s.t. w_e ≥ 0, Σw = 1，
  投影梯度 + 单纯形投影）
- **依据**：每周锚点样本仅 3~5 个（技术方案 §2.2 锚点预算），无约束最小二乘必然过拟合；
  收缩项让小样本下的候选权重天然保守（样本越少越贴近现权重）——与宪章"诚实边界"同向。
  λ_ridge 入配置。scipy 收益不抵依赖成本（YAGNI）。

## 决策 6：提案生效与 configs 权重快照的改写方式

- **分歧**：确认提案后怎么更新 `configs/movie.yaml` 的 evaluator_weights？
- **备选**：(a) yaml 全量重写（丢注释，005 approve 的已知缺陷）；(b) 定点文本改写
- **结论**：**(b) 定点改写**——按 `evaluator_weights.{agent_id}` 段做行级替换，注释与其他段原样保留
- **依据**：一期遗留 #3 已记录全量重写丢注释的问题，本特性与 WS3 收口共用同一
  定点改写实现（一次做对，两处受益）；生效失败必须整体回滚（注册新版本与配置改写
  构成一个逻辑事务，先注册、改配置、失败则注销指针——新版本对象本身不可删，
  回滚 = 部署指针不切换 + 提案标记失败）。

## 决策 7：生效后评估器版本语义

- **分歧**：权重再拟合生效产生的新版本怎么编号？
- **备选**：(a) 语义化自增；(b) 权重哈希入版本元信息
- **结论**：**(b)**——composite 评估器新版本 `version = "{base}+w{weights BLAKE3 前 12 位}"`，
  `calibration` 字段填入台账最新快照（四要素）
- **依据**：沿用一期"版本号即元信息"惯例（004 judge 提示词/锚点哈希进版本）；
  权重是行为变更，必须升版本（宪章原则一），哈希入版本号使"同权重同版本"天然成立。

## 决策 8：盲评清单的零泄露保证

- **分歧**：如何证明清单不含自动得分？
- **备选**：(a) 构造时小心；(b) 序列化键白名单 + 契约测试
- **结论**：**(b)**——清单条目只允许键 `{node_id, artifact_hash, round_id}`，
  序列化层白名单过滤；契约测试断言任何 `score`/`eval_breakdown` 键不存在
- **依据**：FR-002 要求机检门禁；"构造时小心"不可测试，白名单把防锚定变成可证伪断言。
