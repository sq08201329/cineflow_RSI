# 功能规格说明：外环周校准（人评锚点 → calibration → 权重再拟合）

**功能分支**: `010-weekly-calibration`

**创建日期**: 2026-09-19

**状态**: 草稿

**输入**: 用户描述："二期立项书 F5：外环周校准机制——内容负责人每周对 top-k 产出盲评，人评得分经录入通道入库（写入即冻结）；系统自动对比人评锚点与自动评估器在同工件上的得分偏差，结论写入评估器注册中心 calibration 字段；偏差超阈值时触发代理权重再拟合提案，人工确认后以新版本生效；产出每周评估器信度报告（内环得分 vs 人评相关系数）。验收：首轮 top-k 盲评入库并触发权重再拟合。"

**约束来源**: 项目宪章 v1.1.0（原则一：human 类评估器产出写入即冻结、版本冻结；原则六：人类是校准锚点不是流水线工人——只稀疏抽检 top-k，不得逐条评估；原则五：阈值与周期全配置化）。业务依据 `docs/影视全Agents公司技术方案.md` §2.1（L4 人类锚点层）、§4.2（外环周校准）。立项依据 `docs/二期立项书.md` WS1-F5。依赖功能 001（评估器注册中心 / 合成评分 / 权重快照）、003（平台真值回流通道语义）、004（judge 委员会）。本特性是 F7（judge 漂移检测）与北极星指标"评估器信度 ≥0.6"的数据前置。

## Clarifications

### Session 2026-09-19

- Q: 校准结论写入 `calibration` 字段时评估器版本号如何变化？ → A: 独立 append-only 校准台账（文件化落盘），评估器版本不变；注册新版本时 calibration 字段填入最新台账快照；仅权重再拟合才升版本
- Q: 每周 top-k 盲评覆盖哪些 Agent？ → A: promo 以平台回流真值为锚点（直接入偏差配对，不盲评）；人评盲评覆盖 visual 及后续新 Agent 的 judge/proxy 环节
- Q: 权重再拟合提案的候选新权重由谁给出？ → A: 系统自动拟合算法产出候选值（人工仅确认/搁置，不可编辑）；拟合算法选型属实现细节留 plan 阶段
- Q: promo 平台回流真值锚点与哪个自动得分配对？ → A: 与剔除平台真值分量后的其余分量配对（CTR 平滑估计 vs 真值回流）；通用规则：锚点不得与其自身贡献的分量配对（防自循环）

## 用户场景与测试 *（必填）*

### 用户故事 1 - 盲评任务生成与人评录入（优先级：P1）

内容负责人发起一轮周校准：系统按 `(项目, Agent, 周期)` 从发现树抽取该周期内得分
top-k 的节点（k 来自形态配置）生成**盲评清单**——只含工件引用与节点 id，**不含任何
自动评估得分**（防锚定）。盲评仅覆盖**采用人评锚点的 Agent**（visual 及后续新 Agent 的
judge/proxy 环节）；promo 等平台真值自备的 Agent 不生成盲评清单，其回流数据视同
human 类锚点直接入偏差配对。负责人线下评审后经录入通道提交人评得分（score ∈ [0,1] +
评审人 + 评审时间）；人评一经写入即冻结为常数（human 类评估器语义），同
`(节点, 评审人, 轮次)` 重复录入必须被拒绝。

**为什么是这个优先级**: 人评锚点是整个外环的唯一输入——没有可信的锚点录入通道，
偏差检测、权重再拟合、信度报告全部无源。这也是一期遗留事项（人评录入通道属运营接入）
的正式收口。

**独立测试**: 用 promo/visual 夹具树跑一轮盲评任务生成与录入：清单零泄露（字段机检）、
写入冻结、重复录入拒绝逐断言；不依赖偏差计算与权重再拟合即可交付"锚点可录入"的价值。

**验收场景**:

1. **Given** 池内某 Agent 当周期有 ≥k 个得分节点, **When** 生成盲评清单, **Then** 取 top-k，清单只含节点 id 与工件引用，任何自动得分字段不存在
2. **Given** 盲评清单已产出, **When** 录入人评得分, **Then** 得分 ∈ [0,1] 校验通过即冻结落盘，携带评审人与评审时间
3. **Given** 同一 `(节点, 评审人, 轮次)` 已有记录, **When** 再次录入, **Then** 拒绝且不产生任何变更（幂等）
4. **Given** 已冻结的人评记录, **When** 尝试更新或删除, **Then** 存储层拒绝（与节点 immutable 同等纪律）
5. **Given** 当周期某 Agent 新节点数 < k, **When** 生成清单, **Then** 取实际数量并注明"样本不足"，轮次正常成立

---

### 用户故事 2 - 偏差检测与 calibration 落盘（优先级：P2）

校准负责人查看偏差分析：系统对本轮每个锚点工件，取人评得分与**该工件节点 eval_breakdown
中各自动评估器**（同 `evaluator_id@version`）的得分做配对，按评估器分层计算系统偏差
（均值偏移）与相关系数；结论以 **append-only 校准台账**（文件化落盘，同 005 谱系惯例）
逐轮追加，评估器版本不因校准写入而变化；仅当权重再拟合生效（用户故事 3）时，新版本
评估器的 `calibration` 字段填入最新台账快照。台账记录必须含样本量、周期、偏差值、
相关系数。同时产出**每周信度报告**（JSON 可机读）：per Agent per 评估器的相关系数与
样本量，标注是否达到 ≥0.6 目标口径。

**为什么是这个优先级**: 偏差检测是"人类校准自动评估器"的计算本体；calibration 落盘
是宪章原则六的强制项（校准结论必须写入 calibration 字段）；信度报告是北极星指标
"评估器信度"的唯一数据来源。

**独立测试**: 构造已知偏差的人评/自动得分配对数据集：偏差值、相关系数、分层口径
逐断言；calibration 写入产生新版本且旧版本元数据不变；信度报告 JSON 字段齐全。

**验收场景**:

1. **Given** 本轮 ≥最小样本量（配置）的有效锚点配对, **When** 偏差计算, **Then** 按评估器分层输出均值偏移与相关系数
2. **Given** 偏差结论产出, **When** 写入校准台账, **Then** 台账追加一条记录（样本量/周期/偏差/相关系数四要素齐全），注册中心既有版本元数据零变更
3. **Given** 一轮校准完成, **When** 生成信度报告, **Then** JSON 含 per Agent per 评估器相关系数、样本量与 ≥0.6 达标标记
4. **Given** 有效配对 < 最小样本量, **When** 偏差计算, **Then** 该评估器本轮 calibration 标注"样本不足"，不产出偏差值、不触发再拟合
5. **Given** judge 类评估器（compare 语义）, **When** 偏差计算, **Then** 用锚点排名与 judge 胜率的序一致性口径，不得把胜率当分数直接相减

---

### 用户故事 3 - 权重再拟合提案与生效门禁（优先级：P3）

校准负责人处理再拟合提案：某评估器偏差超过阈值（形态配置）时，系统**自动拟合候选
新权重**并生成**权重再拟合提案**（含偏差证据、拟合目标与候选新权重）；提案必须
**人工确认**后才生效——人工只有确认/搁置两键，**不可编辑候选权重**（改权重 = 换提案，
须由系统重新拟合，防止人工绕开偏差证据随口调参）；生效 = 合成评分权重注册新版本
（`calibration` 填入最新台账快照）+ 形态配置权重快照更新；未确认提案对生产零影响。
权重变更**只影响新产生的节点**，历史节点得分与 config_snapshot 永远不重算、不回改。

**为什么是这个优先级**: 再拟合是外环的闭环动作，但改权重 = 改评估口径，是版本冻结
原则下最危险的操作——必须有人工门禁挡在前面，且它依赖前两个故事的产出才能成立。

**独立测试**: 注入超阈偏差与不超阈偏差两组数据：提案生成/不生成逐断言；确认与搁置
两条路径分别验证"生效产生新版本"与"零变更"；历史节点得分不变性审计。

**验收场景**:

1. **Given** 某评估器偏差 > 阈值（配置）, **When** 校准轮次收口, **Then** 生成权重再拟合提案（含偏差证据与候选新权重）
2. **Given** 提案未获人工确认, **When** 检查生产状态, **Then** 合成权重版本与 configs 快照零变更
3. **Given** 提案获人工确认, **When** 生效, **Then** 合成评分注册新版本、configs 权重快照更新、提案状态落盘（确认人/时间）
4. **Given** 权重已变更, **When** 审计历史节点, **Then** 历史节点 score 与 eval_breakdown 与落盘值逐字节一致（不重算不回改）
5. **Given** 偏差未超阈, **When** 校准轮次收口, **Then** 不生成提案，仅在信度报告记录偏差值

---

### 边界情况

- 首轮校准（无任何历史 calibration）：全部评估器记"首轮基线"，偏差值照常计算但不判超阈（无基线可比）
- 人评与自动得分完全背离（相关系数为负）：如实记录负相关并告警，**禁止**据此自动生成反向权重提案——转人工裁决
- 同一工件被多个评估器打分但节点 eval_breakdown 缺某评估器版本：该配对对该评估器跳过并注明
- 评审人中途退出轮次：已录入部分保留（已冻结），轮次以实际样本量收口并注明
- 提案确认时目标评估器已因其他原因升版：提案必须基于最新版本重新锚定，拒绝基于过期版本生效
- 盲评清单生成后节点所在树被证明有误：锚点仍有效（评的是工件），但信度报告注明树来源异常
- 锚点来源恰好是某评估器分量（如 promo 平台真值）：该分量对该锚点的配对必须剔除（防自循环），分层报告注明剔除口径

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供校准轮次执行器：输入 = `(项目, Agent, 周期)` + 形态配置（k、最小样本量、偏差阈值、信度目标）；输出 = 盲评清单、偏差分析、信度报告与（可选）权重提案
- **FR-002**: 盲评清单必须只含节点 id 与工件内容寻址引用，**禁止**携带任何自动评估得分、score 或 eval_breakdown 字段（机检门禁）；top-k 按节点 score 降序取，k 来自配置；盲评清单仅为采用人评锚点的 Agent 生成（visual 及后续新 Agent），promo 等平台真值自备的 Agent 不生成盲评清单，其平台回流数据视同 human 类锚点（来源标记 `platform_truth`）直接入偏差配对
- **FR-003**: 人评录入必须校验 score ∈ [0,1]、评审人非空、轮次存在；写入即冻结，同 `(节点, 评审人, 轮次)` 重复录入拒绝；更新/删除人评记录必须被存储层拒绝
- **FR-004**: 偏差计算必须按 `evaluator_id@version` 分层配对同工件的锚点与自动得分，输出均值偏移与相关系数；**锚点不得与其自身贡献的评估器分量配对**（防自循环）——promo 的平台真值锚点与剔除平台真值分量后的其余分量（如 CTR 平滑估计）配对，人评盲评锚点与全量自动评估器配对；judge 类用序一致性口径；有效配对 < 最小样本量时该评估器本轮不产偏差值
- **FR-005**: 校准结论必须写入**文件化 append-only 校准台账**（每轮每评估器一条，四要素齐全：样本量、周期、偏差值、相关系数）；评估器注册版本**不因**校准写入而变化；仅当评估器因权重再拟合升版时，新版本的 `calibration` 字段必须填入最新台账快照；台账与既有注册版本元数据不得被修改
- **FR-006**: 每周信度报告必须为 JSON 可机读：per Agent per 评估器的相关系数、样本量、≥0.6 达标标记（目标值来自配置）；相关系数为负时必须产生告警条目
- **FR-007**: 偏差超阈值（配置）必须生成权重再拟合提案：候选新权重由系统**自动拟合算法**产出（基于台账偏差数据），提案附偏差证据与基于的评估器版本；提案必须人工确认才生效，人工仅可确认/搁置、**禁止**编辑候选权重；未确认零变更；确认记录（确认人/时间）落盘
- **FR-008**: 权重生效必须 = 合成评分新版本注册（`calibration` 填入最新台账快照）+ 形态配置权重快照更新；历史节点 score、eval_breakdown、config_snapshot 永远不重算不回改（immutable 审计口径覆盖）
- **FR-009**: 每轮校准的锚点得分分布快照必须落盘（per 评估器 per 周期），为 F7 judge 漂移自动检测供数
- **FR-010**: 周期、k、最小样本量、偏差阈值、信度目标值必须全部形态配置化（configs/*.yaml），切换形态零代码改动
- **FR-011**: 校准过程自身禁止触发任何昂贵动作（视频生成、投放等）；读取仅限发现树与对象存储只读路径

### 关键实体 *（如果功能涉及数据）*

- **校准轮次（CalibrationRound）**: 一轮周校准的完整记录——周期、Agent、盲评清单、样本量、结论与提案指针
- **锚点评分（AnchorScore）**: 一条锚点记录——节点 id、工件引用、score、来源（`human_blind` 人评盲评 / `platform_truth` 平台回流真值）、评审人或来源渠道、时间、轮次；写入即冻结
- **偏差记录（BiasRecord）**: 某评估器本轮的偏差分析——分层口径、均值偏移、相关系数、有效配对数；逐轮追加进校准台账
- **配对记录（PairingRecord）**: 一条锚点×评估器分量的配对——锚点得分、自动得分、剔除标记（自循环剔除时注明）；偏差计算的内部中间输入
- **校准台账（CalibrationLedger）**: 文件化 append-only 存储——每轮每评估器一条 BiasRecord；是新版本评估器 `calibration` 字段快照的来源，也是 F7 漂移检测的数据源
- **信度报告（CalibrationReport）**: 每周 JSON——per Agent per 评估器相关系数/样本量/达标标记/告警条目
- **权重提案（WeightProposal）**: 再拟合提案——偏差证据、候选新权重、基于版本、状态（待确认/已确认/已搁置）、确认人与时间

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书周 1~2）：首轮 top-k 盲评入库且至少一次权重再拟合提案流程完整走通（生成 → 确认/搁置 → 状态落盘）
- **SC-002**: 盲评清单自动得分泄露字段为 0（机检：清单序列化结果中不存在 score/eval_breakdown 键）
- **SC-003**: 人评记录的更新/删除尝试 100% 被拒绝；重复录入 100% 幂等拒绝
- **SC-004**: 注入已知偏差数据集：偏差值与相关系数计算误差 < 1e-6；超阈提案生成率 100%，未超阈不生成
- **SC-005**: 未经人工确认的权重提案生效次数为 0（门禁可机检）
- **SC-006**: 权重变更后历史节点审计（score 与 eval_breakdown 复算比对）100% 一致
- **SC-007**: 单元测试覆盖率 ≥ 85%（core + agents + dreaming 口径，新模块同口径）

## 假设

- 评审人为内容负责人（组织角色假设，技术方案 §5.1）；评审过程在系统外完成，本特性只交付清单生成与录入通道，不做评审 UI（Web 看板属 F8，且宪章限定只读——录入永远走 CLI/文件通道）
- 一期遗留"真实在线轨迹采集周期"仍属运营接入，本特性以录制夹具与既有 promo/visual 树为数据来源
- promo 的平台真值回流（003 已实现）与本特性锚点语义一致：平台回流数据视同 human 类锚点，写入即冻结，纳入偏差配对
- 权重再拟合的具体算法（回归方式、正则化）属实现细节，plan 阶段定；本规格只约束触发条件、生效门禁与版本语义
- 开发 Agent 无自动评估器，不接本校准机制（宪章原则六既定）；剧本 Agent（F4 降级模式）是否接入在其规格中另行决定
- judge 漂移自动检测（F7）不在本特性范围，本特性只负责把锚点分布快照按约定口径落盘供数
