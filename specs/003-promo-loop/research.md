# 阶段 0 调研：宣发 Agent 全闭环

**日期**: 2026-09-18 | **关联计划**: [plan.md](plan.md)

## 决策 1：immutable 树与"回流写入"的张力——两段式落盘

**问题**: 001 规定树节点只 INSERT（immutable），但宣发闭环里投放执行与指标回流之间存在
小时级时间差，"回流写入节点 eval_breakdown"看似要修改已落盘节点。

**决策**: 节点**延迟一次性落盘**。投放执行、成本累计、指标待回流等中间态存放在**可变**
运营表 `promo_campaigns`（新表，迁移 0002）；指标回流校验通过后，构造**完整** TreeNode
（含 `human.platform_metrics@version` 明细与全部成本）单次 INSERT——节点从诞生即终态，
"写入即冻结"由 immutable 天然保证，无需任何例外机制。

**理由**: 宪章原则二不允许给 tree_nodes 开口子；运营状态（活动状态机、幂等键）本来
就不是谱系数据，可变表名正言顺。回放只看见完整节点，语义更干净。

**已评估的替代方案**: 给 eval_breakdown 开部分更新通道（破坏 immutable，一票否决）；
PLANNED 落盘后迁移（001 已约定 PLANNED 不落盘，且状态迁移等于 UPDATE，被否）。

## 决策 2：本期新建 core/llm_gateway 最小版

**决策**: 物料文案生成必须走 LLM，而宪章原则三要求一切 LLM 调用经网关计费——001/002
未建网关，本期新建最小版：`chat(prompt, **params) -> 文本`，统一做成本入账
（映射进 CostRecord 的 llm_calls/llm_tokens）、内容哈希缓存（同 prompt 同参不重复计费）、
指数退避重试（上限 3 次）。后端可插拔：`MockBackend`（prompt 哈希为种子，确定性，开发
/CI 默认）与 `HttpBackend`（OpenAI 兼容端点，凭证读环境变量，本期不由自动化测试覆盖真实调用）。

**理由**: 没有网关，"LLM 调用必须入账"（宪章）与"成本对账 100%"（SC-003）都无法成立。
最小版只覆盖本期所需面，不提前做路由/限流等二期能力（YAGNI）。

**已评估的替代方案**: 业务侧直连 SDK（违宪）；引入 LiteLLM 等现成网关（黑盒计量，
与宪章"成本计量是核心需求，不可依赖黑盒"冲突）。

## 决策 3：模拟平台的确定性设计

**决策**: `SimulatedPlatform` 以 `blake3(物料内容 + 投放参数)` 为种子生成指标：CTR、
完播率、转化率从设定的真实感分布（Beta/截断正态）抽样，同物料同参数**逐字节可复现**；
投放花费按出价与曝光模型结算，严格记账供对账。

**理由**: 开发与 CI 需要"像真的但可复现"的平台；确定性同时服务回放（树可重放）与
测试断言。分布参数进 configs，随形态可调。

**已评估的替代方案**: 随机种子每次随机（测试不可断言，被否）；固定常数指标（无法暴露
进化曲线差异，被否）。

## 决策 4：CTR 代理评估器 = 分桶贝塔平滑

**决策**: `proxy.ctr_history` 按物料特征分桶（平台 × 物料类型 × 题材标签），桶内用
贝塔平滑 `(clicks + α) / (impressions + α + β)` 估计 CTR 并归一化到 [0,1]；只用**已冻结**
的历史回流数据；估计器随数据快照版本化（快照 BLAKE3 哈希写入评估器 calibration 字段，
数据变即版本变）。

**理由**: 一期无 ML 训练管线（规格假设）；分桶平滑可解释、确定性、零依赖，满足原则一
的确定性注册要求。桶稀疏时回退全局先验（α/β 即先验强度）。

**已评估的替代方案**: 训练 ML 模型（超范围）；直接用最近 CTR 均值（无平滑，小样本噪声
大，被否）。

## 决策 5：幂等与预算门禁的落库

**决策**: `promo_campaigns` 表以 `round_id` 为唯一约束——同轮次二次触发命中唯一约束即
返回首轮结果（0 重复投放）；预算门禁在执行器入口校验：`spent + 申请额 ≤ 总预算 ×
promo_pilot_ratio`，数据库事务内校验+扣减，防并发双花。

**理由**: 幂等键必须落在有唯一约束的存储上才可靠；预算扣减与校验同事务是防超支的
标准做法。树节点不提供可变性，故运营状态必须用这张可变表承载。

## 决策 6：进化报告复用 002 回放 + 两手写策略版本

**决策**: `agents/promo/report.py` 对 `policies/history/promo/` 下的基线与变体策略
（本特性手写提交，BLAKE3 版本号）分别在模拟器池中回放，产出 EvolutionReport JSON：
双曲线、成本、pareto_auc 与并行惩罚分量、谱系引用（policy_version → tree_ids）。

**理由**: 里程碑验收要的是"曲线产出"而非自动进化；做梦层（周 11~12）接入前，人工
策略变体是诚实的演进来源（原则六）。
