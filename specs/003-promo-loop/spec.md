# 功能规格说明：宣发 Agent 全闭环（真实投放与数据回流）

**功能分支**: `003-promo-loop`

**创建日期**: 2026-09-18

**状态**: 草稿

**输入**: 用户描述："实现一期里程碑周 7~8 交付物：agents/promo 宣发 Agent 全闭环——线上探索 = 真实小规模投放（单轮 ≤ 总预算 2% 门禁）、物料合规评估（rule/proxy/human 三层评估器）、平台数据回流写入即冻结、树转模拟器回放验证、首轮进化曲线产出、成本数据入账。验收：首轮进化曲线产出，成本数据入账。"

**约束来源**: 项目宪章 `.specify/memory/constitution.md`（原则一/二/三/六为直接相关项）；工程细节参照 `docs/CineFlow开发文档.md` §2.3（宣发评估器清单）、§6（闭环特例）、§7（配置）。依赖功能 001（树/评估器）与 002（回放/沙箱）。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 宣发线上探索闭环（优先级：P1）

宣发工程师触发一轮线上探索：当前策略版本生成候选物料（文案/海报参数）→ 硬规则合规
门禁（尺寸、时长、敏感词）拦截不合格物料 → 合格物料经平台适配器小规模投放——单轮
花费**强制不超过总预算的 2%**，超限拒投 → 平台指标（完播率/CTR/转化）经回流管道写入
节点评估明细，**写入即冻结为常数** → 探索全程落发现树，每一步成本（生成 API、投放
花费、LLM 调用）完整入账。整轮以轮次 ID 幂等，重复触发不重复扣预算、不重复投放。

**为什么是这个优先级**: 宣发是一期闭环最干净的环节——唯一拥有真实自动评估器的链路，
整套"做梦"基建要先用它验证（开发文档 §6）。没有真实数据回流，回放池永远是空池。

**独立测试**: 用模拟平台适配器跑通一轮完整闭环：生成 → 门禁 → 投放（预算断言）→
回流 → 树落盘 → 审计成本对账；不依赖回放与进化报告即可交付"真实评估数据开始积累"
的价值。

**验收场景**:

1. **Given** 一轮探索的总预算 $500, **When** 策略申请投放花费超过 $10（2%）, **Then** 投放被拒并记录拒投原因
2. **Given** 含敏感词或尺寸不合规的物料, **When** 进入投放前评估, **Then** 硬规则门禁拦截，该物料不投放、尝试成本照常入账
3. **Given** 投放已执行且平台指标就绪, **When** 回流管道写入节点, **Then** 指标写入评估明细的 human.platform_metrics 项并冻结，任何后续修改被拒
4. **Given** 同一轮次 ID 的探索被重复触发, **When** 二次执行, **Then** 不重复扣预算、不重复投放，返回首轮结果
5. **Given** 一轮探索结束, **When** 审计成本, **Then** 树内所有节点成本合计与投放/生成账目 100% 一致

---

### 用户故事 2 - 树冻结入池与回放验证（优先级：P2）

平台工程师把一轮探索产出的发现树冻结，加入宣发 Agent 的模拟器池；用回放模拟器验证
"探索数据可回放"：参考策略在池内回放的轨迹与线上轨迹结构一致，human.platform_metrics
作为冻结常数直接参与回放打分，无需任何新生成。

**为什么是这个优先级**: 这是"做梦"机制与真实评估器首次对接——验证 002 的回放引擎
在真实数据上成立（dev doc §6："用真实评估器验证整套基建"）。依赖 US1 产出的树。

**独立测试**: 对 US1 产出的树执行回放：probe 命中真实投放节点、UNKNOWN 语义正确、
零生成；与 002 的引擎单测独立，聚焦"真实回流数据可回放"。

**验收场景**:

1. **Given** 一轮探索产出并已冻结的树, **When** 加入模拟器池, **Then** 池接受且冻结校验通过
2. **Given** 池内含真实回流的平台指标节点, **When** 策略 probe 命中, **Then** 返回的得分即冻结的平台真值，全程生成调用为 0
3. **Given** 线上真实轨迹与池内回放轨迹, **When** 运行无偏性验收, **Then** 输出 τ 值与判定（接入 002 的门禁语义）

---

### 用户故事 3 - 首轮进化曲线产出（优先级：P3）

项目负责人查看首轮进化报告：基线手工策略与一个策略变体（人工调整的探索参数）各自
在模拟器池中的回放得分曲线并排对比，输出 JSON 报告（逐轮最优得分、probe 数、有效
串行轮、成本、pareto_auc 奖励分量），回答"策略变体是否优于基线"。一期为人工改策略
（做梦层自动进化属周 11~12），本特性只交付曲线产出与对比能力。

**为什么是这个优先级**: 里程碑验收要求"首轮进化曲线产出"——它是前两故事价值的
可视化收口，但做梦自动化不在本期，P3 合理。

**独立测试**: 用 US1/US2 的池，回放基线与变体两个策略版本，断言报告字段完整、
曲线单调性正确、版本谱系（policy_version）可追溯到树的来源。

**验收场景**:

1. **Given** 基线与变体两个策略版本, **When** 分别回放并生成报告, **Then** 报告含两条得分曲线、成本合计、奖励分量与各自策略版本号
2. **Given** 进化报告, **When** 追溯任一数据点, **Then** 可定位到产生它的树与策略版本（谱系闭环）

---

### 边界情况

- 平台适配器调用失败/超时：按重试策略重试，最终失败则节点记 FAILED（成本照常入账），闭环不崩溃
- 回流数据迟到（投放完成但指标未就绪）：该投放记录保持待回流状态（节点尚未落盘），超时可重试回流；指标回流校验通过后节点一次性完整落盘，落盘即冻结
- 回流重复推送：按（节点， 指标版本）幂等，重复写入不产生变更
- 平台返回异常指标（CTR > 1、负数）：校验拒绝并告警，不写入树
- 预算刚好等于 2% 上限：允许（≤ 语义）；超出 1 分钱也拒投
- 敏感词库为空/未配置：合规评估器报错拒投（缺配置不放行，而非默认通过）
- 一轮探索零物料过门禁：轮次正常结束，树上只有被拦截节点，成本入账
- 模拟平台与真实适配器行为漂移：适配器契约测试双实现同跑

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供宣发线上探索执行器：一轮探索 = 策略生成物料 → 评估门禁 → 投放 → 回流 → 落树，全程以轮次 ID 幂等
- **FR-002**: 系统必须强制预算门禁：单轮投放花费 ≤ 总预算 × 试点比例（形态配置 `promo_pilot_ratio`，默认 0.02）；超限拒投并记录原因
- **FR-003**: 物料必须先过硬规则合规门禁（平台物料规格：尺寸、时长、敏感词）才可投放；不合格物料不得投放
- **FR-004**: 系统必须实现宣发三个评估器：`rule.material_compliance`（合规）、`proxy.ctr_history`（基于历史回流数据的同类型 CTR 预测）、`human.platform_metrics`（平台回流真值，写入即冻结）——均按 001 注册中心规范注册（evaluator_id@version、确定性声明）
- **FR-005**: 平台接入必须通过适配器接口（投放创建/状态查询/指标读取/暂停）；必须提供确定性模拟实现供开发与测试；真实平台适配器实现同一契约，凭证经配置注入
- **FR-006**: 回流管道必须将平台指标写入节点评估明细（携带 `human.platform_metrics@version`），写入即冻结；异常指标（越界值）必须校验拒绝
- **FR-007**: 闭环每一步成本必须入账到节点成本记录：LLM 调用、物料生成 API、投放花费、耗时；FAILED 节点不例外（宪章原则二）
- **FR-008**: 探索产出的树必须可冻结并加入 002 的模拟器池（冻结校验通过）
- **FR-009**: 回放宣发树时必须复用冻结真值打分，生成调用恒为 0（宪章原则三）
- **FR-010**: 系统必须产出进化对比报告：两个策略版本的回放得分曲线、成本、奖励分量（pareto_auc 与并行惩罚）、策略版本号，JSON 格式
- **FR-011**: 报告任一数据点必须可追溯到来源树与策略版本（谱系闭环，宪章原则二）
- **FR-012**: CTR 预测评估器必须只使用已冻结的历史回流数据训练/估计，且其产出随数据快照版本化（数据快照哈希进评估器版本元信息）

### 关键实体 *（如果功能涉及数据）*

- **宣发物料（PromoMaterial）**: 一次投放的内容载体——文案、海报参数、目标平台规格；内容哈希进节点工件引用
- **投放活动（Campaign）**: 一次真实/模拟投放——预算、状态、平台返回的活动标识；与节点一一对应
- **平台适配器（PlatformAdapter）**: 投放平台的能力抽象——创建投放、查询状态、读取指标、暂停；模拟与真实双实现
- **指标快照（MetricSnapshot）**: 一次回流的平台真值——完播率/CTR/转化 + 平台时间戳 + 数据版本；写入即冻结
- **轮次预算（RoundBudget）**: 单轮探索的预算上限（总预算 × 试点比例）与已耗计数
- **进化报告（EvolutionReport）**: 两策略版本的回放曲线对比——逐轮最优得分、probe 数、串行轮、成本、奖励分量、谱系引用

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 预算门禁：超限投放申请 100% 被拒，含超出 1 个最小货币单位的边界用例
- **SC-002**: 端到端一轮闭环（模拟平台）从触发到树冻结 < 5 分钟完成
- **SC-003**: 成本对账：树内节点成本合计与投放/生成账目 100% 一致（自动审计断言）
- **SC-004**: 幂等：同一轮次重复触发产生 0 次重复投放、0 元重复扣费
- **SC-005**: 首轮进化报告产出：包含两个策略版本的完整曲线与奖励分量，JSON 可机读
- **SC-006**: 单元测试覆盖率 ≥ 85%（延续宪章门禁）
- **SC-007**: 适配器契约测试：模拟与真实实现跑同一契约套件（真实实现无凭证时跳过对应用例，接口语义仍受约束）

## 假设

- 真实广告平台账号与凭证**不在本期接入**：适配器接口 + 确定性模拟实现先行；真实渠道接入是凭证配置的运维动作，不改代码路径
- 一期物料为文本/海报参数级，不含视频渲染（视觉 Agent 属周 9~10）
- `proxy.ctr_history` 一期为基于历史回流数据的分桶平滑估计（如贝塔平滑），不含 ML 训练管线
- 做梦层自动进化不在本期：进化曲线的策略变体由人工产出（周 11~12 才接 dreaming）
- 平台敏感词库与物料规格来自形态配置/运营配置，缺失即拒投（不放行）
- 宣发线上探索的调度（每天何时触发）不在本期——本特性交付"触发即执行一轮"的能力
