# 功能规格说明：发现树与评估器框架（L1 基建第一批）

**功能分支**: `001-tree-evaluators`

**创建日期**: 2026-09-18

**状态**: 草稿

**输入**: 用户描述："实现一期里程碑周 1~3 交付物：core/tree 发现树（节点/树模型、不可变存储约束、谱系查询）+ core/evaluators 评估器框架（基类、注册中心、合成评分），为回放模拟器与生产 Agent 提供基础。验收：单元测试覆盖率 ≥85%。"

**约束来源**: 项目宪章 `.specify/memory/constitution.md`（原则一、二为不可协商项）；工程细节参照 `docs/CineFlow开发文档.md` §1、§2。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 不可变的发现树记录与谱系查询（优先级：P1）

平台工程师在线上探索中把每次尝试追加为发现树节点（提示词、决策时可见的观测上下文、
工件引用、评估明细、得分、成本、策略版本、父节点），树一经写入即不可变；评估工程师、
做梦层与下游 Agent 可按"项目 / Agent / 策略版本"查询任意节点与子树谱系。

**为什么是这个优先级**: 发现树是公司级核心资产与唯一事实来源（宪章原则二）。没有它，
评估器框架、回放模拟器、做梦层都无据可依；它是全部后续特性的地基。

**独立测试**: 追加一批节点后——对任一历史节点发起修改/删除必须被拒绝；按三维索引查询
必须返回正确谱系；成本入账必须完整（含失败节点）。仅此能力即可交付"探索全程可追溯"
的价值，无需评估器框架即可演示。

**验收场景**:

1. **Given** 一棵已落盘的发现树, **When** 对任意历史节点尝试修改或删除, **Then** 存储层拒绝该操作且原节点数据逐字段不变
2. **Given** 某项目存在多棵树、多种策略版本, **When** 按（项目， Agent, 策略版本）任一组合查询, **Then** 返回且仅返回匹配的树及其节点结构
3. **Given** 一次评估器崩溃导致的失败尝试, **When** 节点入库, **Then** 节点以失败状态落盘、得分为空、成本照常入账
4. **Given** 两个内容完全相同的工件, **When** 先后存入对象存储, **Then** 两者共享同一引用，无重复存储

---

### 用户故事 2 - 评估器注册与版本冻结（优先级：P2）

评估工程师实现一个评估器（硬规则 / 代理模型 / judge / 人类锚点），以
`evaluator_id@version` 全局唯一注册；系统拒绝重复注册，拒绝非确定性评估器进入回放
打分路径（人类校准锚点除外）；每次评估返回归一化得分与人可读的诊断明细。

**为什么是这个优先级**: 评估器版本冻结是"回放即等价于重跑"的第一前提（宪章原则一）。
它依赖 P1 的节点落盘能力才有落点，但注册与校验逻辑本身可脱离树独立开发、独立验证。

**独立测试**: 注册若干评估器——同 id 同 version 重复注册必须报错；未声明确定性的
非人类评估器注册必须被拒；调用评估返回 [0,1] 得分与诊断明细。不依赖任何 Agent。

**验收场景**:

1. **Given** 已注册 `proxy.aesthetic@1.0.0`, **When** 再次注册同 id 同 version, **Then** 注册被拒绝并给出明确错误
2. **Given** 一个未声明确定性的代理模型评估器, **When** 尝试注册, **Then** 被拒绝；同一评估器若为人类锚点类型则允许注册
3. **Given** 任一已注册评估器, **When** 对工件执行评估, **Then** 返回 [0,1] 归一化得分及人可读的诊断明细
4. **Given** judge 类评估器, **When** 传入两个工件比较, **Then** 返回前者胜率 ∈ [0,1]

---

### 用户故事 3 - 合成评分与硬规则门禁（优先级：P3）

下游 Agent 把多个评估器结果按形态配置的权重合成为节点总分：任一硬规则评估器
得分为 0 时总分直接为 0（不可行解）；否则按权重加权求和。合成所用权重与评估器版本
组合以全量配置快照冻结进树，保证日后可复现。

**为什么是这个优先级**: 合成评分把 P2 的评估器产出变为节点得分（P1 的落盘字段），
是三者中最小、最上层的逻辑；前两故事各自交付独立价值，本故事将其串成闭环。

**独立测试**: 构造若干评估明细与权重配置——验证门禁语义、加权结果与快照落盘，
无需真实评估器实现即可用桩评估器完成。

**验收场景**:

1. **Given** 评估明细中某硬规则评估器得分为 0, **When** 合成总分, **Then** 总分为 0，无视其余高分
2. **Given** 全部硬规则得分非 0, **When** 合成总分, **Then** 总分等于按配置权重的加权和
3. **Given** 一棵新建的发现树, **When** 树落盘, **Then** 评估器版本组合与权重快照随树冻结，后续修改配置不影响已落盘树的解读
4. **Given** 权重配置中引用了未参与评估的评估器, **When** 合成总分, **Then** 校验失败并拒绝产出得分

---

### 边界情况

- 评估器执行崩溃：节点以失败状态落盘（得分为空）、成本照常入账，树结构不受影响，该节点仍可被回放使用
- 对历史节点发起 UPDATE / DELETE：存储层拒绝（宪章原则二，第二道防线）
- `eval_breakdown` 缺失任一评估器的 `evaluator_id@version`：拒绝写入（第三道防线）
- 同 id 同 version 评估器重复注册：拒绝并报错；任何行为变更必须升版本号
- 权重配置的键与评估明细的键不完全匹配：合成评分必须校验失败而非静默按部分权重计算
- 权重总和不为 1：不做隐式归一化，按配置语义直接加权（口径一致性优先），配置作者自行保证
- 相同内容工件重复写入：内容寻址去重，不产生额外存储
- 查询不存在的节点 / 空树：返回明确的空结果而非异常崩溃
- 线上探索中处于"计划中"状态的节点：不落盘；回放路径中不得出现该状态

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供发现树节点模型，完整记录宪章原则二要求的全部字段（节点标识、树标识、父节点、深度、Agent 标识、策略版本、提示词、观测上下文、工件引用、评估明细、得分、成本、状态、创建时间），且领域对象不可变
- **FR-002**: 系统必须在存储层强制节点不可变：写入后禁止修改、禁止删除，只允许追加
- **FR-003**: 系统必须提供谱系查询能力：单点读取、子节点枚举、按（项目， Agent, 策略版本）任意组合过滤树
- **FR-004**: 系统必须为每个节点完整入账成本（LLM 调用次数与 token 量、生成 API 调用与花费、人工评审工时、耗时），失败节点不得例外
- **FR-005**: 工件必须以内容寻址方式存储，存储键即内容哈希，相同内容天然去重
- **FR-006**: 系统必须提供评估器注册能力，以 `evaluator_id@version` 全局唯一；同 id 同 version 重复注册必须被拒绝
- **FR-007**: 用于回放打分的评估器必须声明确定性；非确定性评估器（人类校准锚点除外）必须被拒绝注册
- **FR-008**: 评估结果必须归一化到 [0,1]，并携带人可读的诊断明细，明细随节点评估明细一并落盘
- **FR-009**: 每个节点的评估明细必须包含所用每个评估器的 `evaluator_id@version`，缺失必须拒绝写入
- **FR-010**: 合成评分必须实现硬规则门禁：任一硬规则评估器得分为 0 时总分为 0；否则按权重加权求和
- **FR-011**: 合成权重必须来自形态配置（禁止硬编码），并以全量配置快照冻结进树
- **FR-012**: 节点状态必须覆盖"计划中 / 已评估 / 失败"三态；"计划中"仅存在于线上探索过程，不得落盘
- **FR-013**: judge 类评估器必须支持成对比较能力，返回前者胜率 ∈ [0,1]；单点打分型评估器不要求此能力
- **FR-014**: 树本体只存结构，节点本体按节点标识独立存储，支持单条线索数万节点规模
- **FR-015**: 评估器类型必须覆盖四类：硬规则、代理模型、judge、人类锚点，且人类锚点产出（人评、平台回流数据）一经写入即冻结为常数

### 关键实体 *（如果功能涉及数据）*

- **发现树节点（TreeNode）**：一次探索尝试的完整、不可变记录——本次尝试的提示词、决策时可见的累积观测（回放重建依据）、工件内容引用、逐评估器明细、合成得分、成本、状态、产生它的策略版本。失败节点的得分为空但成本有效
- **发现树（DiscoveryTree）**：一次探索过程的结构记录——所属项目、Agent、策略版本、根节点、节点集合与全量配置快照（评估器版本组合、权重）；树只存结构，节点独立存储
- **成本记录（CostRecord）**：单次尝试消耗的全部资源——LLM 调用量、生成 API 调用与花费、人工工时、耗时；不可变
- **评估器（Evaluator）**：可注册的质量评估单元，携带标识、版本、类型、确定性声明、单次调用成本、最近校准记录
- **评估结果（EvalResult）**：单次评估的产出——[0,1] 归一化得分与人可读诊断明细
- **注册中心（Registry）**：评估器的全局唯一命名空间，以 `evaluator_id@version` 为键，实施唯一性与确定性校验

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 单元测试覆盖率 ≥ 85%（对应一期里程碑周 1~3 验收线）
- **SC-002**: 随机抽取 100 个历史节点重算得分，与落盘值 100% 一致（immutable 审计通过）
- **SC-003**: 对历史节点的修改 / 删除尝试被 100% 拒绝，原始数据逐字段不变
- **SC-004**: 评估器行为变更不升版本号时，重复注册 100% 被拒绝；回放打分路径中可用的非确定性评估器为 0
- **SC-005**: 下游模块（回放模拟器、生产 Agent）仅通过公开接口即可完成节点写入与全部谱系查询，无需感知存储实现
- **SC-006**: 相同内容的工件重复写入不产生额外对象存储占用

## 假设

- 本特性仅交付框架与接口：**不包含**任何具体生产评估器实现（视觉 / 宣发评估器属后续里程碑）；测试以桩评估器完成
- 沙箱隔离不在本特性内（属周 4~6 的 core/sandbox 里程碑）；本特性内评估器按进程内调用约定执行
- 存储与对象存储的具体连接、部署参数由运维配置管理，不在本特性范围内
- 短剧等其他形态配置不在本特性内；仅需保证权重从形态配置读取而非硬编码，为形态扩展预留接口
- 树规模按"单条线索数万节点"设计，暂不考虑跨项目合并回放（二期事项）
