## 用户场景与测试 *（必填）*

### 用户故事 1 - 只读查询接口与数据同源（优先级：P1）🎯 MVP

内部用户/前端页面经**只读查询接口**取数：接口层只暴露 GET（无 POST/PUT/DELETE/PATCH
路由——机检门禁）；数据源 = 发现树存储（**只读连接**：应用账号仅有 SELECT 权限——
001 的 `cineflow_app` 授权纪律复核）+ 文件化产物（policies/history、dreaming/history、
calibration/、replay/pools/ 的只读文件读取）；**数据同源**：接口响应与既有 JSON 报告
（CLI 产出）逐字段一致（抽样机检）——接口**不另建数据通道、不引入新计算口径**
（读已落盘的报告与表，不在接口层重算）。

**为什么是这个优先级**: 只读门禁与数据同源是宪章新条款的工程落点——前端若自带
计算口径或写路径，就会产生"看板上一套数、报告里另一套数"的双事实源风险；门禁必须
先于页面成立。

**独立测试**: 起服务后对路由表与响应做机检（无写动词路由、写请求被拒）；同源抽样
（接口响应 vs 既有 JSON 报告逐字段一致）逐断言；不依赖任何页面即可交付"只读数据面"
的价值。

**验收场景**:

1. **Given** 服务已起, **When** 枚举路由表, **Then** 无任何写动词路由（POST/PUT/DELETE/PATCH 全部不存在——机检）
2. **Given** 客户端, **When** 向任一路径发写请求, **Then** 405/404 拒绝（无写入效果，存储层零变更）
3. **Given** 同一数据（如某轮做梦的 reward 曲线）, **When** 经接口与经 CLI JSON 报告分别取, **Then** 逐字段一致（抽样机检，同源成立）
4. **Given** DB 连接, **When** 检查权限, **Then** 应用账号仅 SELECT（写权限不存在——权限断言）
5. **Given** 接口层, **When** 审计其代码, **Then** 不存在任何 INSERT/UPDATE/DELETE 调用（静态断言：只读 SQL 与文件只读打开）

### 用户故事 2 - 发现树浏览器（优先级：P2）

项目负责人浏览发现树：按 **(项目, Agent, 策略版本)** 三维过滤树清单；进入某棵树查看
节点列表（深度/得分/成本/状态）与节点详情（prompt 摘要、工件引用（哈希 + 元信息，
**不做媒体播放**）、eval_breakdown 分量（评估器版本标注）、成本明细）；查看谱系链路
（父策略版本 → 本树 → 子策略版本，含 011 跨项目归属标注）。空态与分页有明确行为
（无树/无节点时如实空态；大体量树分页加载）。

**为什么是这个优先级**: 树浏览器是"发现树是公司资产"的可视化证明——让树从 DB 里的
记录变成可浏览、可审计的资产视图；依赖 US1 的只读数据面。

**独立测试**: 夹具树 + 夹具谱系：三维过滤、节点详情字段齐全、谱系链路正确、空态与
分页行为逐断言（接口层测试 + 页面渲染冒烟）。

**验收场景**:

1. **Given** 多项目多 Agent 的树, **When** 按三维过滤, **Then** 树清单正确（项目/Agent/策略版本过滤各自生效）
2. **Given** 某棵树, **When** 查看节点, **Then** 节点列表含深度/得分/成本/状态；详情含 prompt 摘要/工件引用（哈希 + 元信息）/eval_breakdown（评估器版本标注）/成本
3. **Given** 某策略版本, **When** 查看谱系, **Then** 链路完整（父版本/产出树/子版本，跨项目归属标注）
4. **Given** 空项目（无树）, **When** 浏览, **Then** 空态如实呈现（不报错不伪造）
5. **Given** 大体量树（>单页容量）, **When** 浏览节点, **Then** 分页加载（边界正确：无重复无遗漏）

### 用户故事 3 - 进化曲线看板（优先级：P3）

项目负责人查看进化状态：逐轮 reward 曲线（005 做梦轮次数据，按 Agent 分线）、塌缩
检测标注（005 的 collapse 判定在曲线上标注）、成本汇总曲线（CostRecord 按 Agent/周期
合计）、**校准与漂移摘要**（010 信度报告的达标状态 + 012 漂移状态徽标
（normal/suspect/confirmed_drift））——看板是"系统是否在健康进化"的一屏答案。

**为什么是这个优先级**: 曲线看板是管理层视图（北极星指标的持续呈现），依赖 US1/US2
的数据面；信度/漂移摘要让 010/012 的产出首次进入"一屏可见"的层面。

**独立测试**: 夹具轮次 + 夹具校准/漂移数据：曲线序列正确、塌缩标注、成本合计、
信度/漂移徽标状态逐断言。

**验收场景**:

1. **Given** 多轮做梦数据, **When** 查看看板, **Then** 逐轮 reward 曲线按 Agent 分线呈现（序列与 dreaming/history 一致）
2. **Given** 塌缩轮次, **When** 查看看板, **Then** 塌缩标注存在（005 口径）
3. **Given** 成本数据, **When** 查看, **Then** 按 Agent/周期合计曲线与 CostRecord 汇总一致（对账口径）
4. **Given** 010 信度报告与 012 漂移状态, **When** 查看摘要区, **Then** 信度达标状态与漂移徽标（normal/suspect/confirmed_drift）如实呈现（缺失时如实空态）

---

### 边界情况

- 数据源缺失（无树/无做梦轮次/无校准报告）：各面板如实空态（不报错、不伪造占位数据）
- DB 不可用（开发环境未起 PG）：服务照常启动，树相关接口返回明确错误（503 + 说明），
  文件化产物面板仍可用（文件源不依赖 DB）
- 工件媒体内容：页面只给哈希引用与元信息，**不做**媒体播放/预览（避免把只读视图变成
  内容分发通道；预览属后续单独评估）
- 大体量树（万级节点）：分页/懒加载，单页容量配置化；不做全量加载
- 多用户并发读取：只读接口无写锁竞争；不做会话态
- 数据更新中的读（写入树时浏览）：只读视图呈现**已提交**状态（读已落盘数据，进行中
  的中间态不可见——与两段式落盘的"写入即冻结"语义一致）
- 接口被外部探测写路径：无写端点可探测（405/404），不暴露任何写语义

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供只读查询接口：仅 GET 路由；**路由表机检无任何写动词路由**；写请求一律 405/404 拒绝且零副作用
- **FR-002**: 数据源必须为：发现树存储（只读连接，应用账号仅 SELECT 权限——权限断言）+ 文件化产物的只读读取（policies/history、dreaming/history、calibration/、replay/pools/）；**禁止**接口层另建数据通道、重算口径或任何写入
- **FR-003**: 树浏览接口必须支持：按 (项目, Agent, 策略版本) 三维过滤树清单；节点列表（深度/得分/成本/状态，分页）；节点详情（prompt 摘要/工件引用/eval_breakdown 含评估器版本/成本）
- **FR-004**: 谱系接口必须支持：策略版本 → 父版本/产出树/子版本的全链路查询（跨项目归属标注，复用 011 口径）
- **FR-005**: 进化曲线接口必须支持：逐轮 reward 序列（按 Agent 分线）、塌缩标注（005 口径）、成本汇总（按 Agent/周期，与 CostRecord 对账一致）
- **FR-006**: 摘要接口必须支持：010 信度报告达标状态 + 012 漂移状态徽标（normal/suspect/confirmed_drift）；缺失时如实空态
- **FR-007**: 前端页面必须提供：发现树浏览器（三维过滤 + 节点详情 + 谱系）与进化曲线看板（曲线 + 塌缩 + 成本 + 信度/漂移摘要）两个视图；`web/` 目录（宪章唯一例外）；**技术形态 = Python 标准库服务 + 无框架静态页（vanilla JS），零新增第三方依赖**；静态导出与服务共用同一查询层（导出 = 预生成 JSON + 静态资产）
- **FR-008**: 只读门禁必须三重机检：路由表断言（无写动词）、权限断言（应用账号仅 SELECT）、静态断言（接口层无写调用）
- **FR-009**: 必须支持静态导出（把当前数据面导出为离线可浏览的静态资产——离线部署形态，无需长驻服务）
- **FR-010**: 同源校验必须可机检且**分层**：有既有 JSON 报告产物的面板（进化曲线/信度/漂移/谱系报表）——接口响应与报告逐字段一致（抽样断言集）；树/节点浏览接口以 DB 只读读数为权威源（字段语义与 001 落库口径一致，无第二口径比对）
- **FR-011**: 部署形态必须保守：默认 bind 127.0.0.1；可选 token 访问控制；不做公网暴露假设（内部工具）
- **FR-012**: 端口/数据源路径/导出目录/单页容量必须全部配置化

### 关键实体 *（如果功能涉及数据）*

- **只读查询接口（ReadOnlyAPI）**: 数据面——GET 路由集（树/节点/谱系/曲线/摘要），数据源为只读 DB 连接 + 文件化产物
- **树浏览视图（TreeBrowserView）**: 三维过滤 + 节点列表/详情 + 谱系链路的页面模型
- **进化看板视图（EvolutionBoardView）**: reward 曲线 + 塌缩标注 + 成本汇总 + 信度/漂移摘要的页面模型
- **同源校验集（ParityCheckSet）**: 接口响应 vs CLI JSON 报告的逐字段抽样断言集（机检门禁）
- **静态导出（StaticExport）**: 当前数据面的离线快照（静态资产目录，可脱离服务浏览）

## 假设

- 前端为**内部工具**（单人/小团队使用）：无登录体系、无多租户、无公网暴露；默认
  bind 127.0.0.1 + 可选 token
- 工件媒体预览（mp4/wav 播放）不在本特性——页面只给哈希引用与元信息；预览若需，
  另立评估（内容分发有独立的带宽/权限考量）
- 技术选型已定（2026-09-21 澄清）：Python 标准库服务 + 无框架静态页（vanilla JS），
  **零新增第三方依赖**；约束已锁定：只读、独立目录、零新写路径、与既有口径同源
- 看板不承载任何操作入口（录入/审批/部署仍走 CLI——010 的录入通道与 005 的 approve
  在 Web 层**不开放**，宪章只读条款）
- 数据更新中的读呈现已提交状态（与两段式落盘的"写入即冻结"语义一致）
- 前端不引入对 core/agents/dreaming 的代码依赖（只读查询接口由 `web/` 内的独立
  查询层实现，经只读连接与文件读取取数）
