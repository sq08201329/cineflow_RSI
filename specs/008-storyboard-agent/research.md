# 阶段 0 调研：分镜 Agent 闭环（008-storyboard-agent）

> 每个决策 = 分歧点 → 备选 → 结论 → 依据。规格：[spec.md](spec.md)（含 2026-09-20 澄清两条）。

## 决策 1：落树节奏——visual 模式（渲染即评即落树）

- **结论**：与 006/007 相同——分镜评估信号全部自动可得，无外部回流；运营表只承载
  预演渲染中间态，评估完成即节点一次性 INSERT
- **依据**：007 已第三次验证该模式；分镜无平台真值。

## 决策 2：ShotList 作为决策对象与回放匹配键

- **结论**：`agents/storyboard/shotlist.py`——镜头列表（shot_id 本地序号 / 景别档位 /
  机位档位与侧别 / 运动 / 时长估算 / 所属场景与承接剧本行 / 备选数）；规范化 JSON
  （键排序）即 edl_hash 类比的 `shotlist_hash`；合法性执行前三层校验：① 承接的剧本行
  存在；② 场景承接（每场景 ≥1 镜）；③ 景别/机位/运动档位在配置枚举内
- **依据**：与 007 EDL 同构——决策对象即回放匹配键；非法决策 0 渲染 0 成本。

## 决策 3：coverage 门禁口径（澄清 Q1 落地）

- **结论**：`rule.coverage` = **场景级 + 必覆盖清单**：每场景 ≥1 镜为硬要求；ScriptSegment
  中标注 `key=True` 的行必须逐条有镜头承接（`covers` 字段引用）；普通台词行允许合并
  （一镜覆盖多行）或拆分（一行多镜），不判违规；必覆盖清单为空 → 降级纯场景级并注明
- **依据**：澄清决议——逐条全覆盖会误杀合法分镜手法（一句台词拆多镜是常规工艺）。

## 决策 4：emotion_alignment 读预演画面帧（澄清 Q2 落地）

- **结论**：`agents/storyboard/board_render.py` 产分镜卡帧（每镜一卡：程序化构图表达
  景别/机位/运动 + 情绪色板注入）→ 拼接为预演 mp4；`proxy.emotion_alignment` **读帧像素**：
  确定性直方图/色板特征向量 vs 情绪基调配置向量（余弦距离 → 得分，定点 6 位）
- **依据**：澄清决议——保留真实 CLIP 类模型替换路径（替换 = 升版本，路径不变）；
  帧由 ShotList 确定性派生，回放可复现由渲染器逐字节一致性保证。

## 决策 5：轴规则（rule.axis_rule）的可机检口径

- **备选**：(a) 机位侧别推导——ShotList 的机位档位含侧别（A/B），场景输入含轴向基准，
  相邻镜头侧别跳变且中间无过渡镜头（越轴镜头）判违规；(b) 只检查同侧连续；(c) 不实现
- **结论**：**(a)**——规则库配置：`axis_rules: {require_transition_on_cross: true,
  allowed_transition_shots: 1, side_field: "side"}`
- **依据**：180° 线是行业硬规则且可从 ShotList 元数据机检（无需画面分析）；过渡镜头
  豁免（越轴镜头是合法手法，直接的侧别硬跳才是错误）。

## 决策 6：judge 摘要函数与三段哈希

- **结论**：`summary.py`——ShotList + 剧本段落 → 确定性结构化文本（镜头序列/景别/运动/
  承接关系/场景分段）；judge 提示词 3 固定模板；锚点集 = 固定 ShotList 集（configs 内嵌）；
  **版本号 = `1.0.0+j{提示词前8}{锚点集前8}{摘要函数前8}`**（007 同款）
- **依据**：技术方案 §2.2"成对比较分镜与剧本段落的贴合度"= 文本层面判断；摘要函数
  变更改变打分行为，必须入版本（原则一）。

## 决策 7：预算门禁/幂等/两段式——同构复用

- **结论**：申请前校验 + 事务内复核；唯一键 `(round_id, shotlist_hash)`；价目
  `render.price_per_shot_usd`（按镜头数计价，与预演时长的关系在实现注释说明）
- **依据**：四个闭环的既有纪律，零新发明。

## 决策 8：回放匹配槽与 dreaming/010 接入（复用 007 教训）

- **结论**：loop 落观测时**同时写 `shotlist` 与 `gen_params` 双键**（002 的 GEN_PARAMS_KEY
  固定读 `gen_params`），实现零特判接入；dreaming/010 零改动，静态证明测试防特判回归
- **依据**：007 US3 的唯一实现改动就是这个双键取舍；008 直接复用，不再重新发现。

## 决策 9：下游 schema 稳定性（FR-012）

- **结论**：ShotList 序列化为稳定 schema（字段名/枚举值文档化 + schema 版本号字段），
  为视觉线（004 生成参数建议）与剪辑线（007 候选镜头库）的接入留契约；本特性不做下游接线
- **依据**：规格假设——下游消费是各自 Agent 的接入事项，本特性只保证 schema 不再漂移。
