## 用户场景与测试 *（必填）*

### 用户故事 1 - 分镜决策执行与动态预演渲染（优先级：P1）🎯 MVP

分镜生产线运行一轮探索：当前策略对输入（剧本段落 = 场景列表 + 每场景的台词/动作行 +
情绪基调标注）产出**分镜脚本 ShotList**（镜头列表：每镜的景别档位/机位/运动/时长估算/
所属场景与承接的剧本行/备选条数）→ 执行器经预算门禁（单轮 ≤ 配置上限，事务扣减、
轮次幂等）调用预演渲染适配器 → 产出动态预演工件（animatic mp4：程序化分镜卡 + 时序 +
可选临时音轨，BLAKE3 内容寻址）与成本入账。适配器双实现：确定性模拟渲染器
（ShotList → 分镜卡帧 → 拼接 → mp4 逐字节复现）为开发/CI 默认；真实预演渲染服务
适配器骨架（无凭证跳过）。中间态落可变运营表，渲染与评估齐备后节点一次性 INSERT。

**为什么是这个优先级**: 分镜脚本是"剧本到画面"的中间表示——上游承接剧本、下游喂给
视觉与剪辑；预演工件落树是后续评估与进化的物质基础，中等成本纪律（原则三）在此落地。

**独立测试**: 用确定性模拟渲染器 + 夹具剧本跑一轮：ShotList→mp4 逐字节复现、预算门禁、
幂等重建、成本入账、两段式落盘；不接评估器与做梦层即可交付"分镜与预演可落树"的价值。

**验收场景**:

1. **Given** 夹具剧本段（≥3 场景）与当前策略, **When** 执行一轮分镜探索, **Then** 产出合法 ShotList，渲染出 animatic mp4 内容寻址落库，成本入账，节点一次性 INSERT
2. **Given** 同一 ShotList 与剧本, **When** 模拟渲染器执行两次, **Then** 两个 mp4 逐字节一致（哈希相等）
3. **Given** 单轮预演渲染预算上限, **When** 策略请求超上限的渲染次数, **Then** 门禁拒绝超额部分，已执行部分成本照常入账
4. **Given** 同轮次重复触发, **When** 幂等检查, **Then** 0 重复渲染、0 重复扣费、节点不重复
5. **Given** ShotList 引用剧本中不存在的行、或场景缺失承接镜头, **When** 执行前校验, **Then** 拒绝且 0 渲染调用、0 成本

### 用户故事 2 - 五评估器与合成评分（优先级：P2）

评估工程师为分镜节点打分：硬规则三门禁——`rule.shot_grammar`（景别切换合理性：相邻
镜头景别跳跃、同景别连续重复上限等，规则库配置）、`rule.coverage`（剧本覆盖率：
**场景级 + 必覆盖清单**——每场景至少一镜为硬要求，剧本标注的"关键行"必须逐条承接，
普通台词合并/拆分不违规）、`rule.axis_rule`
（轴规则检测：越轴/跳轴判定——180° 线规则库）；代理模型——`proxy.emotion_alignment`
（预演画面与剧本情绪的对齐度：**输入 = 预演画面帧**（分镜卡像素，由 ShotList 确定性
派生）+ 情绪基调，CLIP 类对齐的确定性启发式代理，实现哈希即版本）；judge——`judge.script_fit`（成对比较分镜与剧本段落的贴合度：
输入 = ShotList 结构化摘要 + 剧本段落文本，3 固定提示词 × 冻结锚点集投票，提示词/
锚点/摘要函数哈希入版本号）。合成 = 门禁 + 加权求和（权重形态配置）+ 定点归一（6 位小数）。

**为什么是这个优先级**: 分镜评估是"镜头语言"这一主观工艺的可机检化——语法/覆盖率/
轴线是行业硬经验，judge 承担贴合度的主观判断；信号质量决定进化方向是否可信。
依赖 US1 的工件落树。

**独立测试**: 构造已知属性的 ShotList 夹具（景别跳跃违规、场景未覆盖、越轴、情绪
对齐 vs 背离、贴合度高低）：五评估器得分、门禁语义、judge 投票与三段哈希版本、定点
归一逐断言。

**验收场景**:

1. **Given** 相邻镜头景别跳跃超规则库限制, **When** 评估, **Then** shot_grammar 门禁判 0，总分直接为 0
2. **Given** 某场景无任何镜头承接（或必覆盖清单中的关键行未承接）, **When** 评估, **Then** coverage 门禁判 0；场景级 + 必覆盖清单全部满足则通过（普通台词合并/拆分不违规）
3. **Given** 相邻镜头越轴（180° 线两侧机位跳跃且无过渡）, **When** 评估, **Then** axis_rule 门禁判 0
4. **Given** 情绪对齐 vs 背离两组分镜预演, **When** proxy.emotion_alignment 评估, **Then** 前者得分显著高于后者；对齐口径误差 < 1e-6；同预演重评估逐位一致
5. **Given** judge 委员会, **When** 成对比较, **Then** 3 提示词 × 冻结锚点集投票产胜率（平局 0.5 如实记录），提示词/锚点/摘要哈希入版本号，LLM 全过网关计费，同比较重跑逐位一致

### 用户故事 3 - 回放接入、无偏性验收与做梦进化（优先级：P3）

做梦工程师把分镜 Agent 接入自动进化：分镜树冻结入池（train/validation 分树沿用既有
口径）→ 做梦层生成分镜策略候选（镜头语言策略代码：景别节奏、备选数）→ 沙箱全池回放
（回放零渲染——ShotList 重放只读历史节点，审计断言）→ reward 口径复用 → 人工审批。
**一致性验收（发布阻塞）**：回放打分 vs 真实重跑 Kendall τ ≥ 0.95；注入偏差 100% 拒绝；
产出首轮进化曲线基线。分镜纳入 010 周校准盲评范围（judge 层与对齐代理需人评锚点）。

**为什么是这个优先级**: 自动进化是立项书 F3 的闭环含义与里程碑验收线；分镜是
"创意决策最靠前、评估最主观"的环节之一，无偏性验收是它接入发布的前置条件。

**独立测试**: 分镜夹具池跑无偏性对照（τ ≥ 0.95 + 注入拒绝）；一轮做梦（演示档）产出
reward 排名与首轮基线；010 盲评对 storyboard 正常产出。

**验收场景**:

1. **Given** 分镜模拟器池 ≥2 棵树, **When** 无偏性验收, **Then** 回放与真实重跑得分序列 Kendall τ ≥ 0.95
2. **Given** 注入偏差的评估器或篡改 judge 胜率, **When** 无偏性验收, **Then** 100% 被拒绝
3. **Given** 一轮做梦（分镜策略候选）, **When** 沙箱全池回放, **Then** 渲染调用计数恒为 0（审计断言），reward 口径与既有 Agent 一致
4. **Given** 首轮进化完成, **When** 查看产出, **Then** 首轮基线落盘（进化曲线起点）
5. **Given** 010 周校准, **When** 对 agent_id="storyboard" 生成盲评清单, **Then** 正常产出（仅 promo 特判拒绝）

### 边界情况

- 剧本段落为空或场景列表为空：执行前校验拒绝（0 渲染 0 成本），注明"剧本不足"
- 单场景剧本行数超过镜头数上限：策略产出受规则库约束的合法 ShotList，超出部分由覆盖率
  门禁暴露（不静默截断）
- 景别规则库与轴规则库冲突（如强制越轴才能覆盖某动作行）：以覆盖率门禁优先并在诊断中
  注明冲突——诚实暴露而非自动豁免
- judge 委员会平局（3 提示词 1.5/1.5）：胜率 0.5 如实记录，不二次裁决
- 预演渲染部分失败：失败条目成本照常入账，该备选记 FAILED，轮次继续
- 情绪基调缺失（剧本未标注）：proxy.emotion_alignment 标"不适用"注明，合成按适用分量归一
- 必覆盖清单为空（剧本未标注关键行）：coverage 门禁降级为纯场景级判定并在诊断中注明（不伪造关键行要求）
- 规则库配置缺失（镜头语法/轴规则）：合成评分拒绝启动并报错（不允许静默放过门禁）

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供分镜探索执行器：输入 = 剧本段落（场景列表 + 台词/动作行 + 情绪基调标注）+ 当前策略；输出 = 动态预演工件（animatic mp4 内容寻址）+ 成本入账 + 发现树节点
- **FR-002**: 分镜决策必须表示为 ShotList：镜头列表（景别档位/机位/运动/时长估算/所属场景与承接剧本行/备选条数）；规范化 JSON 相等 = 回放精确匹配键；合法性执行前校验：引用剧本行存在、场景承接完整、景别与机位档位合法——违规拒绝（0 渲染 0 成本）
- **FR-003**: 预演渲染适配器必须双实现：确定性模拟渲染器（ShotList → 分镜卡帧 → 拼接 + 可选临时音轨 → mp4 逐字节复现）+ 真实预演渲染服务骨架；同一套契约套件（无凭证跳过）
- **FR-004**: 预算门禁必须执行：单轮渲染 ≤ 配置上限，事务扣减防双花，轮次幂等；超界拒绝，FAILED 成本照常入账
- **FR-005**: 两段式落盘必须执行：渲染中间态落可变运营表，渲染与评估齐备后节点一次性 INSERT
- **FR-006**: 硬规则评估器必须实现三门禁：`rule.shot_grammar`（景别切换合理性规则库：相邻景别跳跃上限、同景别连续次数上限）、`rule.coverage`（**场景级 + 必覆盖清单**：每场景至少一镜为硬要求；剧本标注的"关键行"必须逐条有镜头承接；普通台词允许合并/拆分，不判违规）、`rule.axis_rule`（轴规则：越轴/跳轴检测）；gate 违规总分直接为 0；规则库与必覆盖清单全配置化
- **FR-007**: 代理评估器必须实现 `proxy.emotion_alignment`：以**预演画面帧（分镜卡像素，由 ShotList 确定性派生）**为输入，计算其视觉特征与剧本情绪基调的对齐度（CLIP 类对齐的确定性启发式代理，实现哈希即版本；真实模型替换 = 升版本，路径不变）；情绪缺失时"不适用"注明
- **FR-008**: judge 评估器必须实现 `judge.script_fit`：输入 = ShotList 结构化摘要（确定性摘要函数）+ 剧本段落文本，3 固定提示词 × 冻结锚点集成对比较投票；提示词/锚点/摘要函数三段哈希入版本号；LLM 全过网关计费；同比较重跑逐位一致（Mock 后端确定性）；平局 0.5 如实记录
- **FR-009**: 合成评分必须 = 三门禁 + 加权求和（权重形态配置）+ 定点归一（6 位小数）；全部评估器 deterministic=True、版本冻结
- **FR-010**: 分镜树必须接入回放模拟器池（observed/probe/规范化精确匹配/UNKNOWN 复用 002），回放零渲染零生成（审计断言）；train/validation 分树（最近树永远只做 validation）
- **FR-011**: 无偏性验收必须执行：回放 vs 真实重跑 Kendall τ ≥ 0.95 发布阻塞；注入偏差 100% 拒绝
- **FR-012**: 做梦层必须支持分镜策略进化（候选静态检查 → 沙箱回放 → reward 复用口径 → 人工 approve）；分镜必须纳入 010 周校准盲评范围；ShotList schema 必须稳定可供视觉线（004）与剪辑线（007）消费

### 关键实体 *（如果功能涉及数据）*

- **分镜脚本（ShotList）**: 一次分镜决策的完整表示——镜头列表（景别/机位/运动/时长估算/场景与剧本行承接/备选数）；规范化 JSON 即回放匹配键
- **剧本段落（ScriptSegment）**: 输入单元——场景列表，每场景含台词/动作行、**关键行标注（必覆盖清单）**与情绪基调标注
- **预演作业（StoryboardRenderJob）**: 预演渲染任务的运营中间态——ShotList 哈希、状态、预估/实际成本、工件引用；两段式落盘的可变侧
- **景别与镜头语法规则库（ShotGrammarRules）**: 配置形态——景别档位定义、切换合理性规则（跳跃上限、重复上限）、轴规则参数
- **分镜策略（StoryboardPolicy）**: 被进化对象——镜头语言策略代码（景别节奏、备选数，OptimalPolicy.solve() 形态）
- **预演工件（AnimaticArtifact）**: mp4 内容寻址引用——哈希、时长、镜头数、临时音轨标记

## 假设

- 真实预演渲染服务不接凭证：适配器骨架 + 确定性模拟双实现，真实接入是凭证配置动作（诚实边界同既有 Agent）
- 剧本段落以夹具提供；剧本 Agent（F4，降级模式）的真实产出契约在其接入时对齐，本特性只定义分镜侧输入 schema（场景/台词/动作行/情绪基调）
- 预演渲染的"程序化分镜卡"只需分镜属性可控（镜头数/时长/景别序列/情绪特征可从 ShotList 确定性复现），不追求真实画质
- 情绪对齐代理沿用既有"确定性启发式 + 实现哈希即版本"模式（004/006 同款），真实 CLIP 类模型替换 = 升版本，代码路径不变
- 分镜镜头清单的下游消费（视觉生成参数、剪辑候选镜头库）是各自 Agent 的接入事项；本特性只保证 schema 稳定与文档化
- judge 漂移自动检测（F7）不在本特性；分镜只保证纳入 010 盲评、锚点数据按 010 口径积累
- 分镜策略的"备选数"（镜头备选条数）是策略参数，其下游渲染/生成成本由各自 Agent 预算门禁约束
