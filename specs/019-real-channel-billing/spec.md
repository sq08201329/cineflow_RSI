## Clarifications

### Session 2026-09-23

- Q: 本特性的"渠道"具体指什么？ → A: **网关之外的付费调用面**——LLM 厂商 API（网关虽已代理调用，但其**计费与账单**在厂商侧，故其账单与价目口径归本特性）与媒体投放/平台数据接口。适配器**协议已在位**（`agents/*/platform/http_real.py` + `core/platform_http.py`），本特性做的是**对接与校准**：凭证、协议校验、计费口径核对，不是重写适配器。
- Q: 第一实例选哪条渠道，媒体渠道是否同批做？ → A: **本特性只做 LLM 渠道**（裁决 2026-09-23）。LLM 是唯一凭证已就绪、真实调用已被验证过的通道（016 实测单轮 $0.042），本特性的全部机制——前置预算门禁、账单导入、差异报告、两维价目、连续运行证据——都在它身上闭环；**媒体渠道不在本特性范围**，随 **G4（短剧真实投放）** 接入（其前置条件：账号、凭证、合规审查、真钱，与 G4 完全同源，同一份运营侧对接能力用一次）。**代价如实登记**：投放侧"厂商 API 与协议假设不符"（立项书 §7 列为**高**风险）的协议校准整条**结转 G4**，不在本特性退休。
- Q: 两维价目要改到什么程度？ → A: **改数据模型**。现状 `prices` 恰好两个键（`prompt_per_1k`/`completion_per_1k`，`core/llm_gateway/profiles.py:51`）、成本是一条硬编码线性式（`:92-96`）、快照形状按该两键固定（`:98-112`）。峰谷与缓存命中**在数据模型里无法表达**（仅在 `price_note`/`accounting_note` 以文字登记为"已登记限制"）。本特性让二者成为**可表达的价目维度**，并把价目快照形状随之升级——**历史节点的成本复算不得漂移**（原则一），故旧形状的解读必须保持原语义。
- Q: 预算门禁的粒度？ → A: **按环节分档 + 前置**。现状：四个平台阶段各有"逐轮逐环节"的估算门禁，但**LLM 这条腿完全没有上限**（网关只累计、从不拒绝），且没有 run 级分档额度。本特性补齐：每环节一档额度、调用**前**校验、超限即拒绝且不入账、额度随配置快照冻结留痕。
- Q: "连续运行 ≥1 周"靠什么证据？ → A: **新增按时间索引的渠道运行记录**。现状无任何时间序列证据件（`pilot/runs/{run_id}.json` 的 `run_id` 由配置指纹派生，重复运行覆盖同一文件）。记录必须可机检地覆盖 ≥7 天窗口。
- Q: 账单从哪来？ → A: 由**厂商侧的导出/接口**提供（控制台导出或 API，按渠道而定），本特性定义**规范化导入面**与来源留痕，不假设统一格式；未识别的格式**报错**而非静默跳过。
- Q: "连续运行 ≥1 周"的机检判定口径是什么？ → A: **覆盖 + 连续双条件**（收紧原 FR-012/SC-001 表述）：窗口内**真实运行**天数 ≥ `min_window_days`（7）**且**任一段断档天数 ≤ 配置声明的容差 `gap_tolerance_days`（0 = 不容断档）。累计够 7 天但有断档**不得**判定通过（假绿必须被拒）；断档仍**如实报出**（缺口区间与最长断档天数），**禁止**插值补齐。
- Q: 跨峰谷切换时刻的调用按谁的时点归属？ → A: **只按调用开始时刻**（收紧原 FR-011"或按厂商口径"的表述）：区间口径 `[start, end)`，一次调用只取一个格位、**不拆分**；厂商按 token 计费时刻或按账单周期摊分峰谷的口径**已登记但不实现**（不做双口径换算，偏差由校准记录登记），故归属取值域为单元素 `call_start`。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 最小规模校准与前置预算门禁（优先级：P1）🎯 MVP

运营工程师接入 LLM 渠道（本特性唯一的渠道面）：先在配置里声明该渠道的**按环节预算档**（缺项即报错），以**最小规模**跑一次真实调用；系统在调用**前**校验额度（超限即拒绝，不先花后报），调用后把**实测花费**与配置价目对照，产出**协议与计费口径校准记录**（偏差 + 口径备注）。校准未通过的渠道**不得扩量**（额度提升被拒绝并留下原因）。

**为什么是这个优先级**: 宪章原则三新增条款的第一句就是"调用前必须通过按环节分档的预算额度"与"必须先以最小规模验证协议与计费口径"。没有这一层，后面所有真实花费都没有护栏——这是本特性其余部分的前提。

**独立测试**: 用 Mock 后端 + 夹具账单可完整测试：额度声明缺失即拒绝启动；超限调用 0 次且不入账；最小规模调用后产出校准记录（含实测偏差与口径备注）；校准未过时扩量请求被拒并留痕。

**验收场景**:

1. **Given** 渠道已声明按环节预算档, **When** 一轮调用的预估额超出剩余额度, **Then** **调用前拒绝**、网关调用计数 0、成本入账 0、原因落盘
2. **Given** 渠道未声明预算档, **When** 装配, **Then** 显式报错拒绝启动（不取码内默认、不静默放行）
3. **Given** 最小规模真实调用完成, **When** 生成校准记录, **Then** 记录含配置价目、实测花费、偏差、口径备注与样本量，且 append-only
4. **Given** 校准未通过, **When** 请求扩量, **Then** 拒绝并留痕（升级=改配置，须有校准记录支撑）
5. **Given** 任一真实渠道调用, **When** 审计, **Then** 必先经门禁（静态/契约断言常驻，不得绕过）

### 用户故事 2 - 厂商账单导入与差异报告（优先级：P2）

财务/运营把厂商账单（控制台导出或 API 拉取）交给系统：系统按**规范化导入面**落成账单条目（含来源、批次、币种、计费口径留痕），随后产出**"网关记账 vs 厂商账单"差异报告**——逐项比对、差异分类（计费口径不同 / 未入账 / 时序错位 / 免费额度与折扣 / 币种与汇率）、给出**实测偏差**与**口径备注**；不可解释的差异**告警**。报告与导入记录 append-only、不可改写。

**为什么是这个优先级**: 宪章明写"网关记账**仅**为内部口径，**禁止**作为'成本已核实'的唯一依据"。没有账单证据链，算力杠杆比这类北极星指标只是自证；差异报告正是"可解释"的载体。

**独立测试**: 夹具账单（含刻意构造的口径差、缺失条目、时序错位、折扣）→ 差异报告逐项分类正确、不可解释项 100% 告警；篡改报告或改写系统字段被拒；网关记账不作为唯一依据（报告必须引用账单批次）。

**验收场景**:

1. **Given** 一份厂商账单, **When** 导入, **Then** 生成规范化条目（来源/批次/币种/口径备注齐备），重复导入同一批次被拒（append-only）
2. **Given** 同一周期的网关记账与账单, **When** 对账, **Then** 产出差异报告：逐项金额、差异分类、实测偏差、口径备注；**每条差异都必须有分类**（无分类即视为不可解释）
3. **Given** 不可解释的差异（分类缺失或超出阈值）, **When** 产出报告, **Then** 告警落盘且报告标记未解释项
4. **Given** 报告已产出, **When** 尝试改写或省略未解释项, **Then** 被拒（不可改写机检）
5. **Given** 未识别的账单格式, **When** 导入, **Then** 显式报错（不静默跳过、不部分导入后谎报成功）

### 用户故事 3 - 两维价目与连续运行证据（优先级：P3）

价目工程师把**峰谷时段**与**缓存命中**两个维度写进形态配置：峰时/谷时的费率不同，缓存命中与未命中不同；价目随快照冻结——此后改价**不影响**历史节点成本复算。同时系统按时间索引记录渠道运行（每次真实调用或每日汇总），使"LLM 渠道**连续运行 ≥1 周**"成为可机检的事实而非叙述。

**为什么是这个优先级**: 两维价目是"记账口径"的精度问题，建立在预算门禁与账单对账之上；连续运行证据是时间维度的积累，天然排在最后（且它是 G3 的关键验收之一）。

**独立测试**: 同一次调用在峰时/谷时与缓存命中/未命中四种组合下取价正确；改价后历史节点成本逐字节不变；价目缺维度即报错；运行记录机检**同时**要求覆盖 ≥7 天与连续（最长断档 ≤ 配置容差）——仅累计够天数但有断档**不通过**（缺口如实报出）。

**验收场景**:

1. **Given** 配置了峰谷与缓存命中两维价目, **When** 调用发生, **Then** 取价按其时段与缓存状态命中正确档位，且所用档位随快照冻结
2. **Given** 价目变更, **When** 复算历史节点, **Then** 历史成本逐字节不变（原则一）；新节点用新价目
3. **Given** 价目缺任一必需维度, **When** 装配, **Then** 报错拒绝启动
4. **Given** 渠道运行记录, **When** 机检连续运行窗口, **Then** **同时**满足覆盖 ≥7 天与连续（最长断档 ≤ 配置容差）即通过；仅累计够天数但有断档**不得**通过，断档如实报缺口（不得插值补齐）
5. **Given** 调用跨越峰谷切换时刻, **When** 取价, **Then** 按时段边界归属明确（不据"开始时刻"含糊带过），口径写入报告

---

### 边界情况

- **账单迟到与周期错位**：账单周期与记账周期不一致时，差异报告必须按"未结账"分类并留待下期对账，**不得**据此判定网关记账有误
- **免费额度、试用、折扣与返券**：计入差异分类并写口径备注，不得静默按 0 记账
- **币种与汇率**：账单币种与记账币种不一致时，必须记录所用汇率来源与时点；缺来源即报错
- **缓存命中的计费口径**：厂商是否对命中计费、按什么折扣计费，属**口径校准**内容；未校准时命中档位**不得**默认按 0
- **渠道不可达**：真实渠道失败**不得**静默回落模拟后端并照常计费（回落必须显式声明且标注来源）
- **额度耗尽后的行为**：拒绝而非排队、而非降级为模拟
- **认证失败与配额限制**：与"预算超限"区分开，各自有独立错误分类（否则对账无法归因）
- **多实例并行**：同一渠道的并发调用共享同一额度（额度校验不得只在进程内）
- **未校准即扩量**：任何提高额度的动作必须引用校准记录；无记录即拒绝
- **媒体渠道不在本特性**：实现时**不得**为媒体/生成侧渠道发明前置条件（账号、凭证、平台名），也不得把投放相关假设写进本特性的配置与代码——它们随 G4（媒体渠道）与 G2（生成侧真实渠道）各自的渠道需求接入

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须为**真实渠道（本特性 = LLM 渠道）**提供**按环节分档的预算额度**，额度必须在形态配置中声明（缺项即报错，不取码内默认）；额度随配置快照冻结留痕
- **FR-002**: 额度校验必须**前置**：在真实渠道调用发生**之前**判断（预估额 vs 剩余额度），超限即拒绝并记录原因；**禁止**先花后报；被拒绝的调用网关计数与成本入账恒为 0
- **FR-003**: **LLM 腿必须同样受额度约束**（现状：网关只累计、从不拒绝）——含 `llm` 角色在内的全部真实调用都要过门禁
- **FR-004**: 真实渠道调用**必须**先以**最小规模**跑通并产出**协议与计费口径校准记录**（配置价目 / 实测花费 / 偏差 / 口径备注 / 样本量 / 时间）；校准记录 append-only
- **FR-005**: **未通过校准的渠道不得扩量**：提高额度的动作**必须**引用校准记录，无记录即拒绝并留痕
- **FR-006**: 系统必须提供**厂商账单规范化导入面**：账单条目含来源渠道、账单批次、币种、周期、原始行摘要与计费口径备注；未识别格式**报错**，不得静默跳过或部分导入后谎报成功；同一批次重复导入被拒
- **FR-007**: 系统必须产出**"网关记账 vs 厂商账单"差异报告**：逐项金额比对、差异**分类**（计费口径 / 未入账 / 时序错位 / 免费额度与折扣 / 币种汇率 / 未结账）、**实测偏差**与**口径备注**；**每条差异必须带分类**，无分类即视为不可解释
- **FR-008**: 差异报告必须可**告警**（不可解释项或超出阈值即告警落盘）；网关记账**禁止**作为"成本已核实"的唯一依据——报告必须引用账单批次与来源
- **FR-009**: 差异报告、账单导入记录与校准记录必须 append-only、不可改写（镜像 009/017 的 `system_digest` 机检范式），人工批注只允许追加
- **FR-010**: 价目**必须**支持**两维表达**：峰谷时段档位与缓存命中/未命中档位；缺失维度即报错；价目随快照冻结，**历史节点成本复算逐字节不变**（原则一），旧快照形状的解读保持原语义
- **FR-011**: 跨峰谷切换时刻的调用必须**明确归属**：本特性**按调用开始时刻**判定（区间口径 `[start, end)`，一次调用只取一个格位、**不拆分**），归属口径必须写进报告口径备注；厂商按 token 计费时刻或按账单周期摊分峰谷的口径**已登记但不实现**（不做双口径换算，偏差由校准记录登记）——归属取值域因此为单元素 `call_start`，不得含糊、不得静默换口径
- **FR-012**: 系统必须提供**按时间索引的渠道运行记录**，使"连续运行 ≥7 天"可机检：判定**必须同时满足覆盖与连续**——真实运行天数 ≥ 配置下限（`min_window_days`）**且**任一段断档天数 ≤ 配置容差（`gap_tolerance_days`，0 = 不容断档），累计够天数但有断档**不得**判定通过；有断档必须如实报缺口（缺口区间与最长断档天数），**禁止**插值补齐
- **FR-013**: 真实渠道失败**禁止**静默回落模拟后端并照常计费；回落必须显式声明并标注来源（模拟/真实）
- **FR-014**: 全部新参数（额度、价目维度与档位、校准门槛、差异阈值、账单导入配置）**必须**形态配置化；两形态均须声明；**不得**新增形态分支代码
- **FR-015**: 必须提供 CLI（额度查看 / 校准 / 账单导入 / 对账报告 / 运行记录）与离线演示，退出码语义与既有工具一致

### 关键实体 *（如果功能涉及数据）*

- **真实渠道（Channel）**: 网关之外的付费调用面——标识、适配器、凭证环境变量名、计费口径、校准状态、连续运行窗口（本特性只实例化 LLM 渠道）
- **预算档（BudgetTier）**: 按环节分档的额度——环节、额度上限、时间窗、当前余量、拒绝计数
- **价目表（PriceBook，两维）**: 峰谷档位 × 缓存命中档位；随快照冻结；历史复算不漂移
- **厂商账单（VendorBill）与账单条目（BillEntry）**: 来源渠道、批次、币种、周期、原始行摘要、口径备注；append-only
- **差异报告（ReconciliationReport）**: 周期、逐项比对（网关记账 vs 账单）、差异分类、实测偏差、口径备注、未解释项、告警
- **校准记录（CalibrationRecord）**: 渠道、配置价目、实测花费、偏差、口径备注、样本量、时间；扩量的先决条件
- **渠道运行记录（ChannelRunLog）**: 时间索引的真实调用记录（渠道、时刻、结果、花费来源）；连续运行窗口的机检依据

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书周 5~8）：**LLM 真实渠道连续运行 ≥1 周**（运行记录机检**同时**满足覆盖 ≥7 天与连续——最长断档 ≤ 配置容差；断档如实报缺口、不插值）；媒体渠道随 G4，其协议校准风险已登记结转
- **SC-002**: 账单对账**差异可解释率 100%**——每条差异都有分类与口径备注；不可解释项 100% 告警落盘
- **SC-003**: **两维价目可表达**：峰谷 × 缓存命中四种组合取价正确；改价后历史节点成本**逐字节不变**；缺维度装配即报错
- **SC-004**: 超预算的真实调用次数恒为 **0**（前置拒绝率 100%，拒绝时网关计数与入账均为 0）；未声明额度即拒绝启动
- **SC-005**: 未通过校准即扩量的次数恒为 **0**（提升额度无校准记录支撑时 100% 拒绝并留痕）
- **SC-006**: 差异报告 / 账单记录 / 校准记录**改写与省略尝试 100% 被拒**（不可改写机检）；重复导入同一账单批次 100% 被拒
- **SC-007**: 未识别账单格式 100% 显式报错（零静默跳过、零"部分导入后成功"）
- **SC-008**: 单元测试覆盖率 ≥ 85%（口径不降，含 web）；对抗测试与无偏性门禁不放松
- **SC-009**: 账单对账周期内，网关记账金额与账单金额的**偏差原因可逐条指认**（分类 + 口径备注 + 实测数值），不允许"差额不明"的条目

## 假设

- **本特性的渠道面 = LLM 渠道**（唯一凭证已就绪、真实调用已被验证者）。媒体投放平台随 **G4** 接入，生成侧真实厂商按 **G2** 的渠道需求接入——本特性**不为其发明前置条件**，也不重写已在位的适配器协议（`agents/*/platform/http_real.py`、`core/platform_http.py`、双实现契约套件）
- 真实渠道的凭证与账号由**运营侧**提供
- 首次接入按**最小规模**起步（参考二期实测：单轮真实 LLM 花费 $0.042 量级），扩量须有校准记录支撑
- 账单由厂商侧导出或接口提供，**格式因渠道而异**；本特性定义规范化导入面，不假设统一格式
- 单币种记账为主，多币种以"记录汇率来源与时点"的方式表达（不做汇率引擎）
- 不做自动比价路由、不做多租户、不做公网服务化（三期不做项不变）

## 开放问题（需人工裁决）

1. **预算档的最终数字**：规格按"按环节分档 + 先最小规模"写成机制，具体额度（LLM 每环节上限）需运营侧给定；未给定前以最小规模档运行并如实标注"未标定"，**不得**在规格或代码里发明数字。
2. **账单获取方式**：控制台导出（人工上传）还是 API 拉取（自动）——决定导入器的第一实现形态；建议先做导出（不引入新凭证面），API 作为第二实现。
