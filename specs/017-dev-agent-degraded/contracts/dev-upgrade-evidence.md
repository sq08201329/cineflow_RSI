# 契约：开发 Agent 升级判据材料（全量阈值 + 逐项可评价性 + 覆盖与留痕）

> 对应规格 US3 / FR-010、SC-006。实现：通用件 `core/degraded/evidence.py`（判据项抽象）+
> 业务件 `agents/dev/upgrade_evidence.py`（登记两类来源缺失）；schema 与 009 同构。

## C16 阈值全量声明 + 逐项可评价性

- 阈值项（相关性目标、最小样本量、门禁违规率上限、漂移带、010 信度目标等）**必须**全部在
  `dev` 段判据配置中声明，**缺任一项即报错**（不得静默"无判据"；口径同
  `agents/screenplay/upgrade_evidence.py:74` `_require_thresholds`、`:89` `_require_reliability_target`）
- 判据项 = 键 + 阈值键 + 提供者可调用（计划研究决策 3）；计算时逐项输出**实测值**或
  **"无法评价（来源缺失）"** + 缺失原因；**无空白、无省略阈值项**（FR-010 / SC-006）；
  阈值项清单本身即继续观察条件的量化基线
- 阈值快照随材料冻结（不可变快照，含当时阈值），此后配置变更不影响已产材料

## C17 系统结论恒不为"达标"

- 结论字段取值**不含**"达标/meets"：可评价但未过阈 ⇒ `below`（不达标）；存在无法评价项 ⇒
  `insufficient`（证据不足）——二者**都不得**被解读为可升级（FR-010、原则六；取值沿用 009
  `meets|below` 先例并去掉 `meets`，字段名 plan 未定，属本契约判断项）
- 系统字段不可改写：写入"达标"、省略某阈值项或手工改写系统字段 ⇒ **拒绝**（机检口径镜像
  `agents/screenplay/upgrade_evidence.py:34` 的 `_SYSTEM_FIELDS` + `:141` `_system_digest`）
- 人工推翻必须留痕（人/时间/理由）且**不改变**系统字段（`:257` `override_conclusion`）；
  推翻后系统字段逐字节不变（SC-006）
- 材料为 **append-only 不可变快照**：同周期已存在即拒绝（`:238`）

## C18 缺失来源登记 + 继续观察条件

- 两类来源缺失**必须逐项登记**（登记为"无法评价（来源缺失）+ 原因"，不是留空）：
  ① **无 judge 层** ⇒ 无 012 漂移材料（漂移项无法评价，不得据未测量项达标）
  ② **010 按设计排除本 Agent** ⇒ 无信度数据（`specs/010-weekly-calibration/spec.md:157`）
- 继续观察条件 = **待补齐阈值项的量化清单**：宪章原则六（v1.2.0 新增条款；现行宪章 v2.0.0）明写"**维持降级则必须
  记录未达标的具体判据与继续观察条件**"（`.specify/memory/constitution.md:127-130`；本次修订
  记录 `:6`，版本 `:222`）——本特性不补齐通道，只如实登记缺口
- 材料按 agent 分目录：`calibration/upgrade-events/dev/{period}.json`（研究决策 5）——
  009 现有路径不含 agent id，同 ISO 周双写会互相覆盖（本特性须同步 009 侧路径与其测试）
- 若改动 009 既有路径，必须同步更新 009 的测试与 quickstart 验证记录（spec 边界情况）；
  010 规格**不改**、不引入锚点层（既定选择，补齐另立决议）

### 场景

1. 合规周期 → 材料字段齐全、阈值快照齐全，每个阈值项均有"实测值或无法评价"标注
2. 漏配任一阈值项 → 产出报错（不产材料）；材料中无空白项、无省略项
3. 无 judge / 未接 010 → 对应项标"无法评价（来源缺失）"+ 缺失原因，系统结论非"达标"
4. 尝试写入"达标"或改写系统字段 → 拒绝；人工推翻留痕后系统字段逐字节不变
5. 同周期重复生成 → 拒绝（不可变快照，只增不改）
