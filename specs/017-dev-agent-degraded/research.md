# 调研：开发 Agent 降级模式（017-dev-agent-degraded）

> 阶段 0 产出。每条决策 = 结论 + 理由 + 被否决的替代方案。规格依据见 [spec.md](spec.md)，
> 架构落点见 [plan.md](plan.md)。

## 决策 1：通用件落点 = `core/degraded/`（而非复制进 `agents/dev/`）

**结论**：把 009 的四个降级机制模块（`policy_versions` / `sandbox_compare` / `adoption` /
`upgrade_evidence`）下沉为 `core/degraded/{policy,compare,adoption,evidence}.py`，参数化为
`agent_id` + 注入可调用（匹配键函数、评估器装配、判据项提供者）；`agents/screenplay/` 与
`agents/dev/` 各自保留薄适配。

**理由**：这四个模块承载的是**降级模式纪律**本身（append-only 留痕、回放零 LLM、人工采纳才
移动部署指针、判据材料不可改写），不是某个 Agent 的业务。第二个降级 Agent 一出现，复制即产生
两份会各自漂移的治理实现，而两份实现之间的分歧不会被任何测试发现——这正是 009 的判据材料
路径缺陷（见决策 5）暴露出的同类问题。依赖方向上，它们是业务无关的，落在 `core/` 与既有的
`core/deployment/`（跨 Agent 的部署门禁与禁止名单同名册）一致；且 `core/degraded/` 不 import
`agents.*`，符合原则五的单向依赖。

**被否决**：
- *复制进 `agents/dev/`（009 式重复）*：省一次改造，但从此每处纪律修正要改两遍；且契约 C2 要求
  009 行为等价，与其留两份不如让 009 真正复用。
- *`agents/degraded/` 共享包*：新增一个既非 core 也非单 Agent 的目录类别，与宪章"新增目录必须
  先归入 core 或 agents"的分类惯例摩擦；且这些件确实与业务无关，放 core 更准确。

## 决策 2：参数化方式 = 显式注入，不用继承或注册表

**结论**：通用件通过形参接收 `agent_id`、`match_key` 可调用、评估器装配可调用、判据项提供者
列表；不引入基类继承、不引入插件注册表或入口点发现。

**理由**：只有两个消费者，注入即可满足；隐式发现机制会让"谁在跑"变得不可静态阅读，反而削弱
可审计性（本项目大量门禁依赖静态断言）。

**被否决**：*抽象基类 `DegradedAgent`*（为两个消费者引入继承层次，且会把业务件塞进 core 的
接口约定）；*注册表 + 装饰器*（隐性耦合，静态断言难写）。

## 决策 3：判据材料引入"判据项（evidence item）"抽象

**结论**：判据材料 = 阈值快照 + **判据项列表**；每项 = `key` + `threshold_key` + 提供者可调用；
无提供者或提供者返回"不可评价"时，该项输出 `无法评价（来源缺失）` 与缺失原因。

**理由**：规格 FR-010 要求"全量声明阈值 + 逐项可评价性"。009 的实现把四项判据写死在函数里
（judge 信度 / 漂移 / 门禁违规率 / 样本量），结构上无法表达"这一项在本环节根本取不到数"。
开发 Agent 无 judge、无锚点，正是这种情形——不抽象就只能另写一份判据材料，与规格明写的
"沿用同一套 schema"冲突，且未来补齐锚点后还要二次改结构。

**被否决**：*dev 侧另写一份判据材料*（schema 分叉）；*把不可评价项整段省略*（材料失去可比对
基线，违反 FR-010"不得留空或省略"）。

## 决策 4：模拟数据源 = 确定性函数 + 夹具，配置参数化

**结论**：`agents/dev/signals.py` 提供两个确定性数据源：同类型票房回归预测与舆情热度检索；
输入 = 配置参数（基线、灵敏度、夹具表）+ 工件中的方向标识；输出 = 分量值 + **来源标注**
（`simulated=true`、来源说明、"非真实商业数据"）。

**理由**：仓库内不存在真实票房数据库与舆情接口（全仓 `票房`/`舆情` 仅出现在设计文档）。
技术方案对该环节规定的两个代理信号只能以确定性实现落地，否则回放打分不成立（原则一要求
回放打分评估器必须确定性）。数据源参数即行为口径：变更必须升评估器版本（契约 C9）。

**被否决**：*接真实数据接口*（属 G3 的渠道范围，且受原则三新条款的预算门禁与账单对账约束，
本特性不得绕过）；*提前预留可插拔数据源接口*（规格 Clarifications 明确不做；接口形状应在 G3
真正替换时按真实渠道形状再定）。

## 决策 5：判据材料按 agent 分目录，并迁移 009 的既有路径

**结论**：证据文件从 `calibration/upgrade-events/{period}.json` 改为
`calibration/upgrade-events/{agent_id}/{period}.json`；**不读旧路径**（不做 legacy 兼容），
避免同一周期出现两份材料的二义性；迁移同步更新 009 的测试断言、`quickstart.md` 验证记录与
`README.md` 中写死的路径字面量。

**理由**：现状 `agents/screenplay/upgrade_evidence.py:26,237` 的文件名不含 agent id，第二个
降级 Agent 写入同一 ISO 周会**静默覆盖**第一个 Agent 的材料——这是判据材料作为审计证据的硬缺陷。
规格"边界情况"已授权本特性修改该路径并要求同步 009 的记录。

**被否决**：*dev 侧单独用新目录、009 保持旧路径*（两套口径并存，且覆盖风险仍在）；*保留旧路径
只读兼容*（同周期两份材料，读者无法判断哪份是权威）。

## 决策 6：回放对比的最小池门槛

**结论**：可比对树数 < 配置下限（`dev.min_comparable_trees`）即**拒绝产出对比报告**并报错，
错误信息含实测树数与门槛值；达到门槛才写报告。

**理由**：开发 Agent 冷启动时池里可能只有引导树，样本极少时"新版本更好"只是噪声。与既有
"无偏性未过不得产出对比报告"（`agents/screenplay/sandbox_compare.py:227`）同构，属本项目
"证据不足即不产出"的门禁风格。

**被否决**：*照常产出 + 标注样本不足*（报告一旦落盘就会被引用，标注拦不住）；*无门槛*
（把噪声当证据）。

## 决策 7：匹配键只含策略可复现的结构键

**结论**：`slate_match_key = {policy_version, model, temperature, max_tokens, 立项约束摘要,
组合区间摘要, plan_digest}`；**不含**生成产物摘要与上游工件哈希。

**理由**：沿用 009 的口径（`agents/screenplay/loop.py:139-162`，见二期总览决策 1/2）：匹配键
必须只含策略能复现的结构键，否则回放命中率崩塌为 UNKNOWN。开发 Agent 无阶段划分，故键里以
"立项约束 + 组合区间"替代 009 的 `target_duration_min`。

**被否决**：*把生成文本摘要入键*（生成非确定性，命中率归零）。

## 决策 8：形态参数进配置，并显式放开 `test_form_switch` 的顶层差异键集

**结论**：`dev` 段（组合条目数区间、进入生产标记数区间、最小可比对树数、组合约束、门禁阈值、
判据阈值、模拟源参数）进两套 `configs/*.yaml`；`evaluator_weights.dev` 一并声明。因两形态取值
确有差异，把 `dev` **显式加入** `tests/unit/test_form_switch.py` 的顶层差异键集字面量，并把
`dev` 纳入该测试的权重差异循环。

**理由**：原则五要求形态差异由配置承载。差异键集是**治理门禁**，不能靠"两形态填一样的值"绕过
（那等于把"可配置"变成空话），也不能隐性放宽——所以是对门禁做一次有记录的、范围明确的扩展。

**被否决**：*让两形态 `dev` 段取相同值以规避改测试*（第一个真实差异就会撞门）；*把 dev 参数
塞进已有的 `screenplay` 段*（语义错位，且归属混乱）。

## 决策 9：配置完整性门禁的字面量清单必须登记 `dev`

**结论**：`tests/unit/test_config_integrity.py` 的 `CONFIG_CLASSES`（加载器清单，`:23`）、
`WEIGHT_AGENTS`（权重覆盖清单，`:39`）、`REQUIRED_PATHS`（缺项即红样例，`:42`）三处字面量
必须同步登记 `dev`（`("dev","agents.dev.config","DevConfig")`、权重段、至少一条 dev 缺项样例）；
并判定 `tests/conftest.py:3151` 的 `_MINIMAL_MOVIE_CONFIG`（"只含加载器必需段"）是否需要补
`dev` 段。

**理由**：该测试是本仓"两形态都过同一加载器 + 缺项即报错"的唯一机检面；新加载器不登记即
**逃逸门禁**（无测试会发现 dev 段在某一形态缺失或解析器静默取默认）。`test_form_switch` 只管
形态差异键集与权重差异，覆盖不到加载器完整性。

**被否决**：*只写新的 `test_dev_config.py`*（新测试不会覆盖既有门禁清单，等于让 dev 成为唯一
不被完整性门禁约束的配置段）。

## 决策 10：回放对比路径的策略执行隔离（原则四）——已裁决走宪章豁免，并附两项落地义务

**结论**：009 的降级回放对比在**同进程**执行人工策略（`agents/screenplay/sandbox_compare.py:112`
的 `exec(compile(...))`，全程不触 `core/sandbox/`；`core/replay/pool.py:36 build()` 返回同进程
`ReplaySimulator`），与宪章原则四第一、二条冲突。**裁决：走路径 (b)——宪章修订豁免**，宪章升
**v2.0.0**（MAJOR），原则四新增"人工编写的降级模式策略"显式例外。

**关键事实（决定了例外的形态）**：该路径**不向策略交付任何环境对象**——`replay_policy` 只调用
`policy.plan(inputs, config)` 取结构键，`probe` 由**宿主**代为执行（`sandbox_compare.py:169`），
策略既不 `observed()` 也不 `probe()`，未揭示状态 (`_latent`) 天然不可达。故冲突**只在容器隔离**，
信息隔离不但未放宽，反而比沙箱更严（策略零信息通道）。例外条款即按"信息通道而非信任度"划定边界。

**附带的必须落地义务**（009 现行亦缺，由 017 的 `core/degraded/compare.py` 与契约 C14 落地）：
① 策略执行**必须**带执行超时（静态检查不禁循环）；② **必须**有断言守护"不向策略交付任何环境对象"。

**被否决**：*路径 (b) 之前的"默认沿用 009 现状"*（分析阶段判定为 CRITICAL：会把偏差固化成第二个
消费者）；*路径 (a) 沙箱化 + IPC*（该路径本无对象传递，为纯规划调用引入容器生命周期与 IPC，
成本与收益不成比例）；*plan 的宪章检查里把原则四标成"满足"*（与事实不符，已改为"依 v2.0.0
例外条款成立 + 附两项落地义务"）。

## 决策 11：明确不做（写进规格与计划防回潮）

- 真实票房 / 舆情数据源接入（属 G3；受原则三新条款约束）
- judge 层与人类锚点（技术方案只为开发 Agent 规定代理信号一层；010 明确排除）
- 修改 010 规格或把开发 Agent 拉入周校准
- pilot 七阶段链插入、选题产出 → 剧本输入的字段级交接声明（属 G2 / 018）
- 可插拔数据源接口（待 G3 按真实渠道形状再定）
- 开发 Agent 的自动进化（宪章原则六 + 立项书 §3.2 三期不翻案）
