## Clarifications

### Session 2026-09-23

- Q: 开发 Agent 是否引入 judge 层与人类锚点？ → A: **都不引入**。技术方案 §2.2 只给开发 Agent 规定"代理信号"一层（其余六个 Agent 均为四层），且 010 规格明确把开发 Agent 排除在周校准之外（`specs/010-weekly-calibration/spec.md:157`）。故本特性的评估器组合 = **2 硬规则门禁 + 2 代理模型**，无 judge、无 human 锚点——把"信号噪声最大"如实做成可审计的形态，而不是补齐一层看起来完整的假信号。
- Q: 代理信号的"历史票房回归 / 舆情热度"数据从哪来？ → A: 以**模拟数据源 + 夹具**起步（确定性、零边际成本、可回放），并按 015/016 的"模拟生成"标注纪律在产物与报告上如实标注数据来源与"非真实商业数据"。真实票房库/舆情接口属"网关之外的厂商 API/数据接口"，其接入受宪章原则三新条款（预算门禁 + 账单对账）约束，归 G3 的渠道范围，**不在本特性**。
- Q: 本特性是否把 `dev` 插入 pilot 七阶段链？ → A: **不插入**。三期立项书把"跨环节交接契约扩展（017 的选题产出 → 剧本输入）"划在 G2（018）行内；本特性只保证选题工件可导出、schema 版本化、字段足以支撑下游交接声明。
- Q: 升级判据材料对开发 Agent 如何取数？ → A: **如实登记证据来源缺失**——无 judge 层 ⇒ 无 012 漂移材料；010 明确排除 ⇒ 无信度数据。判据材料必须逐项标注"来源缺失"且系统结论**不得**为"达标"；这正是宪章原则六新条款"维持降级则必须记录未达标的具体判据与继续观察条件"的落点。
- Q: `agent_id` / 目录 / 配置段用什么？ → A: 统一用 **`dev`**。`configs/movie.yaml:386` 与 `configs/shortdrama.yaml:393` 的 `no_auto_evolve_agents` 已含 `dev`，`core/deployment/config.py` 的禁止名单读同一份列表、`core/deployment/gate.py:82` 以其为最高优先级，`tests/contract/test_screenplay_no_auto_evolve.py:30` 已按 `("screenplay","dev")` 参数化。沿用该 id，避免出现禁止名单与门禁对不上的第二套口径。
- Q: 选题产出的粒度（阶段划分）？ → A: **单一产出**（一份立项组合工件），不设多阶段。技术方案未给开发 Agent 规定分段产出，且宪章要求复杂度被论证（YAGNI）——探索维度体现在"探索哪些题材方向、分支数多少"（即策略的探索对象），不需要跨阶段树。
- Q: 开发 Agent 的升级判据是否现在补齐证据来源（纳入 010 周校准盲评 / 引入锚点层）？ → A: **不补齐，维持 010 现行排除**。本特性不含任何人类锚点层、不改动 010 规格（`specs/010-weekly-calibration/spec.md:157` 保持原样）。判据材料必须逐项登记两类来源缺失（012 漂移材料：无 judge 层；010 信度数据：规格明确排除）并写明继续观察条件；补齐锚点通道（含是否需要 judge 层）属独立决议事项，由该决议决定是否另立特性。
- Q: 开发 Agent 一轮产出的主交付物是什么——一份"立项组合"决策，还是一个"选定的选题"？ → A: **立项组合为交付物**。单份工件承载"本轮推荐立项的多个选题"（每条含方向标识、论证要点、评估分量、可移交下游的剧本输入要点）与组合层约束校验，并在组合内标记"本轮进入生产"的那一个供下游取数；不拆成组合与单选两套工件/schema。
- Q: 冷启动时回放池树数不足，回放对比应拒绝产出还是照常产出？ → A: **最小池门槛**。可比对树数低于配置下限即拒绝产出报告并明确报错（门槛按形态配置），不得用极少样本产出看似权威的结论；演示与 quickstart 先跑够轮次再出报告，与既有"无偏性未过不得产出对比报告"的门禁同构。
- Q: 判据材料里的"判据阈值"如何声明（本环节无 judge、无信度数据）？ → A: **全量声明 + 逐项可评价性**，与既有降级 Agent 同一套判据材料 schema。相关性目标、最小样本量、门禁违规率上限、漂移带等阈值**必须**全部配置声明（缺失即报错），计算时逐项输出"实测值"或"**无法评价（来源缺失）**"并标注缺失原因；系统结论恒为"不达标/证据不足"。不采用"只声明可计算项"或"不设阈值"的简化形态——那会让继续观察条件失去可对比的基线，补齐锚点通道后又要改 schema。
- Q: 代理信号以确定性"模拟数据源"起步这个口径可否接受？ → A: **接受，模拟数据源起步**（并记为已裁决事项，不再是待定假设）。产物、对比报告、判据材料三处标注数据来源与"非真实商业数据"；真实数据接入归 G3。**明确不做**"提前预留可替换数据源接口"——按宪章"复杂度必须被论证"，接口形状应在 G3 真正替换时按真实渠道的形状再定（届时换实现并升评估器版本，不改评估器算法）。

## 用户场景与测试 *（必填）*

### 用户故事 1 - 立项组合产出与全量记录（优先级：P1）🎯 MVP

选题线运行一轮产出：当前策略（**人工编写**的题材方向探索策略：探索哪些题材方向、分支
数、组合取舍）对输入（立项约束 + 形态参数）产出**立项组合**工件（本轮推荐立项的多个
选题：各带评估分量 + 可移交下游的剧本输入要点；组合内标记"本轮进入生产"的那一个）→
执行器经 LLM 网关生成（计费、缓存、重试）、成本入账 → 硬规则门禁评估 → 节点一次性完整
INSERT（发现树全量记录）。生成中间态落可变运营表。**本环节不做自动策略搜索**：策略来源
是人，节点携带 `policy_version` 指向人工策略版本。

**为什么是这个优先级**: "记录"是降级模式的第一半——没有全量落盘的选题树，回放沙盘与
判据材料都无从谈起；这也是一条链上唯一能证明"开发环节到底有多弱"的证据基础，而不是
靠断言"信号噪声大"。

**独立测试**: 用确定性 Mock 网关 + 人工策略跑一轮产出：立项组合工件内容寻址落库、评估
分量入 `eval_breakdown`、成本入账（含失败调用）、两段式落盘逐断言；不接回放与对比报告
即可交付"选题产出可记录"的价值。

**验收场景**:

1. **Given** 立项约束输入 + 人工策略版本, **When** 执行一轮产出, **Then** 立项组合工件落树（节点含 `policy_version` = 人工策略版本），成本入账，`eval_breakdown` 含全部门禁与代理分量
2. **Given** 同一轮次重复触发, **When** 幂等检查, **Then** 不重复生成节点、不重复扣费（沿用既有幂等派生口径）
3. **Given** 网关返回失败, **When** 记录, **Then** FAILED 节点落盘且成本照常入账（原则二）
4. **Given** 任一节点, **When** 查询, **Then** 可回溯到产出它的策略版本（人工版本同样版本化，BLAKE3 前 12 位）
5. **Given** 立项组合工件含模拟数据源产出的分量, **When** 读取产物与报告, **Then** 数据来源与"模拟非真实"标注可机读可见（不得让模拟信号看起来像真实商业数据）
6. **Given** 组合内存在达到进入生产条件的选题, **When** 产出工件, **Then** "本轮进入生产"标记数量落在配置区间且指向组合内已存在的选题

### 用户故事 2 - 选题评估器组合与合成评分（优先级：P2）

评估工程师为选题节点打分：硬规则二门禁——`rule.slate_structure`（立项组合工件结构完整性：
组合条目数落在配置区间、方向标识唯一、必填字段齐全）、`rule.slate_combination`
（**组合层核心门禁**：组合内方向的多样性/去重率、数量上限、进入生产标记数量与指向合法性
均符合形态配置）；代理模型——`proxy.genre_regression`（历史同类型票房回归预测）、
`proxy.buzz_heat`（舆情检索热度）。合成 = 门禁 + 加权求和（权重形态配置）+ 定点归一
（6 位小数）。**没有 judge 层、没有人类锚点**（见 Clarifications 第 1 条）——两个代理模型
即为本环节的全部"商业信号"，其确定性实现是回放可打分的前提（原则一）。

**为什么是这个优先级**: 评估信号质量正是"是否升级为自动进化"判据的来源；本故事把"信号
有多弱"变成可测量的数据。技术方案 §2.2 对该环节的警示（信号噪声最大）只有落成可机读的
分量，才谈得上诚实边界。

**独立测试**: 对同一立项组合工件重算各分量逐位一致（确定性）；注入结构违规（条目数越界/
方向标识重复/字段缺失）与组合违规（分向重复、标记数量越界或指向不存在条目）→ 门禁 100%
判 0（gate 短路不跑后续）；注入票房回归偏离与热度异常样本 → 对应代理分量命中；合成定点
归一与总分可复算。

**验收场景**:

1. **Given** 合规立项组合工件, **When** 计算, **Then** 四分量齐全且 `eval_breakdown` 含各评估器 `evaluator_id@version`
2. **Given** 条目数越界或方向标识重复, **When** 门禁评估, **Then** 总分直接为 0（gate 短路，不跑后续分量、不浪费调用）
3. **Given** 组合内方向重复率超限或进入生产标记数量越界, **When** 组合门禁评估, **Then** 总分直接为 0 且原因指明具体违规项
4. **Given** 同输入重跑, **When** 重算, **Then** 各分量与合成总分逐位一致（确定性、定点 6 位）
5. **Given** 评估器实现变更, **When** 注册, **Then** 新 `evaluator_id@version`；同 id 同 version 重复注册被拒（原则一）
6. **Given** 权重或阈值变更, **When** 装树, **Then** 以配置快照冻结进 `config_snapshot`，历史节点得分不受影响

### 用户故事 3 - 回放沙盘与人工改策略闭环（优先级：P3）

选题负责人改进策略：人工编写/修改策略版本 → 提交到策略历史（版本 = 源码 BLAKE3 前 12 位，
`parent_version` 指向改进来源）→ 过静态检查（复用 002：import 白名单、禁网络/文件 IO、
接口签名）→ 在模拟器池上**回放对比**（新版本 vs 当前部署版本，产出对比报告：逐树得分、
分项评估器差异、pareto_auc 曲线对比）→ **人工决定采纳**（采纳才更新部署指针；拒绝则记录
理由）。**硬约束**：dreaming 层**禁止**为开发 Agent 生成候选策略、禁止自动排名与自动部署
（配置名单 + 显式拒绝 + 审计断言三重机检）。同时系统产出**升级判据材料**：全量声明判据
阈值，逐项给出"实测值 / 无法评价（来源缺失）"（无 judge ⇒ 无 012 漂移材料；010 排除 ⇒
无信度数据）+ 代理分量的可复现分布 + 系统结论（**不得为"达标"**）+ 继续观察条件，供
"是否升级为自动进化"的独立决议使用（升级本身不在本特性）。

**为什么是这个优先级**: 这是降级模式的第二半"回放沙盘"——人做决策、系统给零成本的对比
证据；也是宪章原则六"诚实边界"的工程落点：把"不硬进化"从口号变成可审计的代码约束。

**独立测试**: 人工候选三路径（过检查+优/劣/未过检查）：回放对比报告产出、采纳与拒绝记录
落盘、部署指针仅采纳后更新；可比对树数低于配置下限时对比拒绝产出；dreaming 拒绝生成开发
Agent 候选的审计断言 100% 生效；判据材料 JSON 字段齐全且每项阈值都有"实测值或无法评价"
标注、系统结论非达标。

**验收场景**:

1. **Given** 人工提交新策略版本, **When** 过静态检查 + 回放对比, **Then** 产出对比报告（新版本 vs 部署版本：逐树得分、分项差异、pareto_auc 曲线）
2. **Given** 对比报告已产出, **When** 未人工采纳, **Then** 部署指针不变（0 自动部署）
3. **Given** 人工采纳, **When** 更新部署指针, **Then** 采纳记录（采纳人/时间/依据）落盘，谱系建立父子关系
4. **Given** 任何对开发 Agent 调用 dreaming 候选生成, **When** 请求, **Then** 100% 拒绝（显式报错 + 审计断言，宪章原则六）；部署门禁对该 Agent 一律返回"禁止名单"且优先级高于"证据不足"
5. **Given** 任何一轮选题产出, **When** 生成判据材料, **Then** JSON 含代理分量分布、**全部判据阈值的阈值快照**、每项阈值的"实测值或无法评价（来源缺失）"与缺失原因（012 漂移材料缺失 / 010 信度数据缺失）、系统结论（**不达标/证据不足**）、继续观察条件；阈值项无空白、无省略
6. **Given** 判据材料已产出, **When** 尝试写入"达标"结论、省略某阈值项、或改写系统字段, **Then** 被拒（不得以单次演示结果或未入账口径作为升级依据，宪章原则六）
7. **Given** 新策略未过静态检查, **When** 提交, **Then** 拒绝且不进入回放（记录理由）
8. **Given** 选题树与回放池, **When** 无偏性验收, **Then** 回放与真实重跑得分序列 Kendall τ ≥ 0.95（未达标不得产出对比报告）；注入偏差 100% 被拒
9. **Given** 可比对树数低于配置下限, **When** 请求回放对比, **Then** 拒绝产出报告并明确报错，不给出任何"谁更好"的结论（不得以降格样本产出权威结论）

### 边界情况

- **本环节没有 judge 层**：不得为凑齐四层而引入伪 judge（无成对比较对象与稳定判据）；判据材料必须把该缺口登记为"来源缺失"而非留空
- **010 排除开发 Agent 是本特性的既定选择，非遗留待办**（`specs/010-weekly-calibration/spec.md:157` 保持原样）：本特性不引入任何锚点层、不改动 010 规格；判据材料如实登记无信度数据，并把"先补齐锚点通道"写成继续观察条件。补齐（含是否需要 judge 层）须另立决议，不在本特性
- **判据阈值全量声明但部分不可评价**：材料必须逐项标注"无法评价（来源缺失）"，**不得**留空、**不得**省略阈值项、**不得**据不可计算项得出达标结论；阈值项清单本身是继续观察条件的量化基线
- **组合内无任何选题达到进入生产条件**：如实产出 0 个进入生产标记并写明原因（门禁违规项或分数未达阈值），**不得**降格硬凑一个标记；组合条目本身仍完整落盘。与下一条不冲突：配置区间下界 > 0 时，该轮标记数**确实**未落在区间，由 `rule.slate_combination` 判 0 并如实点名（原因随诊断落盘，不是掩盖）
- **组合内条目数与进入生产标记数**均由配置区间约束（标记默认区间为 1）；越界即组合门禁判 0，不由代码兜底
- **冷启动池子不足**：可比对树数低于配置下限即拒绝产出对比报告并明确报错（不得用一棵树的结论冒充证据）；门槛按形态配置，记录积累够了才出报告
- 判据材料目录不得跨 Agent 共用同名文件：`calibration/upgrade-events/` 现有文件名不含 agent id（009 路径），多 Agent 写入同一周期会互相覆盖——本特性必须按 agent 分目录存放；若因此改动 009 既有路径，必须同步更新 009 的测试与 quickstart 验证记录
- 人工候选在回放上全部劣于现部署版本：对比报告如实呈现，建议保留现版本（不做"矮子里拔将军"）
- 回放命中 UNKNOWN（新策略走法无历史覆盖）：该树记 0 分并提示扩大记录（不编造、不放宽匹配）
- 选题生成的 LLM 非确定性：生成结果经网关缓存落盘，回放只读历史节点（原则三）
- 代理模型的模拟数据源变更：**必须**升评估器版本（数据源即行为口径，原则一），且旧树的分量不被重算
- 策略草稿：不入策略历史、不参与回放，仅正式提交的版本版本化
- 参数调整（configs 变更）不产生策略版本：新配置只影响此后新产的树（配置快照随树冻结），历史节点的 `policy_version` 与得分不受影响
- 与下游剧本的交接：立项组合 schema 是剧本输入（题材/约束/角色设定）的上游依据，schema 变更必须同时更新对接文档与快照断言（防漂移）；字段级交接声明（`FieldParity`）由 G2 立
- 若有人把"真实票房库/舆情接口"接进本环节：将触发宪章原则三新条款（预算门禁 + 账单对账），属 G3 范围；本特性不得绕过该约束先行接入

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供选题产出执行器：输入 = 立项约束（题材边界/受众/形态参数等，按配置）+ 人工策略版本；输出 = **立项组合工件**（本轮推荐立项的多个选题条目，每条含方向标识、论证要点、评估分量、可移交下游的剧本输入要点；组合内标记"本轮进入生产"的条目，数量落在配置区间且必须指向组合内已存在条目）+ LLM 成本入账 + 发现树节点（含 `policy_version`）
- **FR-002**: 全部 LLM 调用必须经网关（缓存、重试、计费）；回放路径零 LLM 调用（审计断言）；FAILED 调用成本照常入账（原则二/三）
- **FR-003**: 硬规则评估器必须实现二门禁：`rule.slate_structure`（组合条目数落在配置区间、方向标识唯一、必填字段齐全）、`rule.slate_combination`（**组合层核心门禁**：组合内方向多样性/去重率、条目数上限、进入生产标记数量与指向合法性均符合形态配置）；gate 违规总分直接为 0 且诊断指明具体违规项；阈值全配置化
- **FR-004**: 代理评估器必须实现 `proxy.genre_regression`（历史同类型票房回归预测）与 `proxy.buzz_heat`（舆情检索热度）；**两者必须为确定性实现**（实现哈希入版本号），数据源为模拟/夹具数据源，且数据来源与"非真实商业数据"标注必须随产物与报告机读可见
- **FR-005**: 合成评分必须 = 二门禁 + 加权求和（权重形态配置）+ 定点归一（6 位小数）；全部评估器 `deterministic=True`、版本冻结；**禁止**引入 judge 层与 human 锚点（本环节证据来源缺失须如实登记，不得以伪信号补齐）
- **FR-006**: 选题树必须接入回放模拟器池（observed/probe/规范化精确匹配/UNKNOWN 复用 002），回放零生成零 LLM（审计断言）；匹配键只含策略可复现的结构键（不含生成产物摘要）
- **FR-007**: **降级模式硬约束**：dreaming 层禁止为开发 Agent 生成候选策略、禁止自动排名与自动部署——调用即显式拒绝（含审计断言）；部署门禁对该 Agent 返回"禁止名单"且优先级最高；策略版本仅由人工提交产生。沿用 `no_auto_evolve_agents` 名单的 `dev` 条目，不得另立第二份名单
- **FR-008**: 人工改策略通道必须实现：策略 = 人编写的代码（版本 = 源码 BLAKE3 前 12 位 + `parent_version`）→ 静态检查（复用 002）→ 回放对比报告（新版本 vs 部署版本：逐树得分/分项差异/pareto_auc 曲线）→ 人工采纳或拒绝（记录人/时间/依据/理由）；未采纳不更新部署指针；参数调整走 configs（配置快照随树冻结，不产生策略版本、不入策略历史）；**前置门槛**：可比对树数 ≥ 配置下限，低于即拒绝产出报告并明确报错（不得以降格样本产出结论）
- **FR-009**: 对比报告、采纳记录与判据材料必须按 agent 分目录落盘、append-only、可机读，且不得与既有 Agent 的产物路径冲突（见边界情况）
- **FR-010**: 升级判据材料必须沿用既有降级 Agent 的同一套 schema 并**全量声明判据阈值**：阈值项（相关性目标、最小样本量、门禁违规率上限、漂移带等）**必须**全部在配置中声明，缺失即报错；计算时逐项输出"**实测值**"或"**无法评价（来源缺失）**"并标注缺失原因（012 漂移材料缺失：无 judge 层；010 信度数据缺失：规格明确排除）；阈值项**不得**留空或省略；系统结论**不得**为"达标"；继续观察条件必须给出待补齐阈值项的量化清单；任何人工推翻必须留痕（人/时间/理由）且不改变系统自动写入的结论字段
- **FR-011**: 立项组合工件 schema 必须版本化（字段/枚举变更即升版）、内容寻址（canonical JSON + BLAKE3）；**每个组合条目**必须携带可移交下游的剧本输入要点（判据 = `genre` / `constraints` / `characters` 三字段非空，见契约 C5），而"本轮进入生产"标记指向的条目**必须**具备完整要点（缺任一字段即 `rule.slate_structure` 判 0 并点名，不得留空待补）；字段级交接声明（`FieldParity`）属 G2
- **FR-012**: 全部形态参数（组合条目数区间、进入生产标记数区间、回放对比最小树数、组合约束、权重、门禁阈值、判据阈值、模拟数据源参数）必须配置化；两形态（movie / shortdrama）必须均声明新配置项，缺失即报错（不得静默取码内默认）；**不得**新增形态分支代码
- **FR-013**: **无偏性验收必须执行**（宪章门禁，新增 Agent 发布阻塞）：选题树回放打分 vs 真实重跑（网关缓存命中下的重执行 + 评估器重算）得分序列 Kendall τ ≥ 0.95；注入偏差 100% 拒绝；未通过不得用于回放沙盘与对比报告
- **FR-014**: **禁止自动进化三重机检必须常驻**：①配置名单默认值断言（`no_auto_evolve_agents` 含 `dev`）②显式拒绝行为断言（dreaming 候选生成 0 调用、0 计费、0 落盘）③审计断言（人工策略 meta 标记 `no_auto_evolve: true`），与 009 同口径
- **FR-015**: 必须提供离线端到端演示与 CLI（提交策略 / 回放对比 / 采纳或拒绝 / 判据材料），退出码语义与既有 Agent 一致

### 关键实体 *（如果功能涉及数据）*

- **立项组合工件（TopicSlate）**: 内容寻址的结构化产出，本轮立项决策的载体——组合条目列表（每条：方向标识、论证要点、评估分量、可移交下游的题材/约束/角色设定要点）、组合级约束元数据（条目数、进入生产标记）、数据来源标注；schema 版本化
- **组合条目（SlateEntry）**: 立项组合内的一条推荐选题——方向标识（组合内唯一）、论证要点、评估分量、可移交要点；进入生产标记至多命中其中一条（数量由配置区间约束）
- **选题节点**: 复用 001 `TreeNode`；`prompt` = 立项约束输入摘要，`eval_breakdown` = 二门禁 + 二代理分量，`policy_version` = 人工策略版本
- **人工策略版本（HumanPolicyVersion）**: 人编写的题材方向探索策略——源码哈希版本、`parent_version`、提交人/时间、静态检查结果、`no_auto_evolve` 审计标记
- **回放对比报告（ReplayComparison）**: 新版本 vs 部署版本——逐树得分、分项评估器差异、pareto_auc 曲线、UNKNOWN 覆盖说明、可比对树数（样本量）
- **采纳记录（AdoptionRecord）**: 人工决策留痕——结论（采纳/拒绝）、人、时间、依据（报告引用）、理由
- **升级判据材料（UpgradeEvidence）**: 供独立决议使用的证据包——**全量阈值快照**与逐项可评价性（实测值 / 无法评价 + 缺失原因）、代理分量分布、系统结论（不达标/证据不足）、继续观察条件（待补齐阈值项清单）、推翻记录
- **模拟数据源（SimulatedSignalSource）**: 票房同类型回归与舆情热度的确定性模拟数据源——数据来源标注、参数版本化（变更即升评估器版本）、零边际成本

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书周 3~5）：选题树全量落盘可回放（回放零 LLM 调用审计通过）+ 回放对比报告产出 + 人工采纳/拒绝留痕
- **SC-002**: **禁止自动进化三重机检常驻且全绿**：dreaming 为开发 Agent 生成候选的次数为 0（显式拒绝 + 审计断言）；部署门禁对 `dev` 一律返回禁止名单；未采纳策略更新部署指针的次数为 0
- **SC-003**: 二门禁对违规工件 100% 判 0——含组合层违规（方向重复率超限、条目数越界、进入生产标记数量越界或指向不存在条目）；代理分量对注入的结构/回归/热度异常样本 100% 命中
- **SC-004**: 定点归一后重算一致率 100%；同输入重跑各分量逐位一致
- **SC-005**: 回放路径 LLM 调用恒为 0（审计断言，原则三）
- **SC-006**: 判据材料字段齐全率 100%；**每个阈值项均有"实测值或无法评价（来源缺失）"标注，无空白、无省略**；系统结论为"不达标/证据不足"且可机检；尝试写入"达标"、省略阈值项或改写系统字段 100% 被拒；推翻留痕后系统结论字段逐字节不变
- **SC-007**: 单元测试覆盖率 ≥ 85%（口径不降，含 web）
- **SC-008**: 无偏性验收（宪章门禁）：回放 vs 真实重跑 Kendall τ ≥ 0.95（可复现基础 = 网关缓存命中）；注入偏差 100% 拒绝；未通过不得产出回放对比报告
- **SC-009**: 模拟数据源标注可机读率 100%（产物、对比报告、判据材料三处均含来源标注，不得让模拟信号被当作真实商业数据）
- **SC-010**: 进入生产标记的可移交完整率 100%——被标记条目的题材/约束/角色设定要点齐备；组合内无达标条目时 0 标记 + 原因，不得降格硬凑
- **SC-011**: 可比对树数低于配置下限时对比报告产出次数为 0（拒绝率 100%，错误信息含实测树数与门槛值）

## 假设

- 选题策略由人工编写（本特性提供提交通道与骨架，不提供策略自动生成）；真实 LLM 凭据属
  网关配置动作，Mock 后端为开发/CI 默认
- **代理信号以模拟数据源起步**（已裁决，见 Clarifications 末条）：仓库内不存在真实票房数据库
  与舆情接口，"历史票房同类型回归预测 + 舆情热度"以确定性模拟数据源 + 夹具实现，并按
  "模拟生成"标注纪律如实标注；真实渠道接入归 G3（原则三新条款：预算门禁 + 账单对账）
- **升级为自动进化不在本特性范围**：本特性只保证骨架、判据材料与"不达标/证据缺失"的如实
  登记；升级须另立决议并同步修订宪章原则六相关表述（立项书 §3.2 明示三期不翻案）
- 下游交接不在本特性：立项组合产出 → 剧本输入的字段级声明由 G2（018）立，本特性只保证
  schema 版本化与字段齐备
- 本特性不新增 pilot 阶段、不改变七阶段链的既有形状；`dev` 作为链首阶段的编排属 G2
- 开发 Agent 的昂贵程度低（纯检索分析 + 文本产出），预算门禁按调用次数与 token 计费口径
  配置，不设重型预算闸门
- 冷启动期的记录积累靠演示/排练轮次完成（回放最小树数门槛按形态配置，不硬编码在代码里）
- 002 的沙箱/静态检查、005 的做梦层"不适用"边界、010 的锚点通道、012 的漂移口径均已就位，
  本特性以复用为主，不新造基建
