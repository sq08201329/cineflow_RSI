# 功能规格说明：judge 漂移自动检测

**功能分支**: `012-judge-drift-detection`

**创建日期**: 2026-09-21

**状态**: 草稿

**输入**: 用户描述："二期立项书 F7：judge 漂移自动检测——对比历史锚点评分分布，识别 judge 评估器的评分分布漂移（漂移是 reward hacking 的主要通道）。数据源：010 周校准已积累的锚点得分分布快照（`calibration/snapshots/{agent}/{evaluator}/{period}.json`，FR-009 明确为 F7 供数）+ 偏差台账 + 信度报告。检测：按 (agent, evaluator) 对比当前周期分布 vs 历史基线，输出漂移指标（分布距离 + 分位数偏移）并超阈告警；首周期记基线。处置门禁：漂移判定的 judge 版本标记 `drift_suspect`，其得分不再主导合成（降权/排除），人工处置留痕（确认漂移 → 停用/换锚点升版；误报 → 记录理由恢复），**未处置的漂移 judge 不得进入自动部署证据**（为 F9 预留接口）。联动：与 010 信度下降同时出现 → 强化告警。验收：注入已知漂移 100% 检出；稳定分布不误报；状态机与留痕可机检。"

**约束来源**: 项目宪章 v1.1.0（**原则六**：Judge 漂移必须被持续监控——委员会多提示词 + 盲测样本 + 人评锚点对比；监控必须机检；原则一：评估器版本冻结——漂移检测口径本身版本化，评估器升版 = 新基线；原则二：只读不写树；原则五：窗口/分桶/阈值/联动规则全配置化；原则六诚实边界：漂移判定不自动停用，处置由人工留痕）。业务依据 `docs/影视全Agents公司技术方案.md` §4.3（两条风险红线之一：Judge 漂移导致全线 reward hacking）。立项依据 `docs/二期立项书.md` WS2-F7（前置：F5 校准数据积累；F9 依赖本特性就位）。依赖功能 010（分布快照/台账/信度报告）、006~009（各 Agent 的 judge 评估器——narrative_flow/dramatic_tension/script_fit/cinematic 等）；F6 的 ScoreConflict 作为辅助漂移信号（可选）。

## Clarifications

### Session 2026-09-21

- Q: 漂移判定的"历史基线"如何定义？ → A: **滑动窗口**（最近 N 周期、不含当前周期，N 配置，默认 4~5）——兼顾检出突变与容忍自然演进；窗口内样本不足即如实标注"样本不足"；窗口边界与评估器升版点对齐（升版即新基线）
- Q: `drift_suspect` 的 judge 得分在合成里默认怎么处理？ → A: **分级处置**——`suspect` 降权（配置系数，默认 0.5）、`confirmed_drift` 排除（不参与合成）
- Q: 漂移检测的范围？ → A: 默认判定范围 = **`kind=judge` 的评估器**（与宪章原则六字面与风险指向一致）；proxy/rule 可经配置纳入但**默认关闭**（其分布变化更可能是输入分布变化的镜像，噪声大）

## 用户场景与测试 *（必填）*

### 用户故事 1 - 漂移检测与告警（优先级：P1）🎯 MVP

评估工程师做一轮漂移检测：系统按 **(agent, evaluator)** 读取 010 的锚点得分分布快照
序列（周期序列），对比当前周期与历史基线（窗口）分布——输出**漂移指标**（分布距离 +
分位数偏移两个维度）与判定；超阈（配置）→ 告警 + 该评估器版本登记为 `drift_suspect`；
**首周期记基线不告警**；样本不足（配置下限）如实注明不判定。检测**只读**（不写树、
不改评估器、不触发生成）。

**为什么是这个优先级**: 漂移检测是 F7 的本体——宪章原则六把"持续监控 judge 漂移"列为
强制项，而 010 已把所需数据（分布快照/台账/信度）积累到位，本故事把数据变成判定。

**独立测试**: 构造已知漂移的分布序列（基线 vs 平移/展宽/双峰化）与稳定序列：检出率、
指标口径、首周期基线、样本不足注明逐断言；不接处置门禁与报表即可交付"漂移可检出"的价值。

**验收场景**:

1. **Given** 基线分布与当前周期分布, **When** 检测, **Then** 输出分布距离与分位数偏移两维指标及判定（漂移/正常）
2. **Given** 注入已知漂移（均值平移 / 方差展宽 / 分布双峰化 ≥3 形态）, **When** 检测, **Then** 100% 判漂移（超阈）
3. **Given** 稳定分布序列（无漂移）, **When** 检测, **Then** 不误报（判定正常）
4. **Given** 首周期（无历史基线）, **When** 检测, **Then** 记基线并注明"首周期无基线"，不告警
5. **Given** 样本量低于下限, **When** 检测, **Then** 注明"样本不足"不判定（不伪造结论）
6. **Given** 评估器升版（`evaluator_id@version` 变化）, **When** 检测, **Then** 新版本独立记基线（版本冻结：旧版本基线不沿用到新版本）

---

### 用户故事 2 - 漂移处置门禁与人工留痕（优先级：P2）

校准负责人处置漂移：`drift_suspect` 状态的 judge 评估器版本**其得分不再主导合成**
（配置：降权系数或从加权中排除）；处置必须人工留痕——**确认漂移** → 停用该版本或
换锚点升版（新版本独立记基线）；**判为误报** → 记录理由（谁/何时/为什么）恢复 `normal`。
状态机：`normal → suspect → confirmed_drift | false_alarm`（终态由人工写入，系统只写
`suspect`）。**自动部署证据接口**：查询某评估器版本是否可进入自动部署证据时，
`drift_suspect` 与 `confirmed_drift` 状态必须返回拒绝（F9 未交付，接口与状态先就位）。

**为什么是这个优先级**: 漂移若不抑制其影响，检测本身就失去意义（judge 仍在主导合成）；
而"不自动停用、必须人工留痕"是原则六的诚实边界——系统只说不确定，处置权在人。

**独立测试**: 状态机三路径 + **分级处置**（suspect 降权 / confirmed_drift 排除）的合成效果断言 + 证据接口拒绝断言 + 误报恢复留痕。

**验收场景**:

1. **Given** 漂移判定产生, **When** 合成评分计算, **Then** `drift_suspect` 的 judge 按配置降权（默认 0.5）、`confirmed_drift` 被排除（合成结果与正常态可区分）
2. **Given** 自动部署证据查询, **When** 目标评估器版本为 `drift_suspect` 或 `confirmed_drift`, **Then** 返回拒绝 + 理由（F9 前置）
3. **Given** 人工确认漂移, **When** 处置, **Then** 留痕（人/时间/理由）落盘，该版本状态 `confirmed_drift`，不再参与合成
4. **Given** 人工判为误报, **When** 处置, **Then** 留痕落盘，状态恢复 `normal`，合成恢复正常权重
5. **Given** 系统运行, **When** 检查状态写入, **Then** 系统只写 `suspect`（`confirmed_drift`/`false_alarm` 仅由人工处置写入——可机检）

---

### 用户故事 3 - 漂移监控报表与信度联动（优先级：P3）

校准负责人查看监控：周期报表按 (agent, evaluator) 给出漂移轨迹（指标序列、基线、
阈值、当前状态、处置记录）；**联动**——某评估器的漂移告警与 010 信度下降（相关系数
走低）同时出现时，强化告警（配置规则：两者同时 → 升级告警级别并显式标注"双信号"）；
报表 JSON 可机读，供人工决策与 F9 证据引用。

**为什么是这个优先级**: 单点指标容易被噪声误导，"漂移 + 信度下降"的双信号是
reward hacking 的更强证据；报表是人工处置与后续 F9 决策的输入。

**独立测试**: 报表字段齐全、漂移轨迹序列正确、双信号强化告警触发/不触发两路径、
处置状态与记录在报表中如实呈现。

**验收场景**:

1. **Given** 多个评估器的多周期数据, **When** 生成报表, **Then** 每项含指标序列/基线/阈值/状态/处置记录（JSON 可机读）
2. **Given** 漂移告警与信度下降同时发生, **When** 生成报表, **Then** 强化告警（级别升级 + "双信号"标注）
3. **Given** 仅漂移无信度下降（或反之）, **When** 生成报表, **Then** 常规告警（不误升级别）
4. **Given** 已处置项, **When** 生成报表, **Then** 状态与处置记录（人/时间/理由）如实呈现

---

### 边界情况

- 某评估器无任何快照（从未被 010 采集）：报表标注"无数据"，不判定（不伪造）
- 基线窗口跨评估器升版：升版点作为基线切分（新版本新基线，旧版本数据不混入）
- 漂移由真实质量提升引起（生成确实变好）：检测只判分布变化，**不判原因**；报表提示
  "需结合人评锚点判断"（010 信度即该锚点的量化）
- 多评估器同时漂移：逐项独立判定与告警（不合并成单一结论）
- 漂移指标口径变更（算法升级）：检测口径版本化，历史判定不被回溯改写（只影响此后）
- 配置纳入 proxy/rule 检测（默认关闭）：其分布变化如实记录，但报表显式标注"非 judge 类，漂移信号可能是输入分布镜像"（不改变判定口径，仅供观察）
- 基线窗口内样本不足（快照周期数 < N 或样本量低于下限）：如实标注"样本不足"（不缩小窗口硬判、不插值）
- 01 0 快照被清理/缺失某周期：序列缺口如实标注（不插值、不编造）
- F6 的 ScoreConflict 记录（可选辅助信号）：存在时报表附注，不参与阈值判定（避免
  把"跨项目结构冲突"与"judge 漂移"混为一谈）

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供漂移检测器：输入 = 010 锚点得分分布快照序列（按周期）+ 检测配置；**基线 = 滑动窗口（最近 N 周期、不含当前周期，N 配置）**；输出 = 漂移指标（分布距离 + 分位数偏移）与判定（漂移/正常/样本不足/无基线）
- **FR-002**: 检测必须输出两维指标：分布距离（分桶分布距离口径）与分位数偏移（如 p25/p50/p75/p90 位移）；阈值配置化；判定逻辑可机检
- **FR-003**: 首周期（无基线）必须记基线不告警；样本量低于下限必须注明"样本不足"不判定；无数据标注"无数据"
- **FR-004**: 超阈必须告警并登记评估器版本为 `drift_suspect`（系统只写此状态）；状态机 `normal → suspect → confirmed_drift | false_alarm`，终态仅人工处置写入
- **FR-005**: 合成门禁必须执行**分级处置**：`drift_suspect` 的 judge 得分**降权**（系数配置，默认 0.5）、`confirmed_drift` **排除**（不参与合成）；两者与正常态在合成结果上可区分；**自动部署证据接口必须对这两种状态返回拒绝 + 理由**（F9 前置，接口先就位）
- **FR-006**: 人工处置必须留痕：确认漂移（停用版本或换锚点升版，新版本独立基线）与误报恢复（`normal`），记录（人/时间/理由）落盘且不可改写
- **FR-007**: 周期报表必须产出：per (agent, evaluator) 的指标序列、基线、阈值、状态、处置记录（JSON 可机读）；漂移与 010 信度下降同时出现 → 强化告警（配置规则，显式"双信号"标注）
- **FR-008**: 数据源必须为 010 既有产物（分布快照/台账/信度报告），**不新增采集**；检测只读（不写树、不改评估器、零生成/零 LLM 调用）
- **FR-009**: 检测窗口（N）、分桶数、阈值、样本下限、降权系数、双信号联动规则、以及**检测范围（默认仅 `kind=judge`；proxy/rule 可配置纳入、默认关闭）**必须全部配置化
- **FR-010**: 检测口径本身必须版本化（口径变更 = 新口径版本，历史判定不被回溯改写）；评估器升版必须独立记基线（版本冻结原则）
- **FR-011**: 检测与告警不得自动停用评估器、不得自动修改合成权重（人工处置为唯一通路——原则六）；系统对状态的所有自动写入仅限 `suspect`
- **FR-012**: 残余漂移信号（F6 的 ScoreConflict 等）可作为报表附注，**不得**参与阈值判定

### 关键实体 *（如果功能涉及数据）*

- **漂移基线（DriftBaseline）**: 某 `evaluator_id@version` 的基线分布——**滑动窗口**（最近 N 周期、不含当前周期）、窗口内分桶分布、分位数、样本量、口径版本；升版即新基线
- **漂移指标（DriftMetrics）**: 一次检测的产出——分布距离、分位数偏移（分位点位移向量）、样本量、判定
- **漂移状态（DriftStatus）**: 评估器版本的状态记录——状态（normal/suspect/confirmed_drift/false_alarm）、发现时间、触发指标、处置记录引用
- **处置记录（DriftDisposition）**: 人工处置留痕——结论、人、时间、理由、动作（停用/换锚点升版/恢复）
- **漂移报表（DriftReport）**: 周期报表——per (agent, evaluator) 的轨迹与状态；双信号强化告警标注
- **部署证据结论（DeployEvidenceVerdict）**: 供 F9 的证据查询结果——允许/拒绝 + 理由（漂移状态是组成）

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书 WS2）：注入已知漂移 ≥3 形态 100% 检出；稳定分布 0 误报；首周期基线 100% 正确；样本不足 100% 标注
- **SC-002**: 系统自动写入的状态仅 `suspect`（机检）；`confirmed_drift`/`false_alarm` 100% 来自人工处置留痕
- **SC-003**: `drift_suspect`/`confirmed_drift` 版本的自动部署证据查询 100% 返回拒绝（F9 前置机检）
- **SC-004**: 分级处置效果可区分——`suspect` 降权（默认 0.5）与 `confirmed_drift` 排除的合成结果各与正常态存在可断言差异（前/中/后三态对比）
- **SC-005**: 检测只读：树零写入、评估器零变更、生成/LLM 调用为 0（审计断言）
- **SC-006**: 报表字段齐全率 100%；双信号强化告警触发/不触发两路径正确
- **SC-007**: 单元测试覆盖率 ≥ 85%（core + agents + dreaming 口径不降）

## 假设

- 数据源以 010 的分布快照（FR-009 明确"为 F7 供数"）为主；快照按周期产出，本特性
  不改变 010 的采集节奏（运营节奏属 010 与运营接入）
- **F9（自动部署）未交付**：本特性只提供状态与证据接口（拒绝语义），不实现部署流程
- 处置动作中的"换锚点升版"改变的是 judge 评估器版本（新版本新基线）；升版流程由
  既有评估器版本机制承载（原则一），本特性只登记与引用
- 漂移判定口径（分布距离算法）属实现细节，plan 阶段定；口径版本化是规格要求
- F6 的 ScoreConflict 仅作附注信号（跨项目结构冲突 ≠ judge 漂移，两者不可混判）
- 检测不自动停用评估器（原则六：处置权在人）；自动停用若要做，须另立决议并评估
  "无人值守下误停用"的风险
- 电影形态下 judge 分布样本量偏小是常态（每周 top-k 锚点），故"样本不足"路径必须
  可用且如实——这是与 010 同源的诚实边界
