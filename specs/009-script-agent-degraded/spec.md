## Clarifications

### Session 2026-09-20

- Q: 升级判据材料的"达标"如何定义？ → A: 阈值配置化 + 系统自动判定——判据阈值（judge 相关系数 ≥ target、样本量 ≥ N、漂移指标在带内、门禁违规率 ≤ X）入 configs，系统给出"达标/不达标"结论并附原始数值；人可推翻结论但**必须留痕**（推翻人/时间/理由），系统结论是唯一自动写入的部分
- Q: "人工改策略"的提交形态？ → A: 策略 = 人编写的代码（静态检查 + BLAKE3 版本化，与全线一致）；参数调整走 configs（配置快照随树冻结），**不产生策略版本**——`policy_version` 始终唯一标识行为

## 用户场景与测试 *（必填）*

### 用户故事 1 - 剧本产出与全量记录（优先级：P1）🎯 MVP

剧本生产线运行一轮产出：当前策略（**人工编写**的结构探索策略：先写哪条线、分支数、
节拍安排）对输入（题材/题材约束 + 目标时长 + 角色设定）产出剧本工件（大纲 → 分场 →
剧本，分阶段或一次性）→ 执行器经 LLM 网关生成（计费、缓存、重试）、成本入账 →
硬规则门禁评估 → 节点一次性完整 INSERT（发现树全量记录）。生成中间态落可变运营表。
**本环节不做自动策略搜索**：策略来源是人，节点携带 `policy_version` 指向人工策略版本。

**为什么是这个优先级**: "记录"是降级模式的第一半——没有全量落盘的剧本树，
回放沙盘与 judge 信度积累都无从谈起；这也是后续"是否升级"决策的唯一证据基础。

**独立测试**: 用确定性 Mock 网关 + 人工策略跑一轮产出：剧本工件内容寻址落库、
四硬规则分量入 eval_breakdown、成本入账（含失败调用）、两段式落盘逐断言；
不接回放与对比报告即可交付"剧本产出可记录"的价值。

**验收场景**:

1. **Given** 题材输入 + 人工策略版本, **When** 执行一轮产出, **Then** 剧本工件落树（节点含 policy_version = 人工策略版本），成本入账，eval_breakdown 含四硬规则分量
2. **Given** 同一轮次重复触发, **When** 幂等检查, **Then** 不重复生成节点、不重复扣费（沿用既有幂等派生口径）
3. **Given** 网关返回失败, **When** 记录, **Then** FAILED 节点落盘且成本照常入账（原则二）
4. **Given** 任一节点, **When** 查询, **Then** 可回溯到产出它的策略版本（人工版本同样版本化，BLAKE3 前 12 位）

### 用户故事 2 - 剧本评估器组合与合成评分（优先级：P2）

评估工程师为剧本节点打分：硬规则四门禁——`rule.beat_structure`（节拍表结构完整性：
可解析的三幕/序列结构、关键节拍存在性）、`rule.page_minutes`（页数-时长换算：
1 页≈1 分钟，总页数 ∈ 目标时长 ± 容差）、`rule.scene_character`（场景-角色一致性：
出场角色在场景内、无幽灵角色、场景地点一致）、`rule.dialogue_action_ratio`
（对白/动作行比例统计落在配置区间）；代理模型——`proxy.entity_consistency`
（角色名实体一致性：同名异写/指代歧义检测）、`proxy.timeline_conflict`
（时间线冲突检测：场景时序与标注时间矛盾）；judge——`judge.dramatic_tension`
（成对比较"哪个大纲的戏剧张力更强"，3 judge 投票，提示词/锚点/摘要哈希入版本号）。
合成 = 门禁 + 加权求和（权重形态配置）+ 定点归一（6 位小数）。

**为什么是这个优先级**: 评估信号质量正是"是否升级为自动进化"判据的来源——信号弱
就必须诚实降级，本故事把"信号有多弱"变成可测量的数据（信度报告口径）。

**独立测试**: 构造已知属性的剧本夹具（结构残缺、页数越界、幽灵角色、比例失衡、
实体冲突、时间线矛盾、张力高低）：七评估器得分、门禁语义、judge 三段哈希、定点
归一逐断言。

**验收场景**:

1. **Given** 缺失关键节拍的大纲, **When** 评估, **Then** beat_structure 门禁判 0，总分直接为 0
2. **Given** 总页数超出目标 ± 容差, **When** 评估, **Then** page_minutes 门禁判 0
3. **Given** 场景中出现未登记角色（幽灵角色）, **When** 评估, **Then** scene_character 门禁判 0
4. **Given** 对白/动作行比例超出配置区间, **When** 评估, **Then** dialogue_action_ratio 门禁判 0
5. **Given** 张力高/低两组大纲, **When** judge.dramatic_tension 评估, **Then** 前者胜率显著高于后者；平局 0.5 如实记录；提示词/锚点/摘要哈希入版本号；LLM 全过网关计费
6. **Given** 同工件重评估, **When** 比较得分, **Then** 定点归一后逐位一致（代理与 judge 确定性由缓存与冻结锚点保证）

### 用户故事 3 - 回放沙盘与人工改策略闭环（优先级：P3）

剧本负责人改进策略：人工编写/修改策略版本 → 提交到策略历史（版本 = 源码 BLAKE3
前 12 位，`parent_version` 指向改进来源）→ 过静态检查（复用 002：import 白名单、
禁网络/文件 IO、接口签名）→ 在模拟器池上**回放对比**（新版本 vs 当前部署版本，
产出对比报告：逐树得分、分项评估器差异、pareto_auc 曲线对比）→ **人工决定采纳**
（采纳才更新部署指针；拒绝则记录理由）。**硬约束**：dreaming 层**禁止**为剧本
Agent 生成候选策略、禁止自动排名与自动部署（审计断言 + 显式拒绝）。同时系统持续
积累**升级判据数据**：judge 信度（与 010 人评锚点的相关系数）、漂移指标、门禁违规
分布 → 产出评审材料 JSON，供"是否升级为自动进化"的独立决议使用（升级本身不在本特性）。

**为什么是这个优先级**: 这是降级模式的第二半"回放沙盘"——人做决策、系统给零成本
的对比证据；也是宪章原则六"诚实边界"的工程落点：把"不硬进化"从口号变成可审计的
代码约束。

**独立测试**: 人工候选三路径（过检查+优/劣/未过检查）：回放对比报告产出、采纳与
拒绝记录落盘、部署指针仅采纳后更新；dreaming 拒绝生成剧本候选的审计断言 100% 生效；
升级判据材料 JSON 字段齐全。

**验收场景**:

1. **Given** 人工提交新策略版本, **When** 过静态检查 + 回放对比, **Then** 产出对比报告（新版本 vs 部署版本：逐树得分、分项差异、pareto_auc 曲线）
2. **Given** 对比报告已产出, **When** 未人工采纳, **Then** 部署指针不变（0 自动部署）
3. **Given** 人工采纳, **When** 更新部署指针, **Then** 采纳记录（采纳人/时间/依据）落盘，谱系建立父子关系
4. **Given** 任何对剧本 Agent 调用 dreaming 候选生成, **When** 请求, **Then** 100% 拒绝（显式报错 + 审计断言，宪章原则六）
5. **Given** 累计若干轮产出与锚点, **When** 生成升级判据材料, **Then** JSON 含 judge 信度（相关系数/样本量）、漂移指标、门禁违规分布、人评锚点数、阈值快照与**系统判定结论（达标/不达标）**——字段齐全可机读
6. **Given** 判据未达配置阈值, **When** 人推翻系统结论, **Then** 推翻留痕（人/时间/理由）落盘且系统结论字段不被改写
6. **Given** 新策略未过静态检查, **When** 提交, **Then** 拒绝且不进入回放（记录理由）
7. **Given** 剧本树与回放池, **When** 无偏性验收, **Then** 回放与真实重跑得分序列 Kendall τ ≥ 0.95（未达标不得产出对比报告）；注入偏差 100% 被拒

---

### 边界情况

- judge 信度持续为负或样本不足：升级判据材料如实标注"信号不达标"，**不触发**升级流程（诚实边界）
- 人工候选在回放上全部劣于现部署版本：对比报告如实呈现，建议保留现版本（不做"矮子里拔将军"）
- 回放命中 UNKNOWN（新策略走法无历史覆盖）：该树记 0 分并提示扩大记录（不编造）
- 剧本生成的 LLM 非确定性：生成结果经网关缓存落盘，回放只读历史节点（原则三）
- 剧本策略版本与人工改写的中间态（草稿）：草稿不入策略历史、不参与回放，仅正式提交
  的版本版本化
- 参数调整（configs 变更）不产生策略版本：新配置只影响此后新产的树（配置快照随树冻结），
  历史节点的 `policy_version` 与得分不受影响
- 与 008 分镜的交接：剧本产出的场景/台词 schema 是分镜输入的权威来源，schema 变更
  必须同时更新对接文档与快照断言（防漂移）
- 开发 Agent 同样不做自动进化（宪章原则六），本特性的"降级模式骨架"是其未来复用对象
  （不构成实现承诺）

## 需求 *（必填）*

### 功能需求

- **FR-001**: 系统必须提供剧本产出执行器：输入 = 题材/题材约束 + 目标时长 + 角色设定 + 人工策略版本；输出 = 剧本工件（大纲→分场→剧本，内容寻址）+ LLM 成本入账 + 发现树节点（含 policy_version）
- **FR-002**: 全部 LLM 调用必须经网关（缓存、重试、计费）；回放路径零 LLM 调用（审计断言）；FAILED 调用成本照常入账
- **FR-003**: 硬规则评估器必须实现四门禁：`rule.beat_structure`（三幕/序列结构可解析 + 关键节拍存在）、`rule.page_minutes`（页数-时长换算 ∈ 目标 ± 容差）、`rule.scene_character`（场景-角色一致性：无幽灵角色/地点一致）、`rule.dialogue_action_ratio`（比例落在配置区间）；gate 违规总分直接为 0；阈值全配置化
- **FR-004**: 代理评估器必须实现 `proxy.entity_consistency`（角色名实体一致性）与 `proxy.timeline_conflict`（时间线冲突检测）；确定性实现，实现哈希入版本号
- **FR-005**: judge 评估器必须实现 `judge.dramatic_tension`：输入 = 大纲结构化摘要（确定性摘要函数），3 judge 投票成立对比较；提示词/锚点/摘要函数三段哈希入版本号；LLM 全过网关计费；平局 0.5 如实记录；同比较重跑逐位一致
- **FR-006**: 合成评分必须 = 四门禁 + 加权求和（权重形态配置）+ 定点归一（6 位小数）；全部评估器 deterministic=True、版本冻结
- **FR-007**: 剧本树必须接入回放模拟器池（observed/probe/规范化精确匹配/UNKNOWN 复用 002），回放零生成零 LLM（审计断言）
- **FR-008**: **降级模式硬约束**：dreaming 层禁止为剧本 Agent 生成候选策略、禁止自动排名与自动部署——调用即显式拒绝（含审计断言）；策略版本仅由人工提交产生
- **FR-009**: 人工改策略通道必须实现：**策略 = 人编写的代码**（版本 = 源码 BLAKE3 前 12 位 + parent_version）→ 静态检查（复用 002）→ 回放对比报告（新版本 vs 部署版本：逐树得分/分项差异/pareto_auc 曲线）→ 人工采纳或拒绝（记录人/时间/依据/理由）；未采纳不更新部署指针；**参数调整走 configs**（配置快照随树冻结，不产生策略版本、不入策略历史）
- **FR-010**: 升级判据材料必须产出：JSON 含 judge 信度（与 010 人评锚点的相关系数与样本量）、漂移指标、门禁违规分布、人评锚点计数、**判据阈值快照与系统判定结论（达标/不达标）**；判定由配置阈值自动计算（相关系数 ≥ target、样本量 ≥ N、漂移在带内、门禁违规率 ≤ X），阈值缺配置即报错；人推翻结论必须留痕（推翻人/时间/理由），推翻不改变系统自动写入的结论字段；信号不达标必须如实标注（不得暗示可升级）
- **FR-011**: 剧本必须纳入 010 周校准盲评范围（top-k 大纲 3~5 份/周）；剧本产出的场景/台词 schema 必须版本化并与 008 分镜对接文档/快照断言保持一致
- **FR-012**: 全部形态参数（目标时长、页数容差、比例区间、权重、judge 提示词与锚点集、静态检查策略）必须配置化；策略代码不自动进化（无 dreaming 候选生成）
- **FR-013**: **无偏性验收必须执行**（宪章门禁，新增 Agent 发布阻塞）：剧本树回放打分 vs 真实重跑（网关缓存命中下的重执行 + 七评估器重算）得分序列 Kendall τ ≥ 0.95；注入偏差 100% 拒绝；回放可复现的基础由网关缓存收敛的非确定性提供（缓存键与响应哈希随节点落盘）；未通过不得用于回放沙盘与对比报告

### 关键实体 *（如果功能涉及数据）*

- **剧本工件（ScriptArtifact）**: 大纲/分场/剧本三段或单段的产物——内容寻址引用、页数、场景数、角色清单
- **剧本节点**: 复用 001 TreeNode；prompt = 题材/约束输入摘要，eval_breakdown = 七评估器分量，policy_version = 人工策略版本
- **人工策略版本（HumanPolicyVersion）**: 人编写的结构探索策略——源码哈希版本、parent_version、提交人/时间、静态检查结果
- **回放对比报告（ReplayComparison）**: 新版本 vs 部署版本——逐树得分、分项评估器差异、pareto_auc 曲线、UNKNOWN 覆盖说明
- **采纳记录（AdoptionRecord）**: 人工决策留痕——结论（采纳/拒绝）、人、时间、依据（报告引用）、理由
- **升级判据材料（UpgradeEvidence）**: 供独立决议使用的证据包——judge 信度、漂移指标、门禁违规分布、人评锚点计数、判据阈值快照、系统判定结论（达标/不达标）、推翻记录（人/时间/理由）

## 成功标准 *（必填）*

### 可衡量结果

- **SC-001**: 里程碑验收（立项书周 7~9）：剧本树全量落盘可回放（回放零 LLM 调用审计通过）+ 回放对比报告产出 + 人工采纳/拒绝留痕
- **SC-002**: 未采纳策略更新部署指针的次数为 0（机检）；**dreaming 为剧本生成候选的次数为 0**（显式拒绝 + 审计断言）
- **SC-003**: 四门禁对违规工件 100% 判 0；代理一致性/时间线检测对注入冲突 100% 命中
- **SC-004**: 定点归一后重算一致率 100%；judge 同比较重跑逐位一致
- **SC-005**: 回放路径 LLM 调用恒为 0（审计断言，原则三）
- **SC-006**: 升级判据材料字段齐全率 100%；系统判定结论（达标/不达标）为自动写入且可机检；未达阈值时"不达标"标注存在；人推翻留痕后系统结论字段逐字节不变
- **SC-007**: 单元测试覆盖率 ≥ 85%（core + agents + dreaming 口径不降）
- **SC-008**: 无偏性验收（宪章门禁）：回放 vs 真实重跑 Kendall τ ≥ 0.95（可复现基础 = 网关缓存命中）；注入偏差 100% 拒绝；未通过不得产出回放对比报告

## 假设

- 剧本策略由人工编写（本特性提供提交通道与骨架，不提供策略自动生成）；真实 LLM 凭据
  属网关配置动作，Mock 后端为开发/CI 默认
- 剧本 schema（场景/台词/角色）以本特性为权威来源，008 分镜的输入夹具在该 schema 对齐后
  可切换为真实剧本产出（对接是 008 或后续集成的接线事项）
- 升级为自动进化**不在本特性范围**：本特性只保证判据数据持续积累与"不达标"的如实标注；
  升级须另立决议并同步修订宪章原则六相关表述
- 开发 Agent（选题/IP 评估）同为降级模式（宪章原则六既定），本特性骨架是其未来复用对象，
  但不含其实现
- 剧本生成的昂贵程度远低于视觉/剪辑/声音（文本），预算门禁按调用次数与 token 计费口径
  配置，不设重型预算闸门
- judge 漂移自动检测（F7）不在本特性；本特性只保证剧本入 010 盲评、锚点与信度数据按
  010 口径积累
